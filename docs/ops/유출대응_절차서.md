# 비밀값 유출 대응 절차서 (ENV-04)

비밀값(키·토큰·비밀번호)이 저장소·로그·채팅·화면 공유 등으로 **노출됐거나 노출이 의심되면** 바로 이 순서로 한다. 의심만 들어도 노출로 본다.

| 순서 | 할 일 | 끝났다는 확인 |
|---|---|---|
| 1. 폐기 | 노출된 값을 서비스에서 무효로 만든다. 새 값을 만들기 전에 이전 값부터 끊는 것이 원칙이다. 단, 서비스가 끊기면 안 되는 운영 키는 2·3을 먼저 하고 바로 4·1을 한다 | 서비스 화면·CLI에 이전 키가 없거나 '폐기됨' |
| 2. 재발급 | 새 값을 만든다. 채팅·메일·문서에 붙여 넣지 않는다 | 새 값은 서비스 화면·도구 안에서만 보인다 |
| 3. 환경변수 교체 | 새 값을 두는 곳(아래 표)에만 넣는다 | `node scripts/check-vercel-env.mjs` 통과(Vercel), GitHub Secrets 갱신일 |
| 4. 재배포 | 값이 바뀐 환경을 다시 배포한다 (Vercel은 환경변수만 바꾸면 기존 배포에 반영되지 않는다) | 새 배포 주소 `/api/health` 200 |
| 5. 이전 키 거부 확인 | 이전 값으로 실제 요청을 보내 401·403이 나오는지 본다 | 이전 키 요청 401·403, 새 키 요청 200 |
| 6. 기록 | 시각·담당자·영향 범위·조치를 기록한다 — `docs/ops/유출대응_리허설_기록.md` 형식, 실제 사고는 감사 로그(`audit_logs`, action `secret.rotate`)에도 | 기록에 빈 칸 0 |

## 비밀값별 폐기·재발급 위치

| 비밀값 | 두는 곳 | 폐기·재발급 | 이전 키 거부 확인 |
|---|---|---|---|
| `CRON_SECRET` | Vercel(Production·Preview 따로), 사내 서버 `deploy/.env.server` | 새 무작위 값으로 덮어쓰면 이전 값은 그 순간 무효 | 이전 값으로 `POST /api/jobs/scheduler-heartbeat` → 401 |
| `SUPABASE_SERVICE_ROLE_KEY` | Vercel(Production·Preview), 사내 서버 | Supabase 대시보드 → Project Settings → API Keys. 레거시 JWT 키는 JWT 비밀 교체로만 무효가 된다 — 새 비밀 키(`sb_secret_…`)로 옮기면 키 하나씩 폐기할 수 있다 [결정 안건] | 이전 키로 REST 요청 → 401 |
| `ANTHROPIC_API_KEY` | Vercel, 사내 서버 (AI 도우미를 만들 때) | Anthropic 콘솔 → API Keys → 해당 키 Disable/Delete | 이전 키로 API 요청 → 401 |
| `RESEND_API_KEY` | Vercel, 사내 서버 (메일 기능을 만들 때) | Resend 대시보드 → API Keys → Revoke | 이전 키로 발송 요청 → 401 |
| `SUPABASE_ACCESS_TOKEN`·`VERCEL_TOKEN` | GitHub Actions Secrets | 각 서비스 계정 설정 → 토큰 폐기·새로 만들기 | 이전 토큰으로 CLI 요청 → 401 |
| GitHub 로그인 토큰(이 PC의 gh) | 이 PC | `gh auth logout` 후 다시 로그인, GitHub Settings → Applications에서 폐기 | 이전 토큰으로 `gh api user` → 401 |
| DB 비밀번호(운영) | PO 비밀번호 관리자 | Supabase 대시보드 → Database → Reset password | 이전 비밀번호로 접속 실패 |

## 하지 않는 것

- 비밀값을 채팅·메일·문서·이슈·커밋 메시지에 적지 않는다. 확인할 때도 값 대신 "몇 자리·앞 4글자"만 말한다.
- 노출된 값이 커밋됐다면 이력을 지우는 것보다 **폐기가 먼저**다. 이력 정리는 폐기 뒤에 한다.
- 리허설은 운영(Production) 키로 하지 않는다. 시험(Preview·staging) 키로만 한다.

## 리허설

- 정해진 리허설 절차는 `scripts/ops/rehearse-secret-rotation.mjs`다. Preview의 `CRON_SECRET`을 두 번 바꾸고, 그 사이에 시험 배포를 두 번 하고, 이전 값이 거부되는지 확인한다.
- 결과는 `docs/ops/유출대응_리허설_기록.md`에 남긴다.
