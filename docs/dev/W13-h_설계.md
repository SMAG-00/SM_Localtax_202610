# W13-h 홈 해결 사례와 O5 분류 (HOME-11, AIOPS-15) — 설계 약속 (개발 문서)

5단계 설계(`5단계_설계.md`) 1.1절 W13-h 단계와 PRD-05 HOME-11·AIOPS-15·QNA-03을 구현할 때 DB·서버·화면·시험이 같은 이름과 규칙을 쓰기 위한 약속입니다. PRD와 다르면 PRD를 따르고 이 문서를 고칩니다. (2026-10-27 작성)

**지키는 선**
- 해결 사례는 질문자 동의(질문 등록 때 선택, 기본 꺼짐 — 결정 #17)와 편집자 승인, 개인정보 가림 확인이 모두 있어야 홈에 나옵니다. 하나라도 없으면 공개 뷰에 0행입니다.
- 카드 문장(상황·쟁점·결과·교훈)은 편집자가 직접 씁니다. AI가 쓰지 않고, 세무 결론을 만들지 않습니다. 동의 안내 문구는 법률 검토본이 들어갈 빈 자리이며 개발이 쓰지 않습니다(화면의 한 줄은 기능 설명용).
- O5 분류는 정규식 + 운영자 큐까지 만듭니다. AI 분류 단계는 4단계 AI 공통 기반 운영 뒤에 켜므로 지금은 만들지 않습니다(모델 호출 0, `source`는 `regex`만 허용). 켤 때 DB 허용 값과 NT9 경계를 함께 바꿉니다.
- 국세 금액 0(NT1~NT9). 기능 키 `solved_cases`는 꺼짐으로 출하합니다(190에서 이미 추가됨).

## 1. 이름과 위치
- 마이그레이션 223 `20261027000223_w13h_solved_cases.sql`, 224 `20261027000224_w13h_qna_classify.sql`. 225는 예비입니다.
- 서버 규칙 `apps/web/lib/qna/solved.ts`·`classify.ts`(순수), DB 호출 `apps/web/lib/server/qna/solved.ts`(회원 동의 철회·관리 읽기)·`apps/web/lib/server/public/solved-cases.ts`(공개 읽기).
- 화면: 홈 `해결 사례` 블록(`SolvedCasesSlot`, 기능 키 `solved_cases` 꺼짐이거나 승인된 사례가 0이면 렌더 0) · 관리 `/admin/solved-cases`(권한 `solved_case.approve`, 새 메뉴 `해결 사례` 한 줄). 분류 큐도 같은 화면에 둡니다(편집 책임자·관리자 같은 대상이라 W13-g 파일을 고치지 않기 위함).
- 이벤트는 이미 있는 `solved_case_clicked`(placement=home)만 씁니다. 속성에 질문 본문·식별 값 0.

규칙
- 후보 = 동의한 질문 ∧ 공개(open) ∧ 채택된 답변 있음. 동의하지 않은 글은 `qna_solved_case_save`가 거부합니다.
- 승인 = 가림 확인 체크 + 승인자 기록 + 네 칸 모두 채움. 카드 문장을 고치면 초안으로 돌아가 다시 승인해야 합니다. 카드 문장에도 개인정보 모양 검사(`qna_pii_problem`)가 걸립니다.
- 공개 뷰 = 승인됨 ∧ 지금도 동의 ∧ 원 질문이 open(숨김·보류 제외) ∧ 채택 유지 ∧ 라운지 열림 ∧ 기능 키 켜짐. 동의를 철회하거나 질문이 숨겨지면 다음 요청부터 빠집니다(읽는 순간 판정, 캐시 없이 읽음). 작성자 번호·세목 외 식별 칸이 뷰에 없습니다.
- 분류 제안은 질문 등록 직후 서버가 정규식으로 만들어 큐에 넣습니다(실패해도 등록은 성공). 운영자가 수락하면 해결 사례 카드 세목이 바뀝니다. 질문 본문·세목은 DB 규칙상 고치지 않습니다.

## 3. 시험
- vitest: 분류 정규식(세목 후보·순서·없음), 해결 사례 입력 검사(네 칸·길이·개인정보 모양·가림 확인), 질문 입력의 동의 칸.
- DB(`packages/db/tests/w13h-solved.test.mjs`): 동의 없는 글 후보 거부, 가림 확인 없이 승인 거부, 승인 뒤 공개 뷰, 철회 즉시 제외, 질문 숨김 제외, 개인정보 모양 카드 거부, 재동의 거부, 분류 제안·수락, source 허용 값, anon 직접 접근 0.
- E2E(`e2e/w13h-acceptance.test.mjs`, 작성만): 키 꺼짐 홈 블록 0, 승인 흐름, 철회 뒤 홈에서 빠짐, 질문 폼 동의 체크 기본 꺼짐.

## 4. PO 입력 / 막힘
동의 안내 문구(법률 검토본), AI 분류 단계(4단계 AI 공통 기반 운영 뒤), 해결 사례 카드 문장 작성(편집자), 동의 철회 화면 위치(내 질문 목록은 계정 화면 확장 때).

## 5. 남은 과제
- 질문자 동의 철회는 API(`/api/qna/solved-consent`)까지 만들었고 화면 버튼은 계정 화면에 내 질문 목록이 생길 때 붙입니다.
- 비슷한 질문 연결·참고 자료 링크(AIOPS-15의 나머지)는 운영자 입력 화면 없이 이번 단위에 넣지 않았습니다.
