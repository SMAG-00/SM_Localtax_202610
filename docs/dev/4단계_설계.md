# 4단계(W12) 근거형 지방세봇: 작업 단위 설계 (개발 문서)

PRD-04(v2.0, 요구사항 54개 — 2026-10-25 FAM-09 개정 반영)와 PRD_최종 §11.1 W12 행("근거형 지방세봇을 도우미 창의 별도 모드로 공개 — 300문항 평가 통과")을 구현할 때 작업 단위·순서·마이그레이션 번호·데이터 이름을 맞추려고 정한 약속입니다. 이 문서와 PRD가 다르면 PRD를 따르고 이 문서를 고칩니다. 1~3단계 설계 문서의 값 목록·공개 읽기·캐시·기능 키·감사·승인 RPC 규칙과 W7b 도우미 설계(`docs/dev/W7b_설계.md`)의 마스킹·공개 키·기록 규칙은 그대로 따릅니다. (2026-10-26 작성)

**지키는 선 (1~3단계 설계와 같음)**
- 실제 법령·세무 문장, 세율·공제·기한·한도 값, 감면·판정 요건, 달력 날짜를 쓰지 않습니다. 개발 중의 AI(Claude Code)는 구조와 시험 자료만 만듭니다 — 시험용 원문 청크·평가 문항·정답·요건 항목·범위 안내 문구는 모두 `시험용` 표시 + 지어낸 값입니다. 평가셋 정답·필수 근거·요건 사전·고정 안내 문구·모드 고지·금지 표현 추가분은 빈 칸으로 두고 PO·감수 입력으로 채웁니다.
- 지방세봇 답변은 AI가 쓰는 세무 안내이므로 평가 게이트 리포트(EVAL-04) + 관리자 승인 + 검증기 V1~V6 + 'AI 답변' 고지를 모두 거친 문단만, 승인된 공개 대상에게만 나갑니다. 편집국 AI(O2·O3·O6) 산출물은 `review_items`에만 쓰고 사람이 승인한 것만 공개합니다.
- AI는 국세(양도세·상속세·증여세) 금액을 만들지 않습니다(PRD_최종 §2.2 원칙 ④ 개정본). 지방세봇·도우미·편집국 배치는 `@ltr/igt-engine`을 불러오지 않고(NT9), `run_calculator`에는 지방세 엔진 계산 종류만 있습니다. 상속세·증여세 질문은 금액 없이 링크로만 보냅니다 — 3단계 게이트가 열린 세목은 자체 계산기, 닫힌 세목은 외부 계산기·국세청 공식 안내입니다(FAM-09).
- 새 기능은 모두 기능 키·범위 플래그·공개 단계(4a·4b·4c)를 꺼 둔 채 출하합니다. 코드 완료와 공개 승인은 따로 둡니다.
- 사용자 경로 AI는 서버 전용 상용 키 `ANTHROPIC_API_KEY`만 쓰고, service role 키를 쓰지 않으며, 모델 ID는 환경변수에서만 읽습니다(코드 상수 0, 30일 보관 모델 계열이면 기동 실패). SM 부동산 세금 플랫폼과 「안심 상속증여계산기」 저장소는 이 단계에서 읽지도 않습니다.
- 분야 이름: 지방세·부동산세금(`/tax`) / 부동산재테크(`/realestate`) / 부동산금융(`/finance`) / 지자체뉴스(`/local`). 사이트 이름은 `packages/ui/src/brand.ts`에서만 읽습니다.

## 0. 전제와 현재 위치

### 0.1 일정
PO 결정(2026-10-25): 2~5단계를 모두 구축 → 내부 보고·합격 → W9 이관 → 공개. PRD-04 2장의 공개 계획(4a 내부 → 4b 초청 전문가 → 4c 대국민)은 공개 조건으로 남고, 게이트 리포트가 나오기 전에는 공개 위젯이 아니라 관리 화면(`/admin/eval`의 한 문항 시험·평가 실행)에서만 지방세봇을 돌립니다. 공개 뒤에만 잴 수 있는 것(진입점별 이용 4주 기준선, 4c 뒤 28일 표본 감수, 해결률)은 공개 뒤로 미룹니다. 시간이 걸리는 증거(보존 기한 파기, 표본 감수 부족 경고, 월 예산 경보, 수집 뒤 1시간 색인 반영)는 테스트 주소에서 시각을 주입해 미리 확인합니다.

### 0.2 3단계에서 아직 끝나지 않은 것 (2026-10-26 기준)
W11-0·a~g 코드와 통합 보정(`d5ac135`)은 커밋되어 있고, W11-z 수용 묶음(`e2e/w11-acceptance`)·push·3단계 마이그레이션 원격 적용이 남았습니다(날마다 바뀌는 세부의 정본은 `docs/dev/진행_현황.md`). 4단계가 읽는 3단계 표는 `guides`·`guide_versions`(111), 판정표 kind·`requirement_dictionary`(112), `issue_tags`·`case_issue_tags`(123), `issue_graphs`(124)입니다. W12-0은 W11-z가 141~149 예비 번호 사용을 정한 뒤 시작합니다(번호 충돌 방지). (2026-10-26 W12-0 완료: 마이그레이션 `20261026000150_w12_common.sql`, 로컬 커밋 — 원격 적용은 W12-z에서 번호 순서대로.) W12-0 뒤 바로 시작할 수 있는 단위는 W12-a·W12-e(e1~e3)·W12-f·W12-g입니다.

### 0.4 코드 실사 (읽기만, 2026-10-26)
- `packages/assistant`·`packages/agent`는 README만 있습니다. 도우미 코드는 W7b 결정 #1에 따라 `apps/web/lib/assistant/`·`apps/web/lib/server/assistant/`에 있습니다.
- **경계 검사 빈틈**: `scripts/check-national-tax.mjs` NT9의 `AI_DIRS`(`packages/assistant/`·`packages/agent/`·`workflows/`)와 `scripts/forbidden-packages.json`의 `aiForbiddenDirs`가 `packages/*`만 봅니다. 그래서 지금 도우미·운영 AI 웹 코드(`apps/web/lib/assistant/`·`lib/server/assistant/`·`lib/server/ops-ai/`)는 상속·증여 엔진 import 검사 밖입니다(현재 위반 0건). W12-0에서 목록을 넓힙니다.
- AI 호출은 SDK가 아니라 HTTP 클라이언트(`lib/assistant/anthropic.ts`, `workflows/src/ops/ops-model.ts`)이고, `aiSdkAllowed`에는 `packages/assistant`·`workflows`만 있습니다.
- 도우미 응답은 SSE가 아니라 한 번에 JSON입니다(W7b 결정 #3). 지방세봇은 SSE가 필수입니다(ASK-01, PRD-04 6.13).
- pgvector 확장이 없습니다(마이그레이션 0001~0138).
- 측정 이벤트는 85종입니다. PRD-04 15장 22종 가운데 `external_calculator_opened`·`wetax_handoff`는 이미 있어 속성 값만 더하고, 20종이 새것입니다.
- `case_issue_tags.origin` 제약은 `editor`뿐이고 `issue_tags`에 `tax_items` 칸이 없습니다(123).
- PRD-04 머리말과 1.5 표의 원칙 ④ 줄은 개정 전 문구(국세 금액 미산출)로 남아 있습니다. 지방세봇 동작(AI는 국세 금액 0)은 개정본과 같으므로 이 설계는 개정본을 따르고, PRD-04 문구를 고칠지는 PO에게 알립니다.

## 4. 재사용 규칙

### 4.1 W7b·W10·W11 코드 재사용
마스킹·주입 방어·금지 모델 검사·HTTP 클라이언트는 `lib/assistant` 것을 불러 씁니다(복사 0). 기록은 공개 키 + `security definer` 함수, 지시문은 `prompt_versions`, 실시간 조회는 `pipeline-law` 클라이언트·`data_sources` 관문·`raw_snapshots`, 검수는 `review_item_transition` 하나, 계산·감면·판정은 W10-a 엔진·평가기와 W11-a 판정표, 계산기 카드는 `toolLinkFor`·`official_links`·`wetax_links`, 편집국 AI는 W10-e `OpsModel`·`ops_ai_budget`·`agent_runs`, 등급은 `has_entitlement`, 사람 연결은 W7c 두 버튼입니다. AI 호출은 새 의존 없이 HTTP 클라이언트로 하고(SDK를 들이면 `aiSdkAllowed` 목록 안에서만), 바깥 호출 주소는 한 모듈의 허용 목록(Anthropic API·국가법령정보 API·선정된 임베딩 API)만 씁니다. 수집·색인·감면·판정·통계에는 AI 0(AI 호출 검사 대상).

### 4.2 평가셋
- 기본 300문항·확장 평가셋(신탁·정비 100 · 상속 취득세 30 이상 · 증여 취득세 30 이상 · 추천·예측 차단 30 · 사칭 요청)의 문항·정답·필수 근거·금지 주장은 PO가 쓰고 보조 세무 전문가가 교차 확인합니다. Claude Code는 문항 표·화면·실행기와 `시험용` 견본 문항(`is_test=true`)만 만듭니다.
- 구성 수·교차 유형 최소 수·게이트 수치의 원본은 PRD-04 9장입니다. 4c 값(PRD_최종 §12 첫 문단 — 정답률·인용 정밀도·필수 근거 재현율·역질문 누락·치명 오류)은 낮추지 않습니다.
- 채점은 2인 블라인드(다른 채점자 판정·모델 이름을 숨김), 불일치는 '미확정'으로 집계에서 빼고 원문 재확인 기록 뒤 3인째로 넘깁니다. AI 채점은 대량 회귀의 1차 선별에만 쓰고 게이트 집계에는 사람 판정만 넣습니다.
- 실시간 조회 사례는 색인 제외 목록을 건 별도 실행으로, 회귀는 고정 실응답 견본, 게이트 판정 때 실제 API로 한 번 더 돌립니다.
- 대화에서 옮긴 문항은 익명화 검토 기록이 있어야 저장합니다(W7b 방식). 월간지·총람 출처 문항은 평가 사용 권리(T1) 확인 전 0입니다.
- 지시문·모델·색인 버전·룰셋·판정표가 바뀌면 전체 회귀를 돌리고, 회귀 결과 없이 운영에 반영하지 않습니다(EVAL-03).

### 4.3 인용 검증
재순위를 거친 청크 8~12개를 문서 블록으로 넣고 문서 제목 칸에 `source_id`를 둡니다. 인용 칩의 번호·일자·링크는 렌더러가 DB 원문 메타(실시간 원문은 `raw_snapshots` 응답 원본)에서 채웁니다. V1 결론·요건 문장마다 인용 1개 이상, V2 본문 조문·사건번호(정규식 추출)가 인용 문서 메타에 있고 실시간 인용은 스냅샷 해시가 맞을 때만, V4 인용 조문이 기준일에 시행 중이거나 표기가 있음을 문단 단위로 검사합니다. 근거 점수가 기준에 못 미치면 근거 부족 응답, 재생성 뒤에도 실패하면 근거 목록 응답입니다. 서명 전·회수된 가이드·쟁점 지도 버전 청크는 색인에 없고, 지도 인용에는 렌더러가 서명된 지도 버전·감수일을 붙입니다.

### 4.4 거절·범위 안내
- 규칙 사전이 먼저 잡고 모델 결과는 그것을 풀 수 없습니다(W7b 결정 #4와 같은 단방향): 투자 추천·시세·금리 예측(ASK-20, 끌 설정 없음) · 지역 관광 질문(ASK-21, 지역 허브·관광 링크 0) · 양도세 금액(ASK-09) · 상속세·증여세 금액·공제(FAM-09, 플래그와 무관) · 실존 인물 사칭(BR-09) · 범위 플래그가 꺼진 주제(ASK-19·FAM-09) · 고위험 배너(ASK-08).
- 범위 안내 응답은 PRD-04 6.4 골격(한 줄 안내 + 링크 2~3개 + 하단 고정)이고 모델 문장이 들어가지 않습니다. 한 줄 안내는 PO 승인 고정 문구이며, 초안은 "다루지 않습니다·갈 곳은 이곳입니다" 수준의 길 안내만 씁니다(세무 내용 0).
- 링크는 `official_links`·`wetax_links`·`toolLinkFor`에서만 읽고 질문·입력값·세션 ID를 경로·쿼리·해시에 붙이지 않습니다. 링크가 `broken`이면 국세청 공식 안내만 둡니다.
- 모델 거절 → 서버 폴백 → 그래도 실패하면 검색 모드(ASK-15)입니다.

### 4.5 비용 가드
- 등급별 하루 한도·세션 턴·역질문 상한·청크·토큰 상한·실시간 조회 상한은 모두 설정(`ask_limits`·`ask_live_fetch_policy`)에서 읽고 코드 상수 0입니다. 하루 한도는 사용자가 보내기를 눌렀을 때만 차감합니다.
- 월 예산·단가(`ask_budget`·`ask_pricing`)가 비어 있으면 지방세봇 호출 0입니다. 80%에서 경보(`review_items` — W10-e 방식, 달마다 1건), 100%에서 비회원부터 검색 모드입니다. 비용은 API 응답의 사용량 × 설정 단가이고, 같은 키를 쓰는 도우미·지방세봇·운영 배치는 모드 표지로 나눕니다.
- Opus 5.5 단일 기본안으로 시작하고, 혼합안은 같은 평가셋에서 정답률·인용 정밀도 차이가 2%p 이내라는 실행 기록이 있을 때만 단계별로 바꿉니다. 지시문·도구 정의는 고정해 앞에 두고 기준일·범위 플래그 같은 가변 값과 문서 블록은 마지막 캐시 지점 뒤에 둡니다.
- 새 환경변수: `AGENT_MODEL_ANSWER`·`AGENT_MODEL_UTILITY`·`AGENT_EFFORT_ANSWER`·`AGENT_EFFORT_EXPERT`·`AGENT_EFFORT_UTILITY` · 임베딩 `EMBEDDING_PROVIDER`·`EMBEDDING_MODEL`·`EMBEDDING_API_KEY`(공급자 결정 뒤 확정) · `LAW_API_OC`는 웹 서버 범위를 더합니다. 운영 배치는 W10-e 변수를 그대로 씁니다.

### 4.6 AI가 쓴 법·세무 글의 공개
- 개발 중에 Claude Code가 쓰는 것은 구조와 `시험용` 자료뿐입니다(지키는 선).
- 편집국 AI 산출물(요지·태그 후보·3줄 요약·"내게 무슨 의미?"·카드뉴스·채널 원고·개정 영향 배너 제안)은 `review_items`·제안 행에만 들어가고, 공개 표 쓰기 권한이 없으며, 편집자 승인 전 노출 0, 공개분에는 AI 활용 표기를 붙입니다. 채널 게시는 사람이 합니다.
- 지방세봇 답변은 게시 콘텐츠가 아닙니다. 게이트·검증기·고지를 지난 문단만 그 사용자에게 보이고, 답변을 기사·가이드·요지·평가 문항으로 옮기려면 편집국 검수(평가 문항은 익명화 + 감수)를 거칩니다.
- 지시문·고정 안내 문구·모드 고지·V5 사전·요건 사전·역질문 선택지 문안은 PO·감수 입력이며 버전으로 관리합니다(평가 실행 없이 `active` 0).
- 실시간 조회 원문은 '미검수'로 표시하고, 수집 대기열 검수를 마치기 전에는 색인에 넣지 않습니다.

### 4.7 국세 경계
0차에서 넓힌 NT9·`aiForbiddenDirs` 목록이 웹 쪽 AI 코드까지 덮습니다. `run_calculator`의 계산 종류는 지방세 엔진 export 허용 목록뿐입니다. V3가 양도세·상속세·증여세 금액·공제 문장을 막고 안내로 바꿉니다. 상속세·증여세 요건(상속재산·가족관계·증여 이력)은 묻지도 기록하지도 않습니다(PRD-04 6.2.2). 허용 구역(`national-tax-zones.json`)에 AI 경로를 넣지 않고, 국세 낱말이 필요한 감지 정규식·안내 문구는 NT1~NT5에 걸리지 않는 모양으로만 씁니다(W7b `verify.ts` 방식). 지방세 결과와 국세 금액의 한 줄 합계 0, 계산 답변에서 원인이 상속·증여면 "상속세·증여세는 이 계산에 포함되지 않습니다" 한 줄(PRD-02 FAM-04와 같은 문장)입니다.
