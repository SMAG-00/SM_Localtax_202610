# F2 설계 — 기자·기고자 등록부와 본문 서식 보강

합격 시험 2단계(실제 글 1개 올리기)에서 기사 생성이 409로 막혔습니다. 편집국 계정에 연결된 인물(people)을 만들 화면과 API가 없었기 때문입니다(PRD-01A NAV-19 누락).

## 결정과 이유

1. **API** `/api/admin/people`(목록·등록), `/api/admin/people/[id]`(조회·수정·계정 연결/해제). 권한 `people.manage`는 관리자만이며 거부는 감사에 남깁니다. 한 계정에 인물 하나는 기존 DB 제약(`people_staff_user_id_key`)이 지키고, 위반은 409 문장으로 바꿉니다. `registered_at`은 DB 기본값(서버)이며 입력으로 받지 않습니다(422). 약력·동의서는 받지 않습니다(브랜드 화면의 몫). 모든 변경은 audit_logs에 전후 값과 함께 남깁니다.
2. **마이그레이션 없음.** 필요한 칸·제약이 이미 있어 권한·RLS·공개 뷰를 건드리지 않습니다. 새 코드는 service_role로만 people을 읽으므로 공개 뷰로 내부 칸이 새지 않습니다.
3. **화면** `/admin/people`: 등록 폼, 목록, 계정 연결(편집국 계정 목록은 listMembers, 이미 연결된 계정은 후보에서 뺍니다). 기사 생성 409 문구에 `/admin/people` 안내를 넣었습니다.
4. **본문 서식**: `lib/text/inline-markup.ts` 한 곳이 `**굵게**`와 `[글](URL)`(균형 잡힌 괄호 두 겹까지)을 읽습니다. 공개 화면·관리자 미리보기·글자 수·SEO 본문이 같은 규칙을 씁니다. 링크 허용 주소는 http/https와 사이트 안 경로뿐이며 바깥 주소는 `target=_blank rel="noopener noreferrer"`. 그 밖의 HTML·마크다운은 해석하지 않습니다.
5. **license_cleared**: DB 계산 칸으로 '공공누리 유형이 허용 유형에 든다'는 뜻일 뿐 권리 확인이 아닙니다. media 응답에서 `license_type_allowed`로 이름을 바꿨습니다. 권리 확인은 `rights_status`만 봅니다.
6. **메뉴**: 관리자 메뉴 `기자·기고자 등록부`(사진 보관함 뒤, 분야 앞). E2E 정확 목록에 '사진 보관함'(기자·편집 책임자)을 반영했습니다.
