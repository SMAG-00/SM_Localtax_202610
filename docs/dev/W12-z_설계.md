## 2. 이번에 고친 것

- **비회원 한도 IP**: 기존 `clientIp`는 `x-real-ip`를 먼저 읽습니다. Vercel은 이 머리글도 덮어쓰지만, 사내 Caddy는 `x-forwarded-for`만 접속 주소로 다시 쓰고 `x-real-ip`는 그대로 넘기므로 Docker에서는 이 머리글을 바꿔 보내 한도를 초기화할 수 있었습니다. 지방세봇 한도는 새 `trustedClientIp`(`x-forwarded-for`의 마지막 값만)를 씁니다. 앞쪽에 사용자가 끼운 값과 `x-real-ip`는 무시합니다. `deploy/Caddyfile`에 `trusted_proxies`를 넣지 않는다는 주석을 달고, `w12-acceptance` h가 그 설정이 생기면 실패하도록 지킵니다.
- **`/data/[키]` 긴 제목**: 끊을 곳이 없는 긴 제목이 360px에서 가로 스크롤(74px)을 만들었습니다. 제목과 차트 캡션에 `break-words`를 더했습니다.
- `/security`·`/cases/keywords` 첫 문단 길이를 줄이고, 사용법 문장은 목록 뒤로 옮겼습니다(문구 의미는 그대로).

## 3. Docker 이미지에서 첫 `status` ≤ 1초 (문서화)

CI의 Docker 단계(`e2e/run-docker.mjs`)는 `docker-image`와 `api-health-jobs`만 돌리고, 이미지 안에서 지방세봇 게이트를 열 수 없어 SSE를 재지 않습니다. 같은 시험을 이미지로 돌리려면 `E2E_TARGET=docker node --test e2e/w12b-acceptance.test.mjs`를 로컬에서 실행합니다(`e2e/lib/local.mjs`가 이미지를 빌드해 같은 방식으로 띄우고 설정 값은 같은 로컬 DB를 씁니다). 이 시험의 b)가 첫 이벤트 시각과 `x-accel-buffering: no`를 확인합니다. 사내 중계는 `flush_interval -1`이며 `w12-acceptance` h가 지킵니다. 사내 서버 실측은 배포 뒤 PO 입력입니다.

## 4. 알려진 한계와 남은 과제

1. **R1 측정만**: `/security`(7항목)와 `/cases/keywords`(결정례 목록)는 360px 첫 화면이 177자·205자입니다(기준 150자). 짧은 안내 화면용 규칙을 목록형 화면에 그대로 적용할지 PO 판단이 필요해, 이 두 화면은 R1을 측정만 하고(R2·R3·접근성·가로 스크롤은 강제) 나머지 화면은 모두 강제합니다.
2. **다른 속도 제한도 `trustedClientIp`로 옮기기** (검색·폼·가입 등): 지금은 `x-real-ip`가 우선이라 Docker에서 우회될 수 있습니다. 이번에는 고치지 않았습니다. 기존 E2E 7개(account-recovery·account-security·account-signup·search-terms·site-search·w2d·w2e)가 `x-real-ip`로 IP를 흉내 내므로 시험 방식을 `x-forwarded-for`로 함께 바꿔야 합니다.
3. `run_determination`의 정상 입력 경로(공개 판정표가 있는 종류)는 HTTP 시험에서 잘못된 입력만 확인했습니다. 정상 경로는 `agent-calc.test.ts`가 덮습니다.
4. 도우미 마스킹이 "로 12345원"처럼 '로' 뒤 숫자를 주소로 가리는 W7b 기존 동작은 그대로입니다(W12-b 한계).
