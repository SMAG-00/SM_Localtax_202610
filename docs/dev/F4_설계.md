# F4 설계 — 관리자 화면 길잡이

## 1. 메뉴 묶음

- 정본은 `apps/web/lib/admin/menu.ts`의 `MENU_GROUPS`입니다. 항목의 보이는 조건(when)과 이름은 그대로이고, 모든 항목은 정확히 한 그룹에 속합니다(`menu.test.ts`가 확인).
- 보이는 항목이 0개인 그룹은 숨깁니다. 평면 목록 `adminMenu()`는 그대로이고, 묶음은 `adminMenuGroups()`가 만듭니다.
- 화면(`AdminNav.tsx`): 그룹 버튼(`aria-expanded`)을 누르면 항목이 두 번째 줄에 펼쳐집니다. 지금 화면이 속한 그룹은 처음부터 펼쳐지고, Esc는 펼친 그룹을 닫고 그 버튼으로 포커스를 돌립니다. 아래 방향키는 첫 항목으로 이동합니다. 360px에서는 '메뉴' 버튼 하나로 접히고, 열면 그룹이 세로로 쌓입니다. 항목 링크는 닫힌 그룹에서도 문서에 남습니다.

| 그룹 | 항목 |
|---|---|
| 기사 만들기·발행 | 첫 화면, 기사 기획, 기사, 검토·발행, 사진 보관함, 기자·기고자 등록부, 감수 가이드, 편집국 AI |

## 2. 발행까지 할 일 단계표

- 기사 편집 화면의 제목 아래, 탭 위에 둡니다(`PublishSteps.tsx`). 발행 전(draft·held·검토 중·승인) 기사에만 보입니다.
- 판정은 서버 페이지가 `gateFor`(GET check와 같은 판정)로 한 번 읽고, 변환은 순수 함수 `lib/admin/publish-steps.ts`의 `publishSteps()`가 합니다. 화면은 따로 판정하지 않습니다. 저장·출처 추가 뒤 `router.refresh()`로 서버가 표를 새로 만듭니다.
- 막힘(level=block)만 단계에 넣습니다. 경고는 점검 패널에 맡깁니다. 각 막힘은 한 단계에만 들어갑니다.

| 번호 | 단계 | 누가 | 이 단계에 들어가는 막힘 | 바로 가기 |
|---|---|---|---|---|
| 1 | 본문·기본 정보 저장 | 기자 | art01.*, nav03.author-required, 제목·요약·주소 칸 | 해당 입력 칸 |
| 2 | 사진 권리 확인 | 편집 책임자 | nav04.image-rights | /admin/media |
| 3 | 출처 더하기 | 기자 | nav04.sources-required, pr13.bill-status-source, pr07.license-required | 출처 더하기 폼 첫 칸 |
| 4 | 그 밖의 막힘 | 기자 | 위에 없는 모든 막힘(모르는 ID 포함, 메시지 그대로) + 문장 없는 failed ID | location의 field·blockIndex 칸, 모르면 점검 패널 |
| 5 | 검수 요청 | 기자 | (상태가 초안·보류이면 할 일) | 검토 요청 버튼 |
| 6 | 세무 감수 서명 | 세무 감수위원 | nav03.tax-review-required | /admin/reviews/{id}#tax-review |
| 7 | 편집 승인 | 편집 책임자(작성자 아님) | nav03.desk-edit-required, nav12.self-desk-edit | /admin/reviews/{id}#desk-edit |
| 8 | 발행 | 편집 책임자 | 모든 막힘이 풀리면 활성 | 점검·발행 칸의 발행 버튼 |

- 상태: 끝남 ✓ / 할 일 / 다른 사람 차례(지금 계정이 할 수 없는 단계). 작성자 본인이 로그인 중이면 편집 승인은 "작성자가 아닌 편집 책임자 계정으로 로그인해 승인"으로 안내합니다.
- 편집 승인은 버전에 묶이므로 "다른 단계를 다 끝낸 뒤 마지막에" 안내를 붙입니다.
- 출처 칸마다 짧은 설명(hint·placeholder)을 보강했습니다. 법안 상태 기사는 출처 종류=공식 문서, 자료 종류=법률안·입법예고(bill), 확인일=원문을 연 날입니다.
