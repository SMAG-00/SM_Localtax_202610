## 1. 메뉴 묶음

PO 결정(2026-10-31): 디펜스투데이 벤치마킹으로 관리자 화면을 단순화합니다 — 메뉴는 날마다 쓰는 것만 처음부터 보이고, 발행 단계표는 3단계로 묶습니다(2장).

- 정본은 `apps/web/lib/admin/menu.ts`의 `DAILY_MENU_IDS`(날마다 쓰는 메뉴)와 `MENU_GROUPS`(그 밖의 항목)입니다. 항목의 보이는 조건(when)과 이름은 그대로이고, 두 목록을 합치면 모든 항목이 정확히 한 번 나옵니다(`menu.test.ts`가 확인).
- 날마다 쓰는 메뉴 6개(첫 화면, 기사, 사진 보관함, 검토·발행, 브리핑, 측정 지표 — 권한으로 보이는 것만)는 메뉴 줄에 처음부터 보입니다(`adminDailyMenu()`). 나머지는 [더 보기] 버튼(`aria-expanded`) 안에 아래 7개 그룹으로 들어갑니다(`adminMenuGroups()`). 보이는 항목이 0개인 그룹은 숨깁니다. 평면 목록 `adminMenu()`는 그대로입니다.
- 화면(`AdminNav.tsx`): 그룹 버튼(`aria-expanded`)을 누르면 항목이 두 번째 줄에 펼쳐집니다. 지금 화면이 [더 보기] 안의 그룹에 속하면 [더 보기]와 그 그룹이 처음부터 펼쳐집니다. Esc는 펼친 그룹(없으면 [더 보기])을 닫고 그 버튼으로 포커스를 돌립니다. 아래 방향키는 첫 항목으로 이동합니다. 360px에서는 '메뉴' 버튼 하나로 접히고, 열면 날마다 쓰는 메뉴와 [더 보기]가 세로로 쌓입니다. 항목 링크는 닫힌 그룹에서도 문서에 남습니다.

| [더 보기] 그룹 | 항목 |
|---|---|
| 기사 만들기·발행 | 기사 기획, 기자·기고자 등록부, 감수 가이드, 편집국 AI |
| 배치·노출 | 기사 배치, 홈 배치, 캠페인 랜딩, 허브 지방세 포인트, 금주 부동산 재테크, 상황 카드, 채널 배포 키트, 검색 최적화 |
| 지방세 자료·연결 | 개정 트래커, 조례 연결, 쟁점 연결 지도, 쟁점 태그, 지방세 통계, 지식창고, 바깥 연결, 계산기 연결, 분야, 사전, 검색어 |
| 검수·품질 | 원문 검수, 공통 검수, 단계 지방세로 읽기 감수, 국세 계산 감수, 룰셋·판정표, 정확도 대조, 평가·게이트, 품질 콘솔, 지역 기사 판정 |
| 분야 콘텐츠 | 분양 정보, 개발방법 비교, 부동산금융, 지자체뉴스, 프로젝트, 해결 사례, 라운지 관리, 전문가 등재 |
| 수익·제휴 | 광고·협찬 콘텐츠, 제휴사, 제휴 피드, 제휴 준비, 라이선스·연재, 기관 구독, 프리미엄 리포트, 스토어·구독 |

## 2. 발행까지 할 일 단계표

- 기사 편집 화면의 제목 아래, 탭 위에 둡니다(`PublishSteps.tsx`). 발행 전(draft·held·검토 중·승인) 기사에만 보입니다.
- 판정은 서버 페이지가 `gateFor`(GET check와 같은 판정)로 한 번 읽고, 변환은 순수 함수 `lib/admin/publish-steps.ts`의 `publishSteps()`가 합니다. 화면은 따로 판정하지 않습니다. 저장·출처 추가 뒤 `router.refresh()`로 서버가 표를 새로 만듭니다.
- 막힘(level=block)만 항목에 넣습니다. 경고는 점검 패널에 맡깁니다. 각 막힘은 한 항목에만 들어갑니다.
- 2026-10-31부터 3단계(① 쓰기 → ② 확인 → ③ 발행)로 묶습니다. 예전 8단계는 판정·데이터를 바꾸지 않고 그대로 단계 안의 항목이 됩니다.

| 단계 | 항목 | 누가 | 이 항목에 들어가는 막힘 | 바로 가기 |
|---|---|---|---|---|
| ① 쓰기 | 본문·기본 정보 저장 | 기자 | art01.*, nav03.author-required, 제목·요약·주소 칸 | 해당 입력 칸 |
| ① 쓰기 | 사진 권리 확인 | 편집 책임자 | nav04.image-rights | /admin/media |
| ① 쓰기 | 출처 더하기 | 기자 | nav04.sources-required, pr13.bill-status-source, pr07.license-required | 출처 더하기 폼 첫 칸 |
| ① 쓰기 | 그 밖의 막힘 | 기자 | 위에 없는 모든 막힘(모르는 ID 포함, 메시지 그대로) + 문장 없는 failed ID | location의 field·blockIndex 칸, 모르면 점검 패널 |
| ② 확인 | 검수 요청 | 기자 | (상태가 초안·보류이면 할 일) | 검토 요청 버튼 |
| ② 확인 | 세무 감수 | 세무 감수위원 | nav03.tax-review-required | 한 버튼 칸, 없으면 /admin/reviews/{id}#tax-review |
| ② 확인 | 편집 승인 | 편집 책임자(작성자 아님, 본인 발행은 예외) | nav03.desk-edit-required, nav12.self-desk-edit | 한 버튼 칸, 없으면 /admin/reviews/{id}#desk-edit |
| ③ 발행 | 발행 | 편집 책임자 | 모든 막힘이 풀리면 활성 | 점검·발행 칸의 발행 버튼 |

- 상태: 끝남 ✓ / 할 일 / 다른 사람 차례(지금 계정이 할 수 없는 항목). 작성자 본인이 로그인 중이고 본인 발행 대상이 아니면 편집 승인은 "작성자가 아닌 편집 책임자 계정으로 로그인해 승인"으로 안내합니다.
- 편집 승인은 버전에 묶이므로 "다른 일을 다 끝낸 뒤 마지막에" 안내를 붙입니다.
- 출처 칸마다 짧은 설명(hint·placeholder)을 보강했습니다. 법안 상태 기사는 출처 종류=공식 문서, 자료 종류=법률안·입법예고(bill), 확인일=원문을 연 날입니다.
- 쓰기 화면의 기본 정보 칸(`editor/MetaFields.tsx`)은 자주 쓰는 칸만 먼저 보이고, 나머지는 [더 보기]로 펼칩니다(`lib/admin/meta-more.ts`).

### 2.1 ② 확인 한 버튼 (`ConfirmPublish.tsx` · `lib/admin/confirm-publish.ts`)

- 지금 계정이 남은 확인(세무 감수·편집 승인)과 발행을 모두 할 수 있을 때만 ② 확인 안에 '한 번에 확인하고 발행' 칸이 나옵니다(`ConfirmPlan`). 기자 계정에는 없습니다.
- 버튼 이름은 세 가지입니다.

| 버튼 | 누구 | 보내는 요청(순서) |
|---|---|---|
| 감수하고 발행 | 세무 감수 대상 기사 · 감수위원 + 편집 책임자 역할이 모두 있고 작성자가 아닌 계정 | 세무 감수 승인(tax_review) → 편집 승인(desk_edit) → 발행 |
| 승인하고 발행 | 세무 감수가 남지 않은 기사 · 작성자가 아닌 편집 책임자 | 편집 승인 → 발행 |
| 본인 발행 | 아래 본인 발행 조건을 채운 작성자 본인 | 편집 승인(checklist.selfPublish = true) → 발행 |

- 칸 안의 세무 감수 2항목(대상 기사만)과 편집 확인 항목(정량·혼합형은 '인과 단정 없음', 지역 기사는 3항목 추가)을 모두 체크하고 ① 쓰기 막힘이 0일 때만 버튼이 켜집니다. 저장하지 않은 고침이 있으면 보내지 않습니다.
- 이미 있는 API(`POST .../reviews`, `POST .../publish`)를 차례로 부릅니다. 판정은 서버가 다시 하고, 첫 실패에서 멈춰 서버 문장을 그대로 보입니다. 앞에서 끝난 기록은 남으므로 "○○은 기록됐습니다"와 [화면 새로 불러오기]를 함께 보입니다.
- 이 칸이 있으면 검수 요청 없이 바로 진행할 수 있다고 안내합니다.
