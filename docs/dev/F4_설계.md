## 1. 메뉴 묶음

PO 결정(2026-10-31): 디펜스투데이 벤치마킹으로 관리자 화면을 단순화합니다 — 메뉴는 날마다 쓰는 것만 처음부터 보이고, 기사는 작성자가 바로 발행합니다(2.2).

- 정본은 `apps/web/lib/admin/menu.ts`의 `DAILY_MENU_IDS`(날마다 쓰는 메뉴)와 `MENU_GROUPS`(그 밖의 항목)입니다. 항목의 보이는 조건(when)과 이름은 그대로이고, 두 목록을 합치면 모든 항목이 정확히 한 번 나옵니다(`menu.test.ts`가 확인).
- 날마다 쓰는 메뉴 5개(첫 화면, 기사, 사진 보관함, 브리핑, 측정 지표 — 권한으로 보이는 것만)는 메뉴 줄에 처음부터 보입니다(`adminDailyMenu()`). 나머지는 [더 보기] 버튼(`aria-expanded`) 안에 아래 7개 그룹으로 들어갑니다(`adminMenuGroups()`). 보이는 항목이 0개인 그룹은 숨깁니다. 평면 목록 `adminMenu()`는 그대로입니다.
- 화면(`AdminNav.tsx`): 그룹 버튼(`aria-expanded`)을 누르면 항목이 두 번째 줄에 펼쳐집니다. 지금 화면이 [더 보기] 안의 그룹에 속하면 [더 보기]와 그 그룹이 처음부터 펼쳐집니다. Esc는 펼친 그룹(없으면 [더 보기])을 닫고 그 버튼으로 포커스를 돌립니다. 아래 방향키는 첫 항목으로 이동합니다. 360px에서는 '메뉴' 버튼 하나로 접히고, 열면 날마다 쓰는 메뉴와 [더 보기]가 세로로 쌓입니다. 항목 링크는 닫힌 그룹에서도 문서에 남습니다.

## 2. 기사 편집 화면의 발행 흐름

2026-10-31 PO 결정(간편 발행 — 2.2)으로 기사 편집 화면의 발행 단계표와 '확인 한 버튼'(감수하고 발행·승인하고 발행·본인 발행)을 뺐습니다. 이제 작성자가 저장·발행 칸의 [발행]을 한 번 누르면 됩니다.

- **본인 발행** 기록(`checklist.selfPublish`, 마이그레이션 `20261031000234_self_publish.sql`)은 검토 API(`POST .../reviews`)에 그대로 남아 있습니다. 기사 편집 화면의 발행은 2.2의 작성자 발행(`authorPublish`)을 씁니다.

### 2.1 발행 기사 빠른 수정 (PO 지시 2026-10-31 "대폭 간소하게")

- 발행된 기사의 편집 화면(`ArticleWorkspace.tsx`)은 고칠 칸만 보입니다. 순서는 기본 정보 → 본문 → 저장입니다. 칸 바로 가기도 기본 정보·본문·저장·그 밖의 칸 4개뿐입니다.
- 지역 기사 판정·핵심 주장·출처·취재 근거·필수 기록 안내·확인 목록·「지방세로 읽기」·해결 사례는 접힌 '그 밖의 칸' 하나에 넣습니다(`details#more-sections`). 저장 오류가 그 안의 칸을 가리키면 `focusField`가 펼칩니다.
- 오른쪽 점검 결과도 발행된 기사에서는 '발행 점검 결과 보기'로 접습니다. 모든 기사에서 품질 점수·규칙 버전은 '품질 점수 보기'로 접고, 항목마다 붙던 규칙 번호(예: OPT-03 · common.similarity)는 화면 글자에서 빼고 마우스를 올리면 보이게 합니다.
- 수정 사유는 비워 둘 수 있습니다. 비우면 처음 불러온 상태와 비교해 바꾼 칸으로 문장을 만듭니다(`lib/admin/quick-fix.ts` `suggestedFixReason` — "요약 수정"·"제목·본문 수정"·"기타 칸 수정"). 수정 종류(오탈자·실질 수정·정정)는 뜻이 달라 사람이 고릅니다. 서버의 ART-05 검사(종류·사유 필수)는 그대로입니다.
- 쓰는 중인 기사(미발행) 화면은 바뀌지 않습니다.
- 증거: `e2e/simple-publish.test.mjs` e) — 접힘·칸 순서를 확인하고 요약만 고쳐 저장한 뒤 수정 기록 사유 '요약 수정'·종류 typo·게재 유지를 확인합니다.

### 2.2 간편 발행 (PO 결정 2026-10-31 — "복잡한 절차는 모두 뺀다")

기사는 전문기자·회계사·세무사가 써서 올립니다. 그래서 기사 편집 화면은 발행 전후 모두 **기본 정보 → 본문 → 저장·[발행]** 하나의 흐름으로 바꿨습니다. 예전 단계표와 확인 한 버튼은 기사 편집 화면에서 빠졌습니다. 다만 검토·발행 화면(`/admin/reviews/[id]`)에는 그대로 남아 있어서, 편집 확인 항목이 필요한 기사에 씁니다.

- **누가 발행하나**: 기자는 자기 기사, 편집 책임자는 모든 기사(`lib/access.ts` `article.publish`). 칼럼 필자 본인은 자기 칼럼을 발행할 수 없습니다(BR-08). 지역 기사는 편집 책임자의 확인 3항목(REG1-17)이 있어야 공개되므로 기자 화면에는 [발행] 대신 검토 요청이 보입니다.
- **발행 버튼**: 저장·발행 칸의 [발행](`#publish-now`)을 누르면 저장하지 않은 입력을 먼저 저장(PATCH)하고 발행(POST publish)합니다.
  - 남은 차단 문장은 버튼 위 '발행 전에 고칠 것'(`data-testid="publish-blockers"`)에 쉬운 문장으로 보입니다.
  - 점검 결과(경고·점수)는 오른쪽 '점검 결과 보기'에 접어 둡니다.
  - 검토 요청·검토 화면 링크는 발행 권한이 없는 사람에게만 보입니다.
- **발행 API**(`app/api/admin/articles/[id]/publish/route.ts`):
  - 이 버전의 편집 승인이 없으면 발행자 이름으로 편집 승인(`desk_edit approve`)을 함께 남깁니다. 표시는 `checklist.publishApproval`이고, 작성자 본인이면 `authorPublish`, 세무 감수 대상이면 `authorResponsibility`를 더합니다.
  - 지역 기사는 승인 단계를 거쳐 공개합니다.
  - 편집 책임자나 세무 감수위원이 반려·보류한 버전은 409입니다.
  - DB가 편집 확인 항목을 요구하는 기사도 DB 문장 그대로 409입니다. 지역 기사 3항목(REG1-17)과 금융 사례(DF-03)가 여기에 해당합니다.
- **세무 감수**: 작성자 본인 책임으로 대체합니다.
  - 감수 기록이 없으면 발행 기록에 `authorResponsibility: true`를 남기고, 감사 로그 사유는 '작성자 책임 발행 (세무 감수 대체)'입니다.
  - 세무 감수 상태는 감수 기록 없이 approved가 되지 않습니다. 공개 화면의 '감수 ○○'도 서명 기록에서만 그립니다.
- **발행을 막는 규칙**: 판정 정책 `simple`을 씁니다(`@ltr/editorial` `SIMPLE_PUBLISH_BLOCKERS`, `gateFor` 기본값).
  - 법적 의무: 광고·협찬 표시, 사진·공공 자료 저작권, 상속·증여 사례 동의·비식별, 개인정보 형식
  - 기술적 고장: 예약 주소, 임베드 주소, 작성자·분야·유형 없음
  - DB가 같은 조건으로 막는 규칙: 지역 기사 REG1-17, PR-13, PR-14, 공식 자료 칸 REG1-07·09
  - 위에 들지 않는 차단은 경고로 낮춰 발행 기록에만 남깁니다. 발행 뒤 수정에서는 개인정보 형식만 막습니다.
- **DB**(`20261031000235_simple_publish.sql`):
  - `editorial_reviews_guard`가 작성자 본인의 `authorPublish` 승인을 받습니다. 기자·편집 책임자 계정만 해당하고, 칼럼과 반려·보류는 제외합니다.
  - 해석 해설과 고시·조례 자료 해설에서 세무 감수 승인 조건을 뺍니다.
- **새 기사**: 기본 템플릿은 세법 해설입니다(분야 지방세). 지역(지자체뉴스) 기사는 지역 판정 조건이 붙어서 기본값에서 뺐습니다.
- **메뉴**: '검토·발행'은 날마다 쓰는 메뉴에서 빠지고 '더 보기 → 기사 만들기·발행'에 들어갑니다.
- **증거**: `e2e/simple-publish.test.mjs` — 기자가 자기 기사를 화면에서 [발행] 한 번(저장 안 한 요약 포함) → 게재·공개 200·편집 승인 행 `authorPublish`·발행 기록·감사 로그 '작성자 발행', 세금 내용 기사 → `authorResponsibility`·세무 감수 상태 그대로·공개 화면 '감수' 표시 없음, 편집 책임자가 남의 기사 발행, 기자가 남의 기사 발행 403, 저작권 막힘은 '발행 전에 고칠 것'에 보이고 발행 422.
