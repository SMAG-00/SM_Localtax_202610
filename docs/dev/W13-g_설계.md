# W13-g 라운지와 SM 전문가 계정 연결 (EXP-01·02, QNA-01~08) — 설계 약속 (개발 문서)

5단계 설계(`5단계_설계.md`) 1.1절 W13-g 단계와 PRD-05 EXP-01·02·QNA-01~08을 구현할 때 DB·서버·화면·시험이 같은 이름과 규칙을 쓰기 위한 약속입니다. PRD와 다르면 PRD를 따르고 이 문서를 고칩니다. (2026-10-27 작성)

**지키는 선**
- 라운지 답변자는 SM 소속 전문가뿐입니다(PRD_최종 13장 #29). 외부 세무사·회계사·변호사 인증 가입, `/my/expert`, 외부 증빙 칸, 외부 활동 띠, 유료 등재는 만들지 않습니다.
- 중립성 고지·답변 하단 고지·약관 문구는 PO·법률 검토본이 들어갈 빈 자리입니다. 개발이 문구를 쓰지 않으며 승인 전에는 기능 키 `qna`를 켜지 못합니다. 답변은 사람이 쓰고 AI는 답변·세무 결론을 쓰지 않습니다.
- 국세 금액 0(NT1~NT9). 라운지 서버 코드는 `@ltr/igt-engine`을 불러오지 않습니다.
- 기능 키 `qna`·`account_links`는 꺼짐으로 출하합니다(마이그레이션 190에서 이미 추가됨).

## 1. 이름과 위치
- 공개 화면은 PRD 주소를 따라 `/qna`(목록·활동 띠), `/qna/new`, `/qna/[id]`, `/qna/criteria`, `/qna/experts/[id]`입니다. 진입은 `/experts` 목록의 링크(기능 키 `qna`가 켜진 때만)입니다. 5단계 결정 #12(유틸 메뉴 `전문가 소개` 영역에서 진입)와 같습니다.
- 관리: `/admin/experts`에 '계정 연결' 구역(권한 `expert_link.edit`, 관리자만)과 `/admin/qna`(권한 `qna.moderate`, 편집 책임자·관리자) 새 메뉴 `라운지 관리` 한 줄.
- 서버 코드는 `apps/web/lib/qna/`(순수 규칙)와 `apps/web/lib/server/qna/`(DB 호출). 로그인한 회원 번호를 서버가 확인한 뒤 service_role RPC·표로 씁니다(W7c 방식).

규칙
- 배지 유효 = 연결 active ∧ 기한 전 ∧ 프로필 공개·철회 없음. 만료·해제·소속 종료 즉시 배지·활동 띠에서 빠집니다.
- 활동 집계: 창은 `qna_criteria.window_days`(기본 90일). 채택은 채택 시각 기준, 창 시작 시각은 포함. 제재 여부는 제재 중이거나 창 안에 시작된 제재 이력이 있는 경우(PO 확인 필요: '이력 없음'을 전체 기간으로 볼지). 입력에 결제·구독·광고 표 0.
- 띠 선정(서버 `lib/qna/strip.ts`, 순수 함수): 제재 제외 → 최소 채택 수·최소 채택률 이상 → 채택 수 내림차순 → 채택률 내림차순 → 프로필 번호 오름차순(동점 규칙, 기준 페이지에 공개) → 상위 `strip_size`명. 기준이 비어 있으면 띠는 비어 있습니다.
- 질문·답변 본문은 가림이 끝난 글만 저장합니다(`lib/assistant/mask.ts`의 `maskText` 재사용). 가림이 일어난 글은 게시 보류(`pii`), 검출 사전에 걸린 글은 `contact_terms`·`consult_terms`로 보류합니다. 운영자가 확인해 풀기 전에는 공개 뷰에 나오지 않습니다.
- 라운지 글은 `chunks.source_type` 허용 목록에 없으므로 지방세봇·코파일럿 근거가 될 수 없습니다(QNA-07). 채택된 전문가 답변의 편입은 별도 결정(결정 #19 기본값 제외).
- 신고 처리 목표 = 접수 후 1영업일(`lib/qna/logic.ts`의 `reportDueAt`, 서버 계산 → `due_at`). 주말과 설정 `business_holidays`(편집국 AI 기한과 같은 설정, 한국 날짜 목록)를 건너뜁니다. 이 설정은 씨앗이 없어 비어 있으면 주말만 봅니다 — 공휴일 달력 값은 PO 입력이며 한계입니다.
- 스키마에 상담 신청·매칭·소개 대가·건별 수수료·별점·연락처 칸 없음(시험이 열 이름을 검사).

## 3. 화면 규칙
- 라운지 3개 화면(목록·작성·상세)과 답변 하단에 `public_qna_notice`의 고지를 그대로 보여 줍니다. 고지가 없으면 라운지는 열리지 않습니다.
- 전문가 연결은 1단계 두 링크(`/experts`, `/experts/request`)뿐입니다. 질문 원문·작성자 정보를 링크로 넘기지 않으며 상담 신청·매칭·결제 버튼, 연락처·사무소 렌더 0.
- 질문 작성은 개인정보 경고를 확인해야 [등록]이 열립니다. 비슷한 질문 제안은 같은 세목의 공개 질문 제목만(지방세봇 답 제안은 4c 공개 뒤).
- 이벤트는 이미 있는 `qna_posted`·`qna_answered`·`qna_accepted`·`expert_strip_clicked`·`expert_verified`를 쓰고 속성에 질문 원문·작성자 식별을 넣지 않습니다.

## 4. 시험
- vitest: 띠 선정(경계·동점), 공무원 도메인 판정(`notgo.kr` 거부), 신고 입력 검사, 가림 후 게시 보류 판정, 영업일 1일.
- DB(`packages/db/tests/w13g-*.test.mjs`): 연결 규칙, 배지 만료, 질문·답변·채택 규칙, 90일 경계, 신고·제재, 설정 켜기 조건, 스키마 금지 열, `chunks` 허용 목록 부재, 활동 함수에 결제·구독 표 0.
- E2E(`e2e/w13g-acceptance.test.mjs`): 키 꺼짐 404, 고지 승인 전 켜기 거부, 질문·답변·채택 흐름, 배지 해제, 상담·매칭·결제 버튼 0, 연락처 렌더 0.

## 5. PO 입력 / 막힘
중립성 고지·답변 하단 고지·약관 문구(법률), 검출 사전(상담 유도 표현), 활동 전문가 기준 값, 통합 메일 도메인 확인, 배지 만료 사전 알림 일수, SM 전문가 프로필 등록·계정 연결(PO).

## 6. 남은 과제 (이번 단위에서 뺀 것)
- `/qna/criteria`의 '기준 변경 이력' 표시: 이력 원본이 관리자 전용 감사 로그라 공개 화면에서 읽지 않습니다. 이력을 보여 주려면 기준 변경을 공개 가능한 이력 표로 따로 남기는 작업이 필요합니다(W13-z에서 결정).
- 공휴일: 설정 `business_holidays` 값이 비어 있으면 신고 처리 목표(1영업일)는 주말만 건너뜁니다. 공휴일 달력은 PO 입력입니다.
- 제재 정의: 활동 집계의 '제재 여부'는 제재 중이거나 집계 창 안에 시작된 제재로 둡니다. '이력 없음'을 전체 기간으로 볼지는 PO 확인입니다.
- 회원 계정 연결 입력은 계정 번호(UUID) 직접 입력입니다(회원 이메일 열람 회피, 리드 승인).
- 질문 작성의 '비슷한 질문 제안'과 지방세봇 답 제안(4c 공개 뒤), 해결 사례 동의(W13-h), 재검증 만료 사전 알림 메일(설정 `expert_badge_notice_days` 입력 뒤)은 이 단위에서 만들지 않았습니다. 만료 닫기 배치 `expert-badge-expiry`는 등록되어 있습니다.
- 질문 작성 화면의 개인정보 확인 문구는 기능 설명용 한 줄입니다. 법률 문구가 필요하면 PO 입력으로 교체합니다.
