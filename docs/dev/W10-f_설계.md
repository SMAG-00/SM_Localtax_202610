# W10-f 결제 기반·디지털 구독·페이월: 구현 기록 (개발 문서)

2단계 설계(`docs/dev/2단계_설계.md`) 1장 W10-f·3장·5장 #13·#19~#23·6장에 맞춘 구현 기록입니다. 설계와 다르면 설계가 맞고 이 문서를 고칩니다. (2026-10-25 작성)

지키는 선: 시험(샌드박스) 결제만 씁니다. 실제 가격·약관·환불 문구·법률 판단은 이 단위에 없고 모두 데이터 칸 또는 PO 입력입니다. 시험 자료의 금액·본문·상품은 지어낸 값입니다. 기능 키(`billing`·`digital_subscription`·`paywall`)는 꺼 둔 채 출하합니다.

## 11. 구현 기록

### 11.1 마이그레이션 (로컬 적용 완료, 원격 미적용)

| 번호 | 내용 |

### 11.2 서버 (`apps/web/lib/server/billing/`)

| 파일 | 역할 |
|---|---|
| `config.ts` | `PG_MODE` 기본 test, 키 모양 검사(시험 모드에 실결제 키·실결제 모드에 시험 키는 닫힘), 가짜 PG 주소는 localhost만 |
| `pg.ts` | `PgAdapter`(lookup·confirm·issueBillingKey·chargeBilling). 공급자 `fake`(로컬 가짜 PG)와 `toss`(토스페이먼츠 시험 키) 모두 토스 HTTP API 모양, 기준 주소만 다름. SDK 설치 0(fetch) |
| `webhook.ts` | HMAC-SHA256 서명 검증, 이벤트 번호 정하기(본문 → 머리글 → 해시) |
| `service.ts` | 결제 시작·마무리·웹훅 처리·해지·내 구독·권한 판정 호출·정기 정리·카드번호 스캔 |
| `paywall.ts` | 미리보기(공개 뷰) + 권한 있는 요청에만 본문, 요청마다 읽음 |
| `card-scan.ts` | 13~19자리 + Luhn 카드번호 패턴 검사(정기 작업과 시험이 같은 함수) |

- 경로: `POST /api/billing/{checkout,confirm,cancel,webhook}` · `/api/admin/billing`(상품·요금제·유료 본문·실결제 준비 기록) · 화면 `/store/subscription`·`/store/subscription/complete`·`/my/billing` · 유료 기사는 `/news/[slug]`가 공개 기사 뷰에서 못 찾은 주소에 한해 페이월로 이어짐.
- 정기 작업: `billing-reconcile`(오래 끝나지 않은 주문 PG 조회 정리 · 만기 구독 갱신 결제 · 만기 정리 · 카드번호 스캔), `renewal-notice`(가격 변경 사전 고지 기록). `vercel.json` crons에 하루 1회씩.
- 구조화 데이터는 `@ltr/structured-data`에 생성기 `paywalledArticle`을 더하고 `components/site/JsonLd.tsx`로만 냅니다(`isAccessibleForFree: false`, 본문·미리보기 글자 0).
- AI 도우미 런처는 `lib/site/assistant-paths.ts` 목록(`/store/subscription`·`/my/billing`·`/admin`)에서 숨깁니다.

### 11.4 남은 일

- 관리 화면(`/admin/billing`)은 만들지 않았고 API만 있습니다. 관리 메뉴 정확 비교 E2E와 함께 리드가 마지막에 처리합니다.
- P1(마이그레이션 97: 지면 구독자 연동 PAY-06, 지면 정기결제 BIZ-05)은 시작하지 않았습니다.
- 토스 시험 키로 실제 호출한 적은 없습니다(키 없음). 실제 토스 SDK 결제창(`SubscribeForm.tsx`)과 웹훅 서명 방식은 키를 받은 뒤 확인합니다.
- 메일 발송(갱신 사전 고지·해지 안내)은 문구를 PO가 정하기 전까지 만들지 않았습니다. 고지는 DB 기록과 `/my/billing` 표시만 합니다.

## 12. 결정

모든 결정은 `권고안으로 진행 (PO 위임 2026-10-22)`입니다. 법률·세무 내용은 [감수 필요]로 표시했습니다.

| # | 결정 | 이유 |
|---|---|---|
| 1 | 공급자는 `fake`·`toss` 둘, 구현은 같은 HTTP 클라이언트(기준 주소만 다름) | 가짜 서버로 토스 프로토콜 모양 전체를 시험하고, 키가 생기면 주소·키만 바꿈 |
| 2 | 결제 최종 상태 = 가장 최근 PG 조회. 조회 시각이 이미 반영한 조회보다 오래되면 무시 | 취소가 승인보다 먼저 와도 결과가 같게 |
| 3 | 웹훅 서명은 항상 요구(HMAC-SHA256, `tosspayments-webhook-*` 머리글). 서명 없는 웹훅은 거부 | 위조 방어. 토스의 결제 상태 웹훅에 실제로 이 서명이 붙는지는 계약 때 확인 [확인 필요] |
| 4 | 설정 `renewal_notice_policy`가 비어 있으면 사전 고지 기한 30일, 구독 기간보다 길 수 없음 | PO 지시 기본값. 법정 기한·고지 방식은 법률 검토 [감수 필요] |
| 5 | 가입 때(`checkout`)와 갱신 결제 확인 때(`auto_renew`)의 화면 고지를 고지 기록으로 인정, 금액이 바뀌면 `price_change` 고지가 새로 있어야 갱신 | "고지 기록 없는 갱신 거부"를 데이터로 강제. 이 인정 범위가 충분한지는 [감수 필요] |
| 6 | `billing_retry_policy`가 비어 있으면 재시도 0·유예 0(결제 실패 즉시 종료). 유예는 한국 날짜 마지막 날까지 이용, 다음 날 0시 회수 | 값을 AI가 정하지 않음. PRD PAY-02 문장 그대로 |
| 7 | `valid_until`은 끝 시각(배타적): 직전 요청 허용, 그 시각부터 거부 | PRD 경계 시험 문장 |
| 8 | 환불(PG 취소 확인)은 권한 즉시 회수, 해지는 남은 기간 끝에 회수 | PAY-03. 환불 기준 문구는 PAY-05 정책 [감수 필요] |
| 9 | `products`는 종류·주문 방식 값만 늘리고 `billing_mode` 칸을 더함. pg 상품은 W8 공개 뷰에 나오지 않음 | W8 경로 불변 |
| 10 | 유료 본문은 `paid_bodies` 분리 + 판매 권리 확인(`sale_allowed`, 근거·확인일 필수)된 것만 구독자에게 나감. 권리 확인 본문이 없으면 요금표도 닫힘 | PO 준비물 #23 |
| 11 | 유료 화면은 noindex, 미리보기는 400자 이하 | 색인·요약으로 본문이 새지 않게 |
| 12 | 카드 패턴 스캔은 Luhn 통과한 13~19자리만 | 날짜·식별자 오탐 방지 |
| 13 | 회원 탈퇴 시 구독·권한은 함께 지우고 주문은 `user_id`를 비워 보존 | 전자상거래 기록 보존 기간은 법률 검토 [감수 필요] |
