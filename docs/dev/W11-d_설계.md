# W11-d 감시 법령 확대·쟁점 태그·쟁점 연결 지도: 구현 기록 (개발 문서)

3단계 설계(`docs/dev/3단계_설계.md`) 1장 W11-d, 1.1 단계 d1~d8, 2.1 번호 122~126, 2.2(`laws` 표 순서 d(122) → e(127) → g(138)), 3장 d행, 4.1, 5장 #6·#7, 6장, 7장에 맞춘 구현 기록입니다. 설계와 다르면 설계가 맞고 이 문서를 고칩니다. (2026-10-26 작성)

지키는 선: 이 단위의 코드와 시험 자료에는 실제 법령 문장·조문 내용·쟁점 내용을 쓰지 않습니다. 감시 법령은 이름만 넣고 `[감수 필요]`로 표시하며, 시험 자료는 모두 `시험용` 표시와 지어낸 글입니다. 쟁점 이름, 태그 이름, 지도 본문은 빈 칸으로 출하하고(씨앗 0행) 감수 입력으로 채웁니다. 감시·태그·지도 흐름에는 AI가 없습니다(AI SDK import 0 시험). 서명 없는 지도의 공개는 0이고, 없는 조문 번호는 저장을 거부합니다. 기능 키 `issue_graph`는 꺼 둔 채 출하합니다.

- 쟁점 태그 사전의 이름·동의어: 모두 편집자 입력입니다.

## 5. 남은 일과 한계

- 신탁 세금 가이드·정비 단계 상세·판례 원문 화면의 `[쟁점 연결 지도 보기]` 진입 링크는 각 화면의 담당 단위(W11-c 등)가 `/realestate/issues/<slug>`로 붙입니다. 판정 결과 카드(PR-12)에서의 진입도 같습니다.
- DB 시험·Playwright E2E·`next build`는 이 작업에서 실행하지 않았습니다. 첫 실패가 나올 만한 곳: `legal_docs` 삽입 때 `legal_doc_texts` 자동 생성, `review_items.data_source_key='law_api'` 존재, 시험 DB의 `public_laws` 노출 조건(스냅샷이 있는 개정판).
- `menu.test.ts`는 W11-e의 `ordinances` 메뉴가 들어오면서 기대값 갱신 대기 중입니다(이 단위가 더한 `issues`·`issue-tags`는 이미 반영).
