# W12-a 검색 색인(RAG): 구현 기록 (개발 문서)

4단계 설계(`docs/dev/4단계_설계.md`) 1장 W12-a 행, 1.1 단계 a1~a7, 2.1 번호 151~155, 2.2 공통 파일 규칙, 3장 a행, 4.1·4.3·4.7, 5장 #4·#5·#6, 6장에 맞춘 구현 기록입니다. 설계와 다르면 설계가 맞고 이 문서를 고칩니다. PRD-04 요구사항 RAG-01~06, ASK-14가 이 단위의 범위입니다. (2026-10-27 작성)

지키는 선: 이 단위의 코드와 시험 자료에는 실제 법령·세무 글을 쓰지 않습니다. 시험 자료는 모두 `시험용` 표시와 지어낸 글입니다. 색인에는 공개·감수를 거친 자료(법령 DB, 스냅샷이 있는 해석·결정례, 서명 공개된 가이드, 공개된 쟁점 지도)만 들어가고, 출판물 청크는 권리 확인(PO #4) 전까지 0입니다. AI가 쓴 글은 색인에도 공개에도 들어가지 않습니다. 색인 코드에는 AI 호출이 없고(임베딩 공급자를 설정한 경우에만 임베딩 API 호출), 상속·증여 엔진을 불러오지 않습니다(NT9). 임베딩 공급자는 PO 결정(유료, #5) 전이라 인터페이스와 가짜 구현, 후보 틀만 두었고, 벡터 검색은 설정이 비어 있는 동안 꺼진 채 전문 검색만으로 동작합니다. 기능 키는 이 단위에서 켜지 않습니다.

## 4. 확인이 필요한 곳 (PO·감수·리드)

- 임베딩 공급자·재순위 방식(PO #5, 유료): 후보 틀의 요청·응답 모양은 공식 문서로 다시 확인합니다. 결정 뒤 차원이 1024가 아니면 155에서 표를 새로 만들고 `embeddingEnv`의 차원 상수를 바꿉니다.
- 출판물 색인 권리(PO #4, 법률): 확인 전 출판물 청크 0. 출판물 원천 표는 5단계에서 생깁니다.
