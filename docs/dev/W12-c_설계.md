# W12-c 계산·감면·판정 연결과 범위 확장: 구현 기록 (개발 문서)

4단계 설계(`docs/dev/4단계_설계.md`) 1장 W12-c 행, 1.1 단계 c1~c7, 2.1 번호 160~162, 2.2 공통 파일 규칙, PRD-04 ASK-05·ASK-18·ASK-19·ASK-22·FAM-09, 6.2·6.2.1·6.2.2, 6.3에 맞춘 구현 기록입니다. 설계와 다르면 설계가 맞고 이 문서를 고칩니다. (2026-10-27 작성)

지키는 선: 코드와 시험 자료에 법령·세무 문장, 세율·공제·기한·한도 값, 안내 문구를 쓰지 않습니다. 고정 문구 5개(`calc-copy.ts`)는 빈 칸이고 시험에서만 `시험용` 문구를 채웁니다. 이 단위의 코드는 `@ltr/igt-engine`·`lib/igt`를 불러오지 않습니다(NT9). 양도세·상속세·증여세 계산 도구는 없습니다. 답변의 금액은 엔진이 만든 `calc` 카드에만 나오고, 모델에게 돌려주는 도구 결과 글에는 금액이 없습니다.

## 3. 도구 목록

모델에게 정의를 주는 도구는 `run_calculator`(계산기 열림일 때만)와 `run_determination`(공개 판정표가 있는 종류가 있을 때만)입니다. `check_benefits`는 서버 전용입니다. 양도세·상속세·증여세 계산 도구는 없습니다(시험이 도구 이름을 검사). 도구 입력은 서버 메모리에서만 쓰고, 기록에는 도구 이름과 결과 요약(금액·기준일·룰셋/판정표 버전·근거 조문)만 남깁니다. 입력값을 담는 칸은 표에 없습니다.

## 5. 결정 사항 (권고안으로 진행)

| # | 결정 | 이유 |
|---|---|---|
| 1 | 모델 문장에 금액을 허용하지 않습니다(V3 `allowedNumbers`를 채우지 않음). 금액·세율은 카드에만 나옵니다 | "금액은 모델이 아니라 엔진 결과" |
| 2 | 계산 기준일이 룰셋 시행일 전이면 `unsupported`(`not_in_force`) | 과거 시점 질문에 현행 룰셋을 쓰면 틀린 금액이 나옴 |
| 3 | 상속·증여 허브 쟁점 지도, `national_igt`·`related` 법령은 색인하지 않습니다 | 한 문서에 두 범위가 섞여 한 태그로 나눌 수 없음(상속만 켜면 증여 청크 0 원칙). 조문·절 단위 태그 표는 PO·감수 입력 |
| 4 | 계산이 `calculated`가 아닐 때(`unsupported`·`needs_input`·`not_liable`)는 감면 점검을 돌리지 않습니다 | 계산 입력에서 가져오는 값이 없음 |
| 5 | `agent_record_results`는 service_role 전용 | W12-d 169가 기록 함수를 service_role 전용으로 바꾸는 방침과 같음 |
| 6 | 기록 호출은 턴 기록 뒤에 `state.turns + 1` 번째 턴으로 붙임. 저장을 끈 세션 등 기록된 턴이 없으면 0행 | 157의 턴 번호 규칙 |
| 7 | 계산 기능 키가 꺼져 있어도 상속·증여 카드(외부 계산기)는 고름 | FAM-09는 플래그와 무관 |

## 6. PO 입력이 필요한 것

- 고정 문구 5개: 계산 카드 안내 · 감면 "요건 확인 필요" 고지 · 판정 카드 안내 · `unsupported` 안내 · 상속·증여 카드 안내 (`lib/agent/calc-copy.ts`, 비면 공개 단계 승인 전 점검에서 걸림).
- 공개 요건 사전 본문: `keywords`(주제 낱말) · `tax_items` · 칸별 `question`·`options`·`required` (6.2·6.2.1·6.2.2). 없으면 역질문 없이 진행.
- 룰셋·판정표 감수 서명과 계산기 공개 게이트 통과(닫혀 있으면 `unsupported`).
- 감면 적용 시 금액: 엔진에 감면 계산 모듈이 생길 때까지 null.
- 상속·증여 허브 쟁점 지도, `national_igt`·`related` 법령의 조문·절 단위 범위 태그 표.
- 3단계 가이드·쟁점 지도 서명, 확장 평가셋(신탁·정비·주택 수 판정 100문항).
