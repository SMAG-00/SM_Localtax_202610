# W12-f 편집국 AI(요지·대중화·채널 원고·정합성): 구현 기록 (개발 문서)

4단계 설계(`docs/dev/4단계_설계.md`) 1장 W12-f 행, 1.1 단계 f1~f7, 2.1 번호 172~175, 2.2(`issue_tags`·`case_issue_tags`는 W12-f(172)만), 3장 f행, 4장 재사용 규칙, 5장 기본값에 맞춘 기록입니다. 설계와 다르면 설계가 맞고 이 문서를 고칩니다. (2026-10-27 작성)

지키는 선: AI는 세액·감면 판정·개별 세무 결론을 만들지 않고, 공개 표에 직접 쓰지 않습니다. AI 초안은 승인 전 표와 `review_items`에만 들어가며 사람이 승인해야 공개 뷰에 나옵니다. 시험은 AI를 끈 상태(키 없음)와 가짜 모델로 돌고, 코드·시험 자료에 실제 법령·세무 문장은 없습니다. 이 단위 서버 소스는 국세 엔진을 불러오지 않습니다(NT9). 기능 키 `case_summaries`·`article_ai_box`·`impact_banner`는 꺼 둔 채 출하합니다.

## 4. 확인이 필요한 곳 (PO·감수)

- 개정 영향 배너의 고정 문구와 채널 원고 끝줄의 AI 활용 표기 문구 [PO 확인 필요].
- 결정례 요지 열람 권한(일반 회원 미리보기 범위)은 PRD 16장 결정 안건 [PO 결정].
- 영업일 계산에 쓰는 공휴일 목록(`business_holidays` 설정)은 비어 있으면 주말만 제외합니다. 설정 씨앗은 0차(150) 소관이라 이 단위에서 만들지 않았습니다 [리드 확인].
- 금지 표현은 `brief_publish_policy.forbidden_words`(설정)를 읽습니다. `packages/editorial` 금지 표현 사전에 낱말을 더하는 일은 하지 않았습니다 [리드 확인].
- 용어 링크(AIOPS-08)는 만들지 않았습니다 [리드 확인].

## 5. 남은 일과 한계

- DB 시험(`w12f-editorial-ai.test.mjs`)·E2E·`next build`는 실행하지 않았습니다. 첫 실패가 나올 만한 곳: `legal_doc_texts` 자동 생성(후보 선별 시험), 기사 직접 INSERT의 발행 상태 트리거, `law_events` 삽입 때 스냅샷 규칙.
- AI 호출 모델은 W10-e `OpsModel`(HTTP) 그대로라서 실제 API 응답 모양 시험은 첫 실행 때 확인합니다(키가 있는 환경).
- `scheduleAiBox`는 `next/server`의 `after()`를 씁니다. 배포 환경에서 응답 뒤 실행이 허용되는지는 첫 배포 때 확인합니다.
