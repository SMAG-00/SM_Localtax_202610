# W13-i 설계 - 네이버 연재·제휴 피드·데이터 라이선스 (CH-02 · PART-01 · BIZ-11)

5단계 설계 1.1절 W13-i 행을 구현 단위로 풀어 쓴 문서입니다. 마이그레이션은 226~230 범위 안에서만 씁니다.

## 1. 경계 (바뀌지 않는 규칙)

- 네이버를 포함한 외부 서비스로 아무것도 보내지 않습니다. 연재는 원고를 준비해 내려받고, 사람이 올린 뒤 링크만 기록합니다(W12-h 채널 키트와 같은 방식).
- 계약·판매·정산 조건은 PO 입력 칸입니다. AI가 쓴 법률 문구는 0이고, 정산 조건 칸은 비어 있으면 `[확인 필요]`로 표시합니다. 가격 숫자는 코드·시드에 0입니다.
- 피드 키는 `PARTNER_FEED_KEY_PEPPER`로 HMAC-SHA256 해시한 값만 저장합니다. 원문은 발급 응답에서 한 번만 보입니다. 후추값이 비어 있으면 발급은 거부합니다.
- 피드에는 무료 공개 기사만 나갑니다. 프리미엄 칼럼(`access_tier = premium`)·유료 기사(`is_paid`)는 어떤 범위·계약에서도 0이고, 개인정보 칸(필자 이메일 등)은 응답 모양에 없습니다.
- '네이버 제휴 언론사' 표현은 연재 원고·화면·문구에 0입니다(NAV-07). 검사 함수가 원고 내려받기 전에 막습니다.

## 2. 데이터 (마이그레이션)

| 번호 | 내용 |
|---|---|
| 226 | `partner_feeds`(제휴사·계약·`key_hash`·범위·발급/폐기) · `partner_feed_usage`(요청 기록, 추가만) · `partner_feed_audit` · 설정 씨앗 `partner_feed_rate_limit`(빈 객체 = 피드 닫힘) |
| 227 | `license_contracts`(상대방·종류 naver_series/data_license·범위·기간·정산 조건·권리 근거·전문 허용 플래그) + 피드의 계약 외래키 + RPC `license_contract_record`·`license_contract_terminate`·`partner_feed_issue`·`partner_feed_revoke`·`partner_feed_serve` |
| 228 | `naver_series_manuscripts`(승인·판매 권리 확인된 프리미엄 칼럼에서 준비한 원고 기록, 게시 링크·이중 결제 안내 확인) + RPC `naver_manuscript_prepare`·`naver_manuscript_text`·`naver_manuscript_post` |
| 229~230 | 예비 (사용하지 않음) |

W12-h `channel_posts`의 채널 값 제약과 `CHANNEL_KEYS`는 바꾸지 않았습니다. 그 값은 W12-f 원고 생성·시험과 한 묶음이라, 네이버 프리미엄 연재는 별도 표(네이버 뉴스 제휴와 다른 상태)로 기록합니다. 5단계 설계의 "채널 값 확장"에서 벗어난 점은 리드에게 보고합니다.
`products` 행은 만들지 않습니다(가격 입력 전 판매 중 검사와 충돌, 연재·라이선스는 계약 기록이 정본).

### 2.1 설계 편차 3건 (리드 승인 2026-10-27)

| 편차 | 이유 |
|---|---|
| 네이버 연재 원고를 `channel_posts` 값 확장 대신 별도 표 `naver_series_manuscripts`에 기록합니다 | `channel_posts` 채널 제약·`CHANNEL_KEYS`는 W12-f 원고 생성·W12-h 시험과 한 묶음이라 값을 더하면 그 시험이 깨집니다. 별도 표는 '네이버 뉴스 제휴와 다른 상태' 요건에도 맞고, 프리미엄 칼럼의 판매 권리·계약 조건을 한곳에서 검사할 수 있습니다 |
| `products` 행을 만들지 않습니다 | 가격이 PO 입력 전이라 판매 중 검사와 충돌합니다. 연재·라이선스의 정본은 계약 기록입니다 |
| 이벤트 `partner_feed_requested`를 분석 이벤트로 보내지 않고 `partner_feed_usage`가 요청 기록을 맡습니다 | 키 소유자 요청은 방문자 분석이 아니라 계약 이용 기록이고, 분석 수집 경로에 제휴사 번호를 넣으면 PII 규칙을 새로 따져야 합니다. 이벤트 이름은 제약에 남겨 두었습니다 |

## 3. 피드 API

`GET /api/feeds?format=rss|json&limit=1..50`, 헤더 `Authorization: Bearer pf_<번호>.<비밀>`(주소에 키를 싣지 않습니다).

| 상황 | 응답 |
|---|---|
| 키 없음·형식 오류·번호/해시 불일치 | 401 (사용 기록 0) |
| 폐기된 키 · 계약 기간 밖(종료 다음 날부터) | 401 + 사용 기록 |
| 기능 키 `partner_feeds` 꺼짐 · `partner_feed_rate_limit.per_minute` 없음 | 503 (닫힘) |
| 분당 한도 n번째까지 | 200, n+1번째 429 (`retry-after`) |

- 요약 범위: 제목·요약·분야·발행일·원문 링크·출처 표기. 전문 범위: 계약 `allows_full` 플래그 ∧ 계약 `rights_ref` 기록 ∧ 기사에 `legacy_source`(외부 이관 자료) 없음 - 셋 다여야 본문이 나옵니다.
- 판정·한도 계산·사용 기록은 DB 함수 `partner_feed_serve` 하나가 같은 트랜잭션에서 합니다(키별 advisory lock). 라우트는 후추 해시를 만들고 결과를 RSS/JSON으로 바꿀 뿐입니다. 익명 호출 가능한 DB 함수는 0이고, 라우트가 키 검증 뒤 service role로만 부릅니다.

## 4. 화면 (관리자만)

- `/admin/feeds` (`feeds.issue`): 키 발급(계약 선택 필수, 키는 한 번만 표시)·폐기·키 목록(해시·원문 칸 0)·최근 사용 기록.
- `/admin/licenses` (`licenses.edit`): 계약 기록·종료, 네이버 연재 원고 준비/내려받기/게시 링크 기록. 정산·범위 칸은 PO 입력.

## 5. PO 입력이 필요한 것

네이버 프리미엄 콘텐츠 판매자 조건·정산 계약 / 제휴 피드 분당 한도 값(`partner_feed_rate_limit`) / 계약별 전문 허용 여부와 권리 근거 / 데이터 라이선스 대상·권리표 / 이중 결제 안내 문구 / 기능 키 `partner_feeds`·`licenses`·`naver_series` 켜기.
