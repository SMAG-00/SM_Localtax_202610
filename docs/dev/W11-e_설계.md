# W11-e 지자체 허브 정비 현황·조례 연결 설계

범위: RDV-06(P2) · RDV-07 · TX-13 · AIOPS-14 · 4-H 지역 가이드. 상위 문서는 `3단계_설계.md` §1 W11-e 행, §1.1 e1~e8, §2.1 마이그레이션 127~130, §5 #8~#11입니다. 이 문서에는 실제 조례 문장, 감면율·세율 값, 달력 날짜를 쓰지 않습니다. 시험 자료는 모두 `시험용` 표시와 지어낸 값입니다.

## 2. 단계별 설계

### e1 마이그레이션 127 — 자치법규 tier·조례 연결·요약 숫자 검사
- `laws.tier` 제약에 `ordinance`를 더합니다(같은 이름 제약으로 값만 늘림). `laws.region_code`(`regions.code` 참조) 칸을 더하고, `tier = 'ordinance'`일 때만 지역 코드가 있어야 합니다(제약). W11-d(122)가 `laws.scope`를 먼저 바꿔도 이 파일은 `tier` 제약과 새 칸만 건드립니다.
- `public_laws` 뷰를 같은 칸으로 다시 만들어 `tier <> 'ordinance'`를 더합니다. 조례는 법령 뷰어가 아니라 조례 연결 뷰로만 보입니다.
- `data_sources`에 `ordinance_api`(kind `law`, api_target `ordin`) 1행을 `unchecked`로 넣습니다(§5 #8). 확인 전 요청 0.
- `ordinance_links`: `region_code`, `kind`(urban_redevelopment·tax_reduction·tax_rate), `law_id`(tier ordinance 법령), `version_id`(그 법령의 개정판), `summary`, `summary_signed_by`·`summary_signed_at`, `effective_from`, `verified_at`, `source_url`, `origin`(collector·editor), `status`(draft·public·hidden), 등록자. 같은 (지역, 종류, 법령)은 1행입니다.
  - 공개 제약: `status = 'public'`이면 `source_url`(http/https)·`effective_from`·`verified_at`이 모두 있어야 합니다.
  - 서명 제약: 서명자와 서명 시각은 둘 다 있거나 둘 다 없습니다. 서명하려면 요약이 있어야 합니다.
  - 지역 검사: 시·도 도시정비(urban_redevelopment)는 시·도 코드, 감면·세율은 시·군·구 코드만 받습니다(코드 자릿수는 `regions` 단계 칸을 읽습니다).
  - 숫자 검사 트리거: 요약이 바뀌는 저장마다 `ordinance_summary_numbers_ok(summary, 원문)`이 거짓이면 예외 `ordinance_summary_number_mismatch`로 거부합니다. 원문은 `version_id`의 `law_articles.body`를 이어 붙인 것입니다. 원문 조문이 하나도 없는데 요약에 숫자가 있으면 거부합니다. 요약이 비어 있으면 검사하지 않습니다.
  - 숫자 규칙: 쉼표 천 단위를 지우고 `[0-9]+(\.[0-9]+)?` 토큰을 뽑아, 요약의 모든 토큰이 원문 토큰 집합에 있어야 합니다(부분 일치가 아니라 토큰 일치 — 요약 `5`가 원문 `15`에 걸리지 않음).
  - 개정 판 바뀜: `version_id`가 새 개정판으로 바뀌면 `summary_signed_*`를 비웁니다(서명 무효) — 이전 서명이 새 원문에 붙어 있지 않게.
- `public_ordinance_links` 뷰: 기능 키 `ordinance_texts`가 켜져 있고, 공개·출처·시행일·확인일이 있고, 이용 조건이 `denied`가 아닌 원천의 연결만. 칸: 지역·종류·조례 이름·시행일·확인일·출처 주소·요약(서명된 것만)·서명 여부·`stale`. 원문 글자는 `public_ordinance_articles`(별도 뷰)로 분리해 두 상자를 따로 읽게 합니다.
- `ordinance_links` 변경 이력은 `rules_audit`가 아니라 `review_item_events`·`audit_log` 기록을 서비스가 남깁니다(룰셋 표를 건드리지 않음).

### e2 자치법규 수집기 (`workflows/src/ordinance/`)
- `ordinanceGate`: 기능 키 `pipelines`·`LAW_API_OC`·`data_source_runnable('ordinance_api')` 셋 중 하나라도 틀리면 요청 0, 이유만 남깁니다(`unchecked` → 0건 요청).
- `collectOrdinance`: 관문 통과 때만 `fetchJson`을 부릅니다. 공포번호·시행일이 지난 값과 다르면 `changed`, 해시만 다르면 `body_only`(검수 항목 만들지 않음).
- 편집자 수동 등록 경로: `validateManualOrdinance` — 이름·지역·종류·원문 글자·출처 주소·시행일·확인일이 모두 있어야 등록 대상이 됩니다. 이 경로는 이용 조건 관문과 무관하게 열려 있고(편집자가 직접 입력), 원문은 같은 `laws`·`law_versions`·`law_articles`에 한 번만 저장합니다.
- 개정 감지: 시행일·공포번호가 바뀐 조례는 `review_items` kind `ordinance_change`(체크 키 `summary_matches_source`) 1건과 연결된 요약의 서명 무효 처리를 요청합니다.

### e3 마이그레이션 128 — `redevelopment_zones` 뷰·확인일 경고
- 뷰 `redevelopment_zones`: `projects`(status public, `source_name`·`last_verified_at` 있음)와 `project_current_stages`로 구역 목록을 만듭니다. 사업 유형은 `settings.stale_check_policy.redevelopment_types`에 든 유형만(비어 있으면 0행). 칸: 구역 id·slug·이름·지역·사업 유형·현재 단계·지정 고시일(설정 `designation_stage` 단계 기록의 고시일)·시행자(129 `projects.operator_name`)·출처 이름·최근 단계 원문 주소·확인일·`stale`. 기능 키 `redevelopment_status`가 꺼져 있으면 0행. 새 구역 표 0.
- `stale_days(verified, now)`: 한국 날짜 차이(일). `stale = days > 경고 일수` — 90일째 false, 91일째 true. 경고 일수는 `stale_check_policy`의 `zone_days`·`ordinance_days`이고, 값이 비어 있는 설정은 128이 PRD 초기값(90)으로 채웁니다(`{}`일 때만). 설정이 없으면 경고 계산 0.
- `stale_check_warnings(p_now)`(service_role): 구역·조례의 경고 대상을 시각 주입으로 돌려줍니다(테스트 주소에서 90/91일 확인).
- 129: `projects.operator_name`(시행자, 선택) 칸 추가 — 가격 칸 검사(PR-05)의 금지 낱말과 겹치지 않는 이름입니다.

### e4 작업 `zone-refresh`
- `workflows/src/index.ts`에 작업 1개, `JobServices.refreshZones`. 서버 구현(`apps/web/lib/server/zones/service.ts`)은 DB만 읽습니다: `stale_check_warnings` 호출 → 경고 수를 `agent_runs.detail`에 수로만 남김. 외부 공급원 갱신은 W10-h `pipeline-field-data`(원천 이용 조건 관문 거부 포함)가 하고, `zone-refresh`는 외부 요청 0입니다. 정비 갱신은 `project_events`에 새 행으로만 쌓이고 덮어쓰지 않습니다(W4 추가만 트리거). 실패하면 마지막 승인 값이 그대로 보입니다.
- URL 호출과 명령줄은 같은 `/api/jobs/zone-refresh`(스케줄러가 같은 함수를 부름). 일정은 `vercel.json` 한 줄.

### e5 허브 블록 ③·⑤
- 순수 함수 `hubOrdinanceBlock`·`hubZoneBlock`(`apps/web/lib/server/public/`): 항목이 0이면 `null`(빈 상자·"준비 중" 0). 지도 요소 0. 조례는 원문 상자와 요약 상자를 나눠 반환합니다. 기능 키 꺼짐이면 `null`.

### e6 `/admin/ordinances`
- 권한 `ordinance.manage`(등록·확인일), `ordinance_summary.sign`(요약 서명). 목록·등록 폼·확인일 갱신·요약 저장(숫자 거부 메시지)·서명. 시·도 도시정비와 시·군·구 감면·세율이 같은 화면입니다.

### e7 지역 가이드
- 허브 안내 문서 `docs/dev/W11-e_설계.md` 이 절과 허브 도움말 블록: 정비 현황·조례를 읽는 법, 확인일 경고 의미, 감수 전 요약 표시. 법·세무 문장 0.
