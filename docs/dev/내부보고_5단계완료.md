- 작성일: 2026-10-28 · 작성: 개발(초안) · 읽는 분: PO(세무사)
- 현재 위치: 전체 6단계(0~5단계) 중 5단계까지 코드 완료 · 다음은 **내부 보고·합격** → W9 실행(기존 기사 이관·도메인 전환) → 공개 (PRD_최종 §11.0, 2026-10-25 PO 결정 순서)
- 이 문서는 숫자를 새로 재지 않았습니다. 모든 숫자는 괄호 안 문서·커밋에서 옮겼고, 문서에 없는 것은 `[확인 필요]`로 적었습니다. 법률·세무 문구는 쓰지 않았고 "무엇이 필요한지"만 적었습니다.
- 용어 풀이: **기능 키**는 화면·기능을 켜고 끄는 스위치(관리 화면 → 운영 설정의 `feature_flags`)입니다. **게이트**는 감수 서명·대조 결과 같은 기록이 없으면 스위치를 켜도 열리지 않게 막는 관문입니다. **E2E**는 실제 브라우저·서버로 사용자 흐름을 끝까지 돌려 보는 시험, **CI**는 GitHub에 올릴 때마다 자동으로 도는 검사, **RLS**는 DB가 행 단위로 읽기·쓰기를 막는 보안 규칙, **anon**은 로그인하지 않은 방문자 권한입니다.

## 5. W9 실행 계획 요약 (기존 기사 이관·도메인 전환)

출처: `docs/dev/W9_설계.md`. 지금까지는 **준비만** 했고 현 사이트·DNS·계정은 바꾸지 않았습니다.

### 5.1 준비된 것

- 이관 도구 `scripts/migration/` — 형식·분류 대응, 옛 주소 정규화, 검증, 변환, 주소 매핑·SQL 생성, dry-run 보고서, 리허설(`cli.mjs adapt`·`dry-run`·`rehearse`), 현 사이트(엔디소프트 계열)·워드프레스 어댑터. 네트워크·DB를 쓰지 않고 같은 입력이면 같은 결과를 냅니다.
- 주소 연결 표 `redirects`(마이그레이션 77 — **파일만, 원격 미적용**). DB가 연쇄 이동·홈 일괄 이동·사유 없는 410을 막습니다.
- 옛 주소 이동 스위치 `legacy_redirects`(기본 꺼짐). 꺼져 있으면 지금 동작 그대로입니다.
- 분류 대응: 현 사이트 8개 분류 → 4대 분야(부동산 정보·전문가 칼럼은 편집국 재분류 대기열).
- 시험 3종(도구·주소 규칙·DB 표).
- 현 사이트 조사(공개 쪽만): 기사 번호 최대 2007(2026-10-20), 실제 기사 수는 약 2,000건 이하로 추정 — 정확한 수는 덤프로만 확인됩니다.

### 5.2 PO가 줄 것 (W9_설계 4.3)

1. 현 CMS DB 덤프 또는 관리자 내보내기 + 사진·첨부 + 필자 표 (엔디소프트에 덤프 가능 여부 문의)
2. 운영사 계약 여부·계약 종료일·서버 유지 가능 기간
3. 도메인·DNS 관리 계정(TTL 인하 권한), Vercel 도메인 연결 권한, 구글 서치 콘솔·네이버 서치어드바이저 소유 확인
4. 전환 날짜·시각, 쓰기 중지 시각, 롤백 판단 시한·책임자, 기존 서버 유지 기간(초안 30일) — 전환 2주 전까지
5. 사진 권리 자료(권리 미확인은 공개 렌더 0)
6. 검색 유입 상위 20곳, 외부 연동 목록, 정정 이력, 회원·구독자 이관 범위와 동의 방침(법률 검토)
7. 결정: 정적 쪽 5곳(약관·개인정보·저작권·이메일무단수집거부·청소년보호)의 새 주소, 관광성 주소 처리, 제외 기사 기준

### 5.3 되돌리기 어려운 단계 — PO 승인 필요

| 단계 | 이유 |
|---|---|
| 원격 DB에 마이그레이션 77 적용 | 실행 직전에만 적용(번호가 이미 지나간 파일이라 순서 예외 처리가 필요할 수 있음 `[확인 필요]`) |
| 기존 사이트 쓰기 중지 | 운영 중인 매체의 발행이 멈춤 |
| `--status published` 최종 실행 | 이관 기사가 새 사이트에 공개됨 |
| `legacy_redirects` 켜기 + DNS 전환 | 옛 주소 전체가 새 사이트로 이동, 검색엔진에 반영 |
| Search Console 주소 변경·네이버 사이트 이전 | 검색엔진 쪽 기록은 되돌리기 어려움 |

### 5.4 리허설 순서 (W9_설계 1장)

1. 자료 받기(원본 해시 기록) → 2. 중간 형식 변환 → 3. dry-run(오류 0, 이관 + 제외 = 원본, 표본 200건 목록) → 4. 로컬 적재(적재기는 자료를 받은 뒤 작성) → 5. 주소 1:1 매핑(미결정 0·연쇄 0·홈 이동 0) → 6. 301 표본 200건 + 주요 20곳, 내용 7항목 사람 눈 대조 → 7. 처음부터 끝까지 **리허설 2회**(기사·매핑·이미지 수·해시 일치) + 델타·DNS 롤백 리허설 → 8. 전환 당일 점검표 → 9. 롤백 준비

### 5.5 롤백 (W9_설계 6장)

- DNS를 전환 전 값으로 되돌리고 `legacy_redirects`를 끕니다. 기존 서버는 유지 기간 동안 쓰기만 막고 살려 둡니다.
- 전환 뒤 새 사이트에 올라온 글은 롤백 전에 내보내 보관합니다(양쪽 쓰기 금지).
- **롤백 리허설 1회 성공이 전환의 조건**입니다.

## 7. 알려진 한계·남은 과제

1. **5단계 CI 확인 대기** — `d7d49a3` CI 실행 중, W13-z 커밋 2개 push 전(2026-10-28 작성 시점). 합격 판정 전에 CI 통과를 확인해야 합니다.

3. **다른 속도 제한의 IP 판정** — 지방세봇 한도만 위조 방지 방식으로 바꿨고, 검색·폼·가입 등은 사내 Docker 배포에서 우회될 수 있습니다. 기존 E2E 7개도 함께 고쳐야 합니다(W12-z 4장 #2).
