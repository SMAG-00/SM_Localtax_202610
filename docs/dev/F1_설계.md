# F1 설계 — 합격 시험 수정 묶음 (사진 보관함·소제목 블록·문단 링크)

합격 시험 2단계(실제 글 1개를 테스트 주소 관리자 API로 올리기)가 1단계에서 막혀 만든 묶음입니다. 사진 기록을 만드는 API·화면이 없었고, 소제목 블록이 없었으며, 문단 링크 지원 여부가 확인되지 않았습니다.

## 1. 결정과 이유

| # | 결정 | 이유 |
|---|---|---|
| 1 | 사진은 **서버가 받아 저장소에 올립니다** (서명 업로드 URL 방식 아님). 한 파일 4,000,000바이트 이하 | Vercel 함수 요청 본문 한도 4.5MB 안에서 끝납니다. 서명 URL 방식은 요청이 2~3번(URL 발급 → 브라우저 직접 업로드 → 기록 등록)으로 늘고, 올린 뒤 등록을 안 하면 고아 파일이 생기며, 파일 내용 검사를 서버가 못 합니다. 기사 사진은 4MB로 충분하고 문의 첨부(4,000,000바이트)와 같은 한도입니다. 더 큰 사진이 필요해지면 그때 서명 URL을 추가합니다 |
| 2 | 버킷 `media`는 **공개 읽기**, 쓰기·지우기는 service_role만 (storage.objects 정책 0) | 손님 화면은 로그인 없이 사진을 봅니다. 공개 버킷이라 권리 미확인 사진의 파일 주소도 열려 있지만, 이름이 추측할 수 없는 무작위(UUID)이고 화면·발행 판정은 권리 확인된 사진만 씁니다 |
| 3 | 형식은 jpg·png·webp. **파일 머리(매직 바이트)** 로 가립니다 | 확장자·content-type은 속일 수 있습니다. SVG(스크립트 포함 가능)와 GIF는 받지 않습니다. 가로·세로도 파일 머리에서 읽어 `media.width/height`에 기록해 동영상 썸네일 16:9 판정(ART-08)이 손 입력 없이 됩니다 |
| 4 | `media.path`에는 `storage/v1/object/public/media/<uuid>.<확장자>`를 저장합니다. `mapping.ts absolute()`가 http 주소는 그대로, 저장소 경로는 `NEXT_PUBLIC_SUPABASE_URL`에 붙이고, 그 밖의 옛 상대 경로는 사이트 주소에 붙입니다 | 환경(로컬·테스트·운영)마다 Supabase 주소가 다르므로 주소 전체가 아니라 경로만 저장합니다. 기존 행은 바뀌지 않습니다 |
| 5 | 권한은 새 작업 2개: `media.edit`(기자·편집 책임자·관리자 — 올리기·목록·메타 고치기), `media.rights`(편집 책임자·관리자 — 권리 확인·반려, 거부 시도는 감사 기록) | 기존 규칙(기사 작성은 기자·편집 책임자, 권리·승인은 편집 책임자 이상)과 같게 맞췄습니다. 기존 작업의 권한은 넓히지 않았습니다 |
| 6 | **권리 확인된 사진의 출처·이용 조건·촬영자·공공누리 유형·원본 주소·종류를 고치려면 `media.rights`가 필요**합니다. 대체 텍스트는 `media.edit`으로 충분합니다 | 기자가 확인된 사진의 출처를 몰래 바꿔 권리 확인을 무력화하는 일을 막습니다 |
| 7 | 권리 확인(`confirmed`)은 API가 먼저 빠진 칸을 문장으로 알립니다(출처·이용 조건·공공누리 유형, 사진은 촬영자도). DB 제약(`media_confirmed_complete`·`media_license_required`)이 마지막 방어선입니다 | 제약 오류보다 어느 칸이 비었는지 알려 주는 편이 편집자에게 낫습니다 |
| 8 | 올릴 때 `alt`(대체 텍스트)를 필수로 합니다 | 접근성. 포토 기사 판정도 사진 설명을 봅니다 |
| 9 | 소제목 블록 `heading`(level 2\|3, text 200자 이하)을 더합니다. 손님 화면은 h2/h3입니다 | 원고의 `##`·`###`가 문단으로 들어가던 문제. 글자 수·유사도·금지 표현 검사·검색 색인·수정 이력 비교·SEO 소제목(질문형) 점검이 소제목 글을 함께 봅니다. 검색 색인 SQL은 블록의 글 칸을 일괄로 읽어서 바꿀 것이 없었습니다 |
| 10 | 문단 링크는 **이미 지원합니다**: `[글](주소)` 표기만, 사이트 안 경로와 http(s) 주소만 링크가 되고 바깥 링크에는 `target="_blank" rel="noopener noreferrer"`가 붙습니다. 그 밖의 표기(`javascript:`·`data:`·`//` 등)와 HTML은 링크도 HTML도 되지 않고 글자로만 그려집니다 | 새로 구현하지 않고 시험(`article-view.test.ts`, E2E d)으로 XSS가 없음을 확인만 했습니다 |

## 2. 만든 것

- 마이그레이션 `20261027000233_f1_media_storage.sql` — 공개 버킷 `media`(4,000,000바이트, jpeg·png·webp). 표·함수는 만들지 않았습니다(RLS·anon 함수 변화 없음)
- API `/api/admin/media`(GET 목록·POST 올리기 multipart), `/api/admin/media/[id]`(PATCH), `/api/admin/media/[id]/rights`(POST decision = confirmed·rejected·unconfirmed, 감사 로그 `media.create`·`media.update`·`media.rights.*`)
- 화면 `/admin/media`, 메뉴 "사진 보관함", 편집기 이미지 고르기에 보관함 링크
- 소제목 블록: `packages/editorial`, `content.ts`, `editor-state.ts`, `BlockEditor`, `ArticleBlocks`, `ArticlePreview`, 글자 수·유사도·AI 대중화·수정 비교 입력

## 3. 올리기 순서 (원격)

1. 마이그레이션 `20261027000233`을 원격 DB에 적용합니다(버킷 생성).
2. 배포한 뒤 `/admin/media`에서 사진을 올리고 편집 책임자가 권리를 확인합니다.
3. 기사 편집기에서 이미지 블록으로 고릅니다.
