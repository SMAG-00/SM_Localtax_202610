# W12-e 평가·게이트 기반 (e1~e3): 구현 기록 (개발 문서)

4단계 설계(`docs/dev/4단계_설계.md`) 1장 W12-e, 2.1 번호 163~164, 3장 e 행, 4.2 평가셋에 맞춘 구현 기록입니다. 설계와 다르면 설계가 맞고 이 문서를 고칩니다. (2026-10-27 작성) e4(실행기·자동 회귀)·e5(165 품질 콘솔·경보)·e6(수용)은 아래 3~5장에 기록합니다. (2026-10-27 추가)

지키는 선: 이 단위의 코드와 시험 자료에는 실제 법령·세무 문장, 세율·공제·기한·한도 값, 정답 결론을 쓰지 않습니다. 기본 300문항과 확장 평가셋의 문항·정답·필수 근거·금지 주장은 PO가 쓰고 보조 세무 전문가가 교차 확인하며, 이 단위는 표·가져오기 화면·채점·게이트만 만듭니다. 시험 자료는 전부 `[시험용]` 표시를 붙입니다. 기능 키는 모두 꺼 둔 채 출하하고, 국세 금액은 만들지 않습니다. AI 경계 목록에 걸리는 폴더(`lib/agent`)는 건드리지 않았고 평가 코드는 `lib/eval`·`lib/server/eval`에 둡니다.

## 3. e4 실행기와 자동 회귀 (EVAL-03 · ASK-17)

| 항목 | 내용 |
|---|---|
| 목록 | 기본 = 범위 base 문항, 확장 = base가 아닌 범위 문항, 색인 제외 = 가릴 근거 ID가 있는 문항. 서버 실행은 판(set) 단위로 돌리므로 기본·확장은 판의 범위로 구분하고, 색인 제외 목록만 문항을 골라 돕니다 |
| 색인 제외 | `withIndexExclusion`이 검색 도구의 결과에서 sourceId 또는 `chunk:번호`를 뺍니다. 실제 지방세봇 흐름(`runAgentTurn`)에 그대로 끼우며, 가려진 근거가 모델 요청에 실리지 않는 것을 시험합니다 |
| 응답 출처 | `fake`(가짜 모델), `fixture`(같은 판의 마지막 실제 API 실행 답변을 그대로 다시 쓰기 - 채점·게이트 경로 점검용), `live_api`(실제 지방세봇 흐름과 실제 모델 API) |
| 실제 API | 관리자가 `/admin/quality`의 "평가셋 실행"에서 `live_api`를 고른 때만 부릅니다(권한 `eval.gate_approve`). 작업·시험은 실제 API를 부르지 않으며, 시험은 `flow-fixtures`의 가짜 모델 서버만 씁니다. 모델 설정·키·런타임 설정이 없으면 실행을 거부합니다 |
| 조건 지문 | 모델·지시문 버전·색인 버전·룰셋 해시·판정표 해시를 `eval_runs`에 기록합니다. 앱 쪽 `fingerprintOf`는 DB 트리거(163)와 같은 식입니다. 룰셋·판정표 해시는 활성 본문 해시의 묶음입니다 |
| 변경 감지 | `changeReasons`가 바뀐 칸마다 사유(prompt/model/index/ruleset/determination_changed)를 냅니다. 이전 실행이 없으면 비교하지 않습니다 |
| 자동 회귀 | 작업 `quality-daily`가 마지막 `live_api`·`fixture` 실행과 지금 조건을 견줍니다. 바뀌었으면 검수 큐(`review_items`, 같은 조건은 1건)에 "회귀 평가 필요"를 올립니다. 설정 `eval_regression.enabled`가 true일 때만 최신 동결 base 판을 가짜 모델로 회귀 실행합니다(기본 꺼짐 - 알림만) |
| 켠/끈 비교 | `compareOutcomes`가 같은 문항을 두 조건(예: 공식 검색 켬/끔)으로 돌린 결과를 문항별로 견줍니다. 응답 모양 변화, 인용 추가·제거, 한쪽에만 있는 문항을 셉니다 |
| 결과 변환 | `toEvalAnswer`가 한 턴 결과를 답변 칸으로 바꿉니다. 투자 추천 차단 이벤트는 blocked, 범위 안내는 scope_guide, 근거 부족은 no_answer, 역질문은 clarify입니다. 인용 중 스냅샷 없는 실시간 인용 수를 셉니다 |
