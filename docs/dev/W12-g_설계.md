# W12-g 키워드 맵·보안 정책: 구현 기록 (개발 문서)

4단계 설계(`docs/dev/4단계_설계.md`) 1장 W12-g 행, 1.1 단계 g1~g5, 2.1 번호 176~178, 2.2 같이 고치는 파일, 3장 g행, 5장 #13에 맞춘 구현 기록입니다. 설계와 다르면 설계가 맞고 이 문서를 고칩니다. (2026-10-27 작성)

지키는 선: 이 단위의 코드와 시험 자료에는 보안 정책 문구·취약점 신고 연락처·통제 항목 내용·쟁점 태그 이름을 쓰지 않습니다. 모두 PO·편집국 입력이고 시험 자료는 `시험용` 표시의 지어낸 글입니다. 7개 항목은 이름(제목)만 코드에 있고(PRD SEC-01 항목명) 본문은 빈 칸으로 출하합니다. 국세 금액 계산 0, AI 호출 0. 기능 키 `keyword_map`·`security_page`는 꺼 둔 채 출하합니다.

## 4. 확인이 필요한 곳 (PO·편집국)

- 보안 정책 7개 항목 본문과 확인일, 취약점 신고 창구(5장 #13) — 법률 감수 필요.
- AI 제공사 데이터 보존·학습 조건은 계약 확인 뒤 본문과 `contract_verified` 체크.
- 통제 목록(ISO/IEC 27001 부속서 A를 본뜬 내부 통제) 항목과 첫 자가 점검.
- 노드 상한 초기값(권고 30)과 최소 건수 입력, 승인 태그가 쌓인 뒤 기능 키 `keyword_map` 켜기.

## 5. 남은 일과 한계

- DB 시험·Playwright E2E·`next build`는 실행하지 않았습니다. 첫 실패가 나올 만한 곳은 `legal_docs` 삽입 시 `legal_doc_texts` 자동 생성, 공개 뷰가 읽는 `public_case_issue_tags`의 결정례 공개 조건입니다.
- `menu.test.ts`는 관리 메뉴에 `security`가 들어와 기대값 갱신이 필요합니다(관리자 줄).
