# W12-b 지방세봇 코어(흐름·도구·인용·검증기·스트림): 구현 기록 (개발 문서)

4단계 설계(`docs/dev/4단계_설계.md`) 1장 W12-b 행, 1.1 단계 b0~b7, 2.1 번호 156~159, 2.2 공통 파일 규칙, 3장 b행, 4.1·4.3·4.4·4.5·4.7, 5장 #11·#14~#18, PRD-04 6.1·6.5·6.6·6.7·6.12·6.13에 맞춘 구현 기록입니다. 설계와 다르면 설계가 맞고 이 문서를 고칩니다. (2026-10-27 작성)

지키는 선: 코드와 시험 자료에 실제 법령·세무 문장, 세율·공제·기한·한도 값을 쓰지 않습니다. 시험 자료는 모두 `시험용` 표시와 지어낸 글입니다. 범위 안내·근거 부족 고정 문구, V5 추가 낱말, 요건 사전, 역질문 선택지 문안은 PO·감수 입력이라 빈 칸(`fixed-copy.ts`·`EMPTY_DICTIONARY`)으로 두고 시험에서만 `시험용` 문구를 채웁니다. 이 단위의 코드는 `@ltr/igt-engine`을 불러오지 않고(NT9) 국세 금액을 만들지 않으며 양도세 계산은 어디에도 없습니다. 기능 키(`taxbot`)와 공개 단계(`ask_rollout`=none)는 이 단위에서 켜지 않습니다. 시험은 AI 끈 상태와 가짜 모델(네트워크 0)로만 돕니다.

## 1. b0 API 재확인 결과 (PRD-04 6.5·6.7의 [확인 필요])

이 작업 환경은 외부 문서를 열 수 없어 **공식 문서로 다시 확인하지 못했습니다.** 그래서 아래 가정을 한 모듈(`lib/agent/model-request.ts`)에 모아 두고, 착수 시 문서를 보고 그 파일만 고치면 되게 했습니다.

| 항목 | 이 구현의 가정 | 틀렸을 때 |
|---|---|---|
| 인용 기능과 구조화 출력의 동시 사용 | 동시 사용 안 함. 답변 호출은 텍스트 + 인용만, 역질문·분류는 코드가 정한 규칙(사전)으로 하고 모델의 구조화 출력은 쓰지 않음 | 쓸 수 있다면 역질문 문장 다듬기에만 UTILITY 모델을 더함 (규칙 판정은 그대로) |
| 특정 도구 강제 호출(`tool_choice`) | 쓰지 않음 (`auto`만). 반드시 돌아야 하는 것(감면 점검 등)은 서버가 직접 부름 | 영향 없음 |
| 스트리밍 이벤트 | 모델 호출은 한 번에 받고, 검증을 통과한 문단만 우리 SSE로 내보냄 (문단 검증이 문단이 끝나야 가능하므로 문단 단위 지연은 같음) | 모델 스트림을 받아 첫 문단을 빨리 내는 최적화는 b7 이후 [확인 필요] |
| 거절 응답 | `stop_reason=refusal` → `ModelClient`가 `ModelError(kind="refusal")` → 보조 모델(UTILITY)로 1회 재시도 → 그래도 실패하면 검색 모드 | 보조 모델이 없으면 바로 검색 모드 |
| 문서 블록 인용 | 문서 블록(`type=document`, 제목=`source_id`, `citations.enabled`)의 인용은 `document_index` 또는 `document_title`로 문서를 가리킴 | 인용 모양이 다르면 `citationsOf` 한 함수 수정 |
| 추론 강도 칸 | `output_config.effort`로 보냄 (환경변수가 비면 칸을 보내지 않음) | `model-request.ts` 한 곳 |
| 캐시 | 지시문·도구 정의는 고정해 앞에 두고 `cache_control: ephemeral`을 시스템 마지막 블록에 둠. 기준일·모드·범위 플래그·문서는 첫 사용자 메시지(캐시 뒤) | 같음 |
