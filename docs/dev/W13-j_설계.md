# W13-j 정보보호 인증 추진 계획: 구현 기록 (개발 문서)

5단계 설계(`docs/dev/5단계_설계.md`) 1장 W13-j 행, 1.1 단계 j1~j3, 2.1 번호 231~233에 맞춘 구현 기록입니다. 설계와 다르면 설계가 맞고 이 문서를 고칩니다. (2026-10-27 작성)

지키는 선: 인증을 취득했다고 말하거나 암시하는 글은 어디에도 없습니다(화면 표기는 '추진 중'뿐). 인증 종류, 범위, 일정, 비용 추정, 담당, 운영 주체 명의, 위험 평가일은 모두 PO 입력이고 시험 자료는 `시험용` 표시의 지어낸 값입니다. AI 호출 0. 기능 키 `security_cert_plan`은 꺼 둔 채 출하합니다. 권한 `security_cert.edit`은 관리자만입니다(W13-0).

## 3. 결정 사항

| # | 결정 | 이유 |
|---|---|---|
| 1 | 승인 계획은 동시에 1건. 새 승인은 이전 승인본을 `superseded`로 바꿉니다 | 게이트와 공개 표기가 하나의 값을 가리키게 합니다 |
| 2 | 공개 화면은 종류와 승인일만 보입니다(범위·비용·담당 비공개) | 영업·내부 정보 노출 최소화 [PO 결정 필요] |
| 3 | `/security` 메뉴는 따로 두지 않고 기존 화면에 더합니다 | 메뉴·E2E 정확 목록 3곳 수정(다른 단위와 충돌)을 피합니다 |
| 4 | 승인과 별개로 인증 취득 기록 칸은 두지 않습니다 | 취득 표기는 이 단위 범위 밖이며 취득 뒤 PO가 문구를 새로 정합니다 |

## 4. PO 입력 필요

- 인증 종류(ISO/IEC 27001 또는 ISMS-P 또는 기타), 범위, 목표 시작·종료일, 비용 추정, 담당.
- 운영 주체 명의(인증 신청 명의), 위험 평가 실시일(문서는 PO 보관).
- 기능 키 `security_cert_plan` 켜기(승인 뒤).
