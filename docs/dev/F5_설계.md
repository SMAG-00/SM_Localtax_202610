# F5 설계 — 출처 자동 채우기

합격 시험 수정 묶음 F5입니다. PO 지적(2026-10-28): "출처 입력 칸 12개를 손으로 넣으라고 안내하지 말고, 본문에 이미 있는 값으로 자동 입력하라."

## 1. 원칙

- 이미 본문에 있는 글자·링크, 원문 페이지에 있는 표시를 **옮기기만** 합니다. 세무·법률 판단 문구를 새로 짓지 않습니다.
- LLM 호출은 쓰지 않습니다. 규칙 기반이고 칸마다 근거(어느 글자·어느 표·어느 페이지)를 화면에 보입니다.
- 근거가 없는 칸은 비웁니다. 후보를 서버가 **저장하지 않습니다** — 추가는 화면이 기존 `POST /api/admin/articles/{id}/sources`로 합니다(DB 제약·감사 로그·권한 그대로).
- 마이그레이션 없음: '자동 확인(주소 열림)' 표시를 담을 출처 표 칸이 없어 응답에만 둡니다(`auto_verified`).

## 2. 구성

| 파일 | 역할 |
| --- | --- |
| `apps/web/lib/admin/source-domains.ts` | 도메인 → 기관·매체 표(유일한 정본). `.go.kr`은 표에 없어도 공식 문서 |
| `apps/web/lib/admin/source-suggest.ts` | 본문 블록 → 후보 (순수 함수), 후보 → 폼 값, 이대로 추가 막힘 판정 |
| `apps/web/lib/server/sources/fetch-check.ts` | 원문 페이지 확인(SSRF 방어)·공공누리 읽기 |
| `apps/web/app/api/admin/articles/[id]/sources/suggest/route.ts` | 후보 + 확인 결과 응답 (권한 `article.edit`, 저장 없음) |
| `apps/web/components/admin/SourceSuggest.tsx` | [본문에서 출처 자동 채우기] 버튼·후보 카드 |

## 3. 후보 뽑기 규칙

- 대상 블록: 문단·인용·안내 상자(제목·글)·표(제목·칸). 소제목은 링크 표기를 쓰지 않으므로 보지 않습니다.
- `[글](https://…)`마다 후보 1건, 같은 주소(끝 슬래시·#조각 무시)는 합칩니다. 이미 기사에 등록된 출처 주소는 뺍니다.
- 제목·발표일은 **`출처:`로 시작하는 줄에서만** 읽습니다. 링크 앞 구간(이전 링크 끝~이 링크)의 글자가 제목이고, 그 구간에 날짜(`YYYY.M.D`·`YYYY-MM-DD`)가 정확히 하나일 때만 발표일입니다. 그 밖의 줄은 링크 글자를 제목으로 쓰고 날짜는 비웁니다(일반 문장의 날짜를 출처의 발표일로 오해하지 않기 위해).
- 종류: 도메인 표의 정부·공공기관 또는 `.go.kr` → 공식 문서(official_doc), 언론사·모르는 도메인 → 기타(other). 출처 종류에 '언론 보도'가 따로 없습니다.
- 발표기관: 도메인 표에 있을 때만. [확인 필요] `moef.go.kr`의 현재 기관 명칭(기획재정부/재정경제부).
- 자료 종류: 법안 상태 기사(coversBillStatus) + 공식 문서 + 허용 목록에 `bill`이 있을 때만 `bill`.
- 수집일: 오늘(한국 날짜).

## 4. 원문 페이지 확인

- 공식 문서·공공 데이터 후보만 확인합니다(언론 링크는 부르지 않음).
- 열림(HTTP 200) → 확인일=오늘. 공공누리: `공공누리 제n유형`·`공공누리 n유형(…)` 글자(img alt 포함), `kogl.or.kr/…/by|by_nc|by_nd|by_nc_nd.do` 링크 → kogl_1~4. 못 찾거나 서로 다른 유형이 함께 보이면 비웁니다. 페이지에 적힌 표시 글자가 '이용 조건' 후보입니다.
- 보안: https·443만, 사용자 정보 거부, 모든 DNS 결과가 사설·루프백·링크로컬·예약 IP가 아니어야 함(IPv4 매핑 IPv6 포함), 기본 전송은 검사한 IP로 연결 고정(DNS 바꿔치기 방지), 리다이렉트 3번(매번 재검사), 8초·2MB·text/html만. HTML은 저장하지 않고 값만 뽑습니다.
- 실패하면 확인일·공공누리를 비우고 이유를 돌려줍니다.

## 5. 화면

- 출처 탭 맨 위 [본문에서 출처 자동 채우기] → 후보 카드(채운 칸·근거·빈 칸 강조) + [모두 추가] + 카드마다 [이대로 추가]·[고쳐서 추가(폼에 채움)]·[빼기].
- **저장된** 본문 기준입니다(저장 전 편집 내용은 반영되지 않음).
- 공식 문서 후보가 발표기관·확인일·이용 조건·공공누리 유형 중 하나라도 비면 [이대로 추가]를 막고 [고쳐서 추가]로 유도합니다. 기준일·지역 단위는 원문에서 자동으로 알 수 없어(REG1-09) 추가 뒤 발행 전에 채울 칸으로 안내만 합니다 — 발행 판정은 그대로 막습니다.
- 단계표 '출처 더하기'의 [바로 가기]는 이 버튼으로 포커스, 설명은 "본문 링크에서 자동으로 채워 드립니다 — 확인 후 추가".

## 6. 시험

- vitest: `source-suggest.test.ts`(기사 1번 출처 줄 기반), `fetch-check.test.ts`(공공누리·SSRF·리다이렉트·크기·시간 — fetch 주입) (발행 단계표 시험은 2026-10-31 간편 발행으로 단계표와 함께 지웠습니다 — F4 설계 2.2).
- E2E: `e2e/source-suggest.test.mjs`. 로컬 주소는 SSRF 규칙에 막히므로 공식 문서 후보는 8443 포트 `.go.kr` 링크(요청 전에 거부됨)로 '고쳐서 추가' 흐름을, 기타 후보로 '이대로 추가'를 시험합니다. 프로덕션 코드에 시험 전용 허용 분기는 없습니다.

## 7. 다음 묶음 (이번에 넣지 않음)

- **사진 등록 [원본에서 채우기]**(`/admin/media`): 원본 주소를 넣고 위키미디어 공용 `api.php?action=query&prop=imageinfo&iiprop=extmetadata`(Artist·LicenseShortName·LicenseUrl)로 작가·이용조건·원본 제목을 채웁니다. 같은 `fetch-check`의 SSRF 방어를 공유하는 JSON 조회가 필요하고 사진 등록 폼·권리 확인 규칙(NAV-04)과 맞물려 이번 묶음에서 제외했습니다.
- 본문 편집 중(미저장) 내용 기준 후보, 확인 결과를 출처 표에 남기는 '자동 확인' 칸(마이그레이션 필요).
