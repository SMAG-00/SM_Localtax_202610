# W10-d 법령 뷰어·해석 DB·관련 자료: 설계와 구현 기록 (개발 문서)

2단계 설계(`docs/dev/2단계_설계.md`) 1장 W10-d와 3·5장, PRD-02 LAW-01~06·CASE-01~03·TX-10·TX-11·ART-12·FAM-06에 맞춘 설계 겸 구현 기록입니다. 설계와 다르면 PRD가 맞고 이 문서를 고칩니다. (2026-10-25 작성)

## 3. 데이터 이름

- `links`: `src_kind`(`legal_doc`·`article`) · `dst_kind`(`law_provision`·`legal_doc`) · `relation`(`cites`·`interprets`·`explains`) · `origin`(`auto`·`editor`) · `status`(`candidate`·`confirmed`·`rejected`). 조문 끝점은 개정판 행이 아니라 (법령 번호, 조, 가지 번호)라서 개정판이 늘어도 연결이 유지됩니다. 대상이 없으면 저장 거부(트리거), 반려는 되살릴 수 없고, 후보 넣기 함수 `link_add_candidate`는 멱등입니다.
- `law_delegations`: 법률 -> 시행령 -> 시행규칙 방향·같은 묶음(이름 규칙)·양 끝 조문 존재 검사, `source`(`api`·`parsed`·`editor`)와 `source_ref` 필수.
- `quality_samples`: 위임 매핑 50건 이상 + 95%(48 합격·47 보류), 조문 인용·기사 패턴 100건 이상 + 95%(95 합격·94 보류). 합격 칸은 DB 생성 칸 하나이고 종류별 가장 최근 표본이 기준입니다(수동 칸 없음).
- `legal_doc_texts`: 스냅샷에서 트리거가 뽑은 읽을 글자와 검색 칸(스냅샷 없는 문서는 행이 없음). `legal_doc_holds`: 실명(`real_name`)·주민등록번호(`rrn`) 패턴 보류 + 공통 검수 `legal_doc`(`pii_hold:<문서>`) 항목. 풀기는 `legal_doc_hold_release`(검수 승인 필요, 주민등록번호가 남아 있으면 승인돼도 불가).
- 공개 뷰: `public_laws`·`public_law_versions`·`public_law_articles`·`public_law_families`·`public_law_delegations`·`public_legal_docs`·`public_legal_doc_bodies`·`public_links`·`public_quality_gates`. 기능 키·권리 확인·스냅샷·원천 이용 조건(`allowed`)·공개 보류·표본 검사 관문을 뷰 안에서 모두 겁니다. 스냅샷 번호·해시·권리 상태 칸은 뷰에 없습니다.
- anon 실행 함수 2개: `search_legal_docs`·`legal_doc_type_counts`(security invoker, 공개 뷰만 읽음). `verify-rls-remote` 허용 목록과 그 시험을 같은 변경에서 고쳤습니다.
