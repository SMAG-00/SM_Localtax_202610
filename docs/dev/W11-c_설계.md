# W11-c 신탁·정비·금융 구조 세금 가이드와 판정: 구현 기록 (개발 문서)

3단계 설계(`docs/dev/3단계_설계.md`) 1장 W11-c와 1.1·2.1·2.2·3장에 맞춘 구현 기록입니다. 설계와 다르면 설계가 맞고 이 문서를 고칩니다. (2026-10-26 작성)

지키는 선: 이 단위의 코드와 시험 자료에는 실제 법령·세무 문장, 세율·공제·기한·한도 값, 감면·판정 요건, 달력 날짜를 쓰지 않습니다. 가이드 원고·판정표·요건 사전은 W11-a가 만든 빈 표에 감수 입력으로 채우고, 시험 자료는 지어낸 값에 `시험용` 표시를 붙입니다. 기능 키(`trust_tax_guide`·`redevelopment_tax`·`finance_tax_guide`·`tax_determination`·`redevelopment_status`)는 모두 꺼 둔 채 출하합니다. 국세 금액은 만들지 않습니다. 사이트 이름은 `packages/ui/src/brand.ts`에서만 읽습니다.

## 1. 이어받는 것

| 이미 있는 것 | W11-c가 쓰는 방법 |
|---|---|
| W11-a `guides`·`guide_versions`·`guide_sign`·`guide_publish`·`public_guides`(허브 `realestate_tax`·`trust`·`redevelopment`·`finance_tax`) | 해설 원고는 이 표 하나. W11-c는 원고를 복사하지 않고 "어느 화면에 어느 가이드를 붙일지"만 `guide_placements`에 둡니다 |
| W11-a 판정표 종류 `trust_taxpayer`·`redevelopment_right`·`redevelopment_tax`·`trust_acquisition`, 평가기 `evaluateConclusionTable`·`parseTableByKind`, `public_determination_tables`·`public_requirement_dictionary` | 판정 화면은 브라우저에서 표를 평가합니다. 신탁 보유세 납세의무자 판정(TRU-03)과 PR-12 신탁 보유세 판정은 같은 표·같은 함수를 호출합니다 |

## 2. 결정

| # | 결정 | 이유 |
|---|---|---|
| 1 | 같은 해설을 두 경로에 두지 않는 방법은 `guide_placements`입니다. 배치 표에는 원고 칸이 없고 가이드 ID·화면 종류·대상 키·순서만 둡니다 | 3단계 설계 3장 c행, TRU-01·02 수용 기준 "중복 원고 0" |
| 2 | TRU-02 = DF-08: 신탁 주제 가이드는 허브 `trust`의 한 행입니다. 허브 `finance_tax`에 주제 `trust`를 따로 만들면 배치 표 트리거가 거부합니다. 두 화면(신탁 유형 페이지·금융 구조별 세금 가이드 허브)은 같은 가이드 ID를 배치하고, 같은 `public_guides` 읽기에서 같은 버전·본문 해시가 나옵니다 | PRD TRU-02 "같은 가이드 버전 ID가 열립니다" |
| 3 | DF-08 공개 관문: 설정 `finance_tax_guide_review`({reviewer, reviewed_on, conclusion, ref}) — `conclusion = approved`와 기록 참조(`ref`)가 없으면 기능 키 `finance_tax_guide`를 켜지 못합니다(저장 거부). 공개 배치 뷰는 이 키가 꺼져 있으면 `finance_tax_hub` 배치를 0행으로 냅니다 | 3단계 설계 §5 #5, 위험 표 "자본시장법" |
| 4 | PR-12 판정 종류 6가지(정비 4·신탁 2)는 판정표 종류 4개에 대응합니다: 입주권 승계취득 → `redevelopment_right`, 조합 원시취득 구분·청산금·멸실 후 토지분 → `redevelopment_tax`(판정 종류를 사실 `judgment_type`으로 받음), 신탁 이전 취득세 → `trust_acquisition`, 신탁 보유세 → `trust_taxpayer`(TRU-03 판정표 그대로) | PRD 7장 kind 이름·4-I 목록. 판정표 본문이 `judgment_type`을 어떻게 쓰는지는 감수 입력 [감수 필요: 판정 종류] |
| 5 | `project_stage_lenses.determination_kind`(마이그레이션 119)는 비어 있어도 되는 칸입니다. 값이 있어야 그 단계 카드에 "세금 판정" 진입 버튼이 생기고, 값이 없으면 버튼도 "준비 중"도 그리지 않습니다 | PR-12 "진입 버튼 0('준비 중' 0)" |
| 6 | 판정 입력은 브라우저 상태에만 둡니다. 서버·이벤트·URL·브라우저 저장소에 쓰지 않습니다. 트래커 단계에서 들어오는 경우 단계 값만 주소의 `stage` 쿼리(값 목록 검사)로 미리 채우고, 프로젝트 ID·입력값은 보내지 않습니다 | PRD 5장·PR-12 수용 기준 |
| 7 | 이벤트는 새로 만들지 않고 W11-0의 `guide_viewed`·`determination_completed`·`step_viewed`를 씁니다 | 이벤트 78종 불변 |

## 5. 확인 필요와 남은 일

- 판정 종류 이름·`judgment_type` 값은 감수 입력입니다(결정 4). 판정표가 비어 있으면 모든 판정 화면은 404가 아니라 진입 자체를 그리지 않습니다.
- 마이그레이션 119는 `project_stage_lenses`의 공개 뷰를 건드리지 않았습니다. c6에서 단계 페이지가 `determination_kind`를 읽으려면 그 공개 뷰에 칸을 더하는 마이그레이션(121 예비)이 필요합니다 — 뷰 정의를 확인한 뒤 추가합니다.
- 관리 화면(`/admin/guides`)에서 배치를 등록하는 입력은 c1 마무리 항목입니다. 지금은 service_role 쓰기(SQL/관리 API)만 열려 있습니다.
- `verify-rls`: 새 뷰 `public_guide_placements`를 허용 목록에 넣어야 하는지 리드가 `verify-rls` 실행 때 확인합니다. 새 DB 함수를 anon에 열지 않았습니다.
