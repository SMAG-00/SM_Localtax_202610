# W13-d 알림·맞춤 브리핑 설계 (NOTI-01 · WS-06)

5단계 설계 1.1절 W13-d 행과 PRD-05 NOTI-01·WS-06을 구현하는 약속입니다. 법률 문구(수신 동의·고지)는 자리 표시로만 둡니다. 마이그레이션은 206~209만 씁니다.

## 1. 실사로 확인한 것 (2026-10-27)

| 확인 | 결과 | 이 단위의 결정 |
|---|---|---|
| 1단계 지자체 주간 메일(LG-07) 전용 표·작업 | 없습니다(코드·마이그레이션 검색 0건). 주간 메일에 가장 가까운 것은 W10-e 주간 브리핑(`consents.kind='brief'`, `brief_issues`, `alert_deliveries`) | "주간 메일과 중복 0" = 빈도가 주간이면서 확인된 `brief` 구독이 있는 회원의 알림은 웹 알림함에만 쌓고 메일은 보내지 않습니다. 메일 중복은 `notifications` 유일 키와 이 규칙으로 막습니다 |
| 수신 설정·관심 지역 | `consents.kind='receive'`(철회 안 된 행) / `profiles.interest_region_codes` | 알림 행은 둘 다 있을 때만 만듭니다(동의 없으면 0건) |
| 지역 코드 승계 | `regions.successor_code` | 폐지된 코드는 후속 코드로 읽습니다(시·도는 하위 시·군·구 포함) |
| 메일 모듈 | `sendMail` + 템플릿 `amendment_alert`(제목·본문을 호출 쪽이 완성) | 새 템플릿 없이 이 템플릿을 씁니다. 본문 끝에 수신 거부 링크 필수 |
| 지방세 달력 본문 구조 | `tax_calendar.body`는 jsonb이고 날짜 구조(키)가 아직 정해지지 않음 | `calendar` 종류는 표 허용값에만 두고 수집기·화면은 만들지 않습니다(준비 중 표시 0). 본문 구조가 확정되면 수집기를 더합니다 [PO 입력] |

## 2. 알림 (NOTI-01)

- 종류 4: `law`(스크랩한 조문이 개정됨) · `saved_search`(알림을 켠 저장 검색의 새 기사) · `region`(관심 지역의 새 기사) · `calendar`(위 표).
- 설정 `notification_prefs`: 켠 종류, 빈도(즉시·일간·주간), 첫 켠 시각(`enabled_at` — 이전 기사로 쏟아지지 않게 이 시각 이후 공개분만). 거부는 종류를 비우는 것이며 알림 메일의 링크 한 번(버튼 한 번)으로 합니다. 수신 동의 철회는 별도로 모든 발송을 막습니다.
- 수집(DB 함수 `noti_collect`): 공개·권리 확인(`lead_media_cleared`)·무료 기사만, 광고·핫뉴스·유형 없는 이관 기사 제외. 같은 기사는 종류와 관계없이 회원당 한 번(`notifications` 유일 키 + 교차 종류 검사). 저장 검색은 `workspace` 권한이 있을 때만.
- 발송(`noti_due` → 서버가 묶음 메일 1통): 크론 개수 한도 때문에 작업은 하루 한 번(`notify-daily`, 한국 08:15)만 돕니다. 그래서 화면의 빈도 선택지에서 "즉시"를 뺐습니다(하루 한 번·주 한 번만 보입니다. 2026-10-28 통합 수정). DB 값 `instant`는 이미 저장된 값 호환용으로만 받으며 화면에는 "하루 한 번"으로 보이고, 발송은 이 실행 때 이뤄집니다(게시 후 1시간 보장은 크론 한도가 풀리거나 게시 이벤트 대기열이 생기면 더합니다 [PO 입력]). 즉시=매 실행, 일간=한국 시각 기준 발송 시각 이후 하루 1통, 주간=지정 요일. 시각·요일은 설정 `notification_policy`. 실패는 3회까지 다시 시도하고 그 뒤에는 멈춥니다. 기록(`notifications`)에는 제목·상대 경로·지역 코드뿐이고 상세 주소·좌표 칸은 없습니다.
- 화면 `/my/notifications`(설정 + 최근 알림 + 읽음), 지자체 허브의 [이 지자체 소식 받기](관심 지역에 담고 지역 알림 켜기). 기능 키 `my_notifications` 꺼짐이면 404.

## 3. 맞춤 브리핑 (WS-06)

- 선정은 순수 규칙(`lib/briefing/select.ts`): 후보 = 관심 분야·관심 지역 기사(`member_feed`), 저장 검색 제목 일치 기사, 승인·공개된 결정례 요지(`public_case_summaries`, 4단계 AIOPS-07 승인분만). 정렬 = 이유 우선순위 → 최신 → 번호 오름차순, 상위 N건(설정 `briefing_policy.max_items`, 비어 있으면 0 = 닫힘). 같은 입력이면 같은 결과. 새 문장을 만들지 않고 AI를 부르지 않습니다.
- 표 `briefings`: (회원, 주차) 유일, `items`는 종류·번호·이유·기준일뿐이며 DB 트리거가 공개 상태 콘텐츠만 허용합니다(미승인·비공개·유료 항목 0). 출판물은 후보에 없습니다(요약 권리 0).
- 대상: 기능 키 `my_briefings` ∧ 개인 설정(`notification_prefs.briefing` = web/mail) ∧ `workspace` 권한. 관심 항목이 없거나 후보가 0이면 만들지 않고 보내지 않습니다. 메일은 `receive` 동의 + 설정이 mail일 때만, 주 1회(월요일 한국 시각, 같은 주차 재실행해도 1통).
- 화면 `/my/briefings`, 대시보드 위젯(최근 브리핑 항목), 열람 시 `opened_at`.

## 4. 작업

`notify-daily`(매일 UTC 23:15 = 한국 08:15, 크론 1줄): 수집 → 발송 → (월요일 한국 시각) 브리핑 생성·발송. 기능 키 둘 다 꺼짐이면 아무것도 하지 않습니다.
