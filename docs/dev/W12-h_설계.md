# W12-h 데이터 스토리·채널 배포 키트: 설계와 구현 기록 (개발 문서)

4단계 설계(`docs/dev/4단계_설계.md`) 1장 W12-h 행, 1.1 단계 h1~h5, 2.1 번호 179~181, 2.2 같이 고치는 파일, 3장 h행에 맞춘 기록입니다. 설계와 다르면 설계가 맞고 이 문서를 고칩니다. (2026-10-27 작성. 상태 칸의 "완료"는 코드와 시험 파일이 있다는 뜻입니다)

지키는 선: 통계 값·데이터셋 이름·이용 조건 문구·채널 원고 문장은 이 단위의 코드에 없습니다. 시험 자료는 모두 `시험용` 표시의 지어낸 값입니다. 수집 배치와 키트 만들기에는 AI 호출이 0이고(원고 생성은 W12-f가 이미 `review_items`에만 씀), 국세 금액 계산 0, 외부 채널 게시 API 호출 0(채널 계정 키가 환경변수에 없음), 기능 키 `data_stories`·`channel_kit`은 꺼 둔 채 출하합니다. DB 시험·Playwright E2E·`next build`는 이 작업에서 실행하지 않고 리드가 차례로 돌립니다.

## 3. 결정 사항

| # | 결정 | 이유 |
|---|---|---|
| 1 | 통계 초안은 `review_items`가 아니라 `stats_series` 초안 행으로 둡니다 | `review_items` 종류는 0차(150)에서만 늘릴 수 있고, 시계열은 승인 전 내용이 불변이어야 해서 전용 표가 맞습니다. 편집자 알림은 관리 화면 목록(새 기준연도 대기·기사 영향)으로 합니다 |
| 2 | 승인본이 새 기준연도로 대체되면 이전 승인본은 `superseded`로 남습니다 | 기사 차트가 시계열 ID와 기준연도로 고정되어 계속 같은 값을 보이게 하려는 요구 |
| 3 | 채널 유입 측정은 별도 랜딩 페이지가 아니라 기사 화면의 등록 값 검사로 합니다 | 채널 링크가 곧 기사 주소(W12-f `utmUrl`)이고, 캠페인 랜딩(W10-i)과 같이 등록 값만 측정하고 주소는 측정 뒤 정리하는 방식을 따릅니다 |
| 4 | 키트는 .txt/.json 내려받기입니다 (zip·이미지 합치기 없음) | 이미지는 기존 미디어 주소·대체 텍스트 목록만 담고, 새 의존 0 |

## 4. 확인이 필요한 곳 (PO)

- 통계 데이터셋 이용 조건·공공데이터포털 계정, 응답 모양(견본 계약 확인 후 `mois_local_tax_stats` 원천을 allowed로).
- 채널 운영 범위·계정 명의, 채널별 글자 수 상한(`channel_copy_limits`).

## 6. 남은 일과 한계

- 첫 실패가 나올 만한 곳: DB 시험의 `review_item_transition` 인자 모양, 기사 삽입 필수 칸, E2E의 `/data` 캐시(서버 재시작으로 우회).
- 국세 항목 이름 거르기는 조각을 이어 만든 패턴이라 새 국세 낱말은 TS(`NATIONAL_STEMS`)와 SQL 179 양쪽에 같은 조각을 더해야 합니다(시험이 대조).
- 키트 대체 텍스트는 기사 본문 이미지 블록의 `alt`만 모읍니다. 비어 있으면 체크리스트에서 사람이 확인합니다 [리드 확인].
- 채널 유입의 브라우저 측 전송은 화면에 그려지는 것이 없어 E2E에서 직접 확인하지 못합니다(공개 뷰·단위 시험으로 대체). 한글 slug 기사는 `article-<번호>`로 집계됩니다.
