# W6 지자체뉴스(금주 핫뉴스·행사 목록·달력) — 설계 약속 (개발 문서)

PRD-01B 8장 W6(핫뉴스 후보 → 선정 → 요약 → 유사도 → 발행, 주간 페이지, 기획 전환, 허브 `금주 핫뉴스`·`행사안내` 블록 열기, 행사 목록·달력·상세·회차·상태·재확인·`Event` 데이터·연결 — LG-01~06 · LG-08~14 · LG-16 · REG-04 · REG1-04 · REG1-05)를 구현할 때 DB·서버·화면·시험이 같은 이름과 같은 규칙을 쓰기 위한 약속입니다. W5 설계와 같은 모양으로 짧게 씁니다.

**이 문서와 구현은 실제 보도자료·행사 사실·법령·세무 문장을 쓰지 않습니다.** 화면 틀·입력 방식·발행 규칙·빈 내용일 때의 표시만 정합니다. 운영 DB의 씨앗은 비어 있습니다(설정 기본값과 출처 차단 목록만 있음). 시험 자료는 모두 지어낸 값(`*.example.test`)입니다.

**MVP 방침(PO 2026-10-24 "최초 완성품을 돌리면서 수정 … 빨리빨리")**: 관리 입력(또는 선택) → 공개 화면이 끝까지 이어지게 만들고, 지켜야 할 선(기본 거부 RLS·공개 뷰·유사도 발행 차단·필수 필드 누락 비공개·상태 이력 추가만·축제 범위·키 꺼짐 링크 0)은 그대로 둡니다. 외부 호출·새 키·장식은 없습니다.

## 2. 데이터 모델

| 표 | 핵심 칸 | 규칙 |
|---|---|---|
| `hot_news_candidates` | sido_code, region_code, source_id, title, press_org, announced_at, source_url(유일), license_type, original_text(내부), status(new·selected·dismissed) | 조회수·클릭 칸 없음(시험이 칸 이름을 봅니다). 출처 `source_id`가 설정 `digest_sources`에 허용 근거(근거 문장·확인일)와 함께 있어야 저장됩니다. 같은 원문 주소는 한 번만(멱등). 공개 뷰에 없음 |
| `weekly_digests` | sido_code, week_key(`YYYY-WW`), starts_on, ends_on, status(draft·published), published_at·by | 주차는 ISO 8601(월요일 시작, 한국 날짜). 존재하지 않는 주 거부. 시·도 + 주차 유일. 발행 뒤 되돌리지 않고 주소는 계속 200(아카이브) |
| `digest_items` | digest_id, candidate_id, region_code, title, source_url, press_org, announced_on, license_type, summary, figures_checked, sim_*(상태·최고 유사도·유사 문장 비율·문장 목록·규칙 판·검사한 요약 해시), original_text(내부), assignment_id | 원문 주소·발표기관·발표일·요약이 모두 있어야 저장됩니다. 요약 길이는 설정 상한 이하. 발표일이 그 주 범위 안이어야 합니다. 요약을 고치면 유사도 기록이 지워집니다. 발행된 주의 항목은 `assignment_id`만 바뀝니다 |
| `local_events` | slug, series_key, title, category(tax_finance·development·festival·commercial·other), organizer, organizer_type, venue, region_code, starts_at, ends_at, official_url, source_name, confirmed_on, status_override(null·cancelled·changing), status_source_url·status_confirmed_at, sponsored, published | 필수 칸은 모두 NOT NULL이라 하나라도 비면 저장되지 않습니다(= 비공개). 상태 `예정·진행·종료`는 시각으로 계산하고 `취소`·`변경 확인 중`만 편집자가 지정합니다(취소는 출처 주소·확인 시각 필수). 끝난 회차의 날짜는 고치지 않고 새 회차는 새 행입니다 |
| `event_status_history` | event_id, from_state, to_state, source_url, confirmed_at, changed_by | 추가만. 지정 상태가 바뀔 때마다 트리거가 1행 |
| `event_links` | event_id, target_kind(project·article), target_id, reason, confirmed_by·at | 행 = 편집자가 확인한 연결. 공개 뷰는 대상이 공개 중일 때만 보입니다 |

설정: `digest_sidos`(핫뉴스를 내는 시·도 코드, 씨앗 `[]`) · `digest_summary_max_chars`(300) · `digest_sources`(`[]`, 항목 `{id, name, host, kind(rss·board), basis, checked_on}`) · `event_url_blocked_domains`(단축 주소·개인 블로그 서비스 도메인 씨앗) · `event_recheck`(`{ "days": 7, "hide_stale": false }`). 공개 읽기 정책에는 넣지 않습니다. 기능 키 `weekly_digest`·`local_events`는 W4부터 있고 꺼져 있습니다. `weekly_digest`는 `digest_sidos`가 시·도 2곳 이상일 때만 켜집니다.

## 11. 기록

- 유사도: 항목마다 검사 시각·최고 유사도·유사 문장 비율·유사 문장 목록·규칙 판(`similarity_internal` 판)·검사한 요약의 해시가 남습니다. 발행은 해시가 현재 요약과 같고 상태가 `pass`일 때만 됩니다.
- 상태 이력: 행사 지정 상태(정상·취소·변경 확인 중)가 바뀔 때마다 이전·이후·출처 주소·확인 시각·변경자가 추가만 표에 남습니다.
- 감사 로그: 관리 화면의 쓰기는 모두 `local_news.*` 동작으로 남깁니다.
