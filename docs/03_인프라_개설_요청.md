### 1.2 0단계 실사

PRD_최종 §11.1 W0와 13장 11~15번의 실사다. 계정을 만들지 않는 항목도 있지만, 결과가 1단계 범위와 일정을 정하므로 여기에 둔다. 결과는 실사표·권리표·결정 기록으로 남긴다. 확인되지 않은 항목이 있어도 테스트 주소의 독립 개발은 진행하되, 관련 데이터·기능은 공개하지 않는다.

## 7. 환경변수와 계정 규칙 (ENV-01~06)

PRD_최종 §9.2다. 앱이 실행에 쓰는 **API 키·토큰만** 환경변수로 다룬다. GitHub·Vercel·Supabase·Anthropic의 **로그인 ID·비밀번호는 `.env`에 넣지 않고** 비밀번호 관리자(2-13)에 둔다.

| 규칙 | 내용 |
|---|---|
| 계정 | 회사 명의, 2단계 인증, 관리자 2명 이상. Supabase prod·staging, Vercel 환경 3종(Production·Preview·Development), Anthropic 운영·개발 워크스페이스와 키 분리 (2-12) |
| 파일 | 저장소에는 키 이름만 적은 `.env.example`, 로컬은 `.env.local`(커밋 금지 — `.gitignore`), 운영·미리보기는 Vercel 환경변수, CI는 GitHub Actions Secrets (2-14) |
| 노출 차단 | 비밀값에 `NEXT_PUBLIC_` 금지, CI가 번들·로그의 키 패턴을 검사, 비밀값 스캔·push protection, Preview가 prod DB를 가리키면 실패 |
| 유출 대응·버전 | 노출 즉시 폐기·재발급·감사 기록. Node·패키지·모델 버전은 `.nvmrc`·lockfile·환경변수로 고정 |
| 환경별 값 | 로컬(`.env.local`)·Preview·Development는 Supabase staging·Anthropic 개발 키, Production은 Supabase prod·Anthropic 운영 키. 테스트 주소의 Production은 전환 전까지 `SITE_INDEXING=off` |
| 설정값 | 지방세봇 모드 하루 한도·예산 경보 기준·금지 표현 사전·지역 색인 임계값·지역 자료 시점 점검 기준은 환경변수가 아니라 DB `settings` 테이블에 둔다. 모델 ID는 환경변수에만 두고 코드에 상수로 적지 않는다 (PRD-00 10.6) |

| 변수 | 범위 | 두는 곳 |
|---|---|---|
| `NEXT_PUBLIC_SITE_URL`, `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY` | 브라우저 공개 가능 (RLS 보호) | `.env.local`·Vercel |
| `SITE_INDEXING`, `ANTHROPIC_MODEL_ANSWER`, `ANTHROPIC_MODEL_ROUTER`, `ASSISTANT_*`(기능 플래그·예산·속도·보관 기간) | 서버 | `.env.local`·Vercel |
| `SUPABASE_SERVICE_ROLE_KEY`, `ANTHROPIC_API_KEY`, `RESEND_API_KEY`, `GUARD_SECRET` | **서버 전용** (`ANTHROPIC_API_KEY`는 사용자 경로 키 하나다 — 1단계 AI 도우미 `packages/assistant`와 4단계 지방세봇 모드 `packages/agent`가 함께 쓴다. AI 도우미는 service role 키를 쓰지 않는다) | `.env.local`·Vercel — Preview·Development에는 staging·개발 키 |
| `SUPABASE_DB_URL`, `SUPABASE_ACCESS_TOKEN`, `VERCEL_TOKEN` | CI 전용 | GitHub Actions Secrets — Vercel 환경변수에 넣지 않는다 |

저장소에 `.env.example`로 들어갈 목록이다. 값은 비워 두고, 실제 값은 위 표의 두는 곳에만 넣는다. 아래 블록에서 `=` 뒤에 적힌 값은 **권고값 표시**다 — 저장소의 `.env.example`에는 값을 비우고 권고값을 주석에 적는다 (PRD-01A ENV-02, 저장소의 `.env.example`이 기준). 아래 모델 값은 시작 후보이며, 계약·공시를 확인한 뒤 정한다. `ASSISTANT_*`와 봇 방지 변수의 이름은 예시이며 저장소의 `.env.example`에서 확정한다.

MAIL_SMTP_PASSWORD=                   # 비밀 · 서버 전용 (Resend이면 그 키)
MAIL_SMTP_SECURE=                     # true이면 처음부터 TLS
SENTRY_DSN=                           # 선택
ANTHROPIC_API_KEY=                    # 비밀 · 서버 전용 · 사용자 경로 키 하나 — 1단계 AI 도우미(packages/assistant)·4단계 지방세봇 모드가 함께 쓴다. 로컬·Preview는 개발 워크스페이스 키, Production은 운영 워크스페이스 키 (2-12)

BOT_PROTECTION_SECRET=                # 비밀 · 위와 같다
CRON_SECRET=                          # 비밀 · 서버 전용 · Cron 호출 인증 (1단계부터 — 핫뉴스 후보 수집·행사 재확인·링크 점검)

# PORT는 넣지 않는다 — 개발 서버는 3001 고정(개발 스크립트), 사내 서버 Docker는 컨테이너 설정에서 정한다

# ── CI 전용 (GitHub Actions Secrets — .env.local·Vercel에 넣지 않는다) ──

5. 1.2 실사 결과(언론사 등록·네이버 제휴·2026 규정, 기존 상품·판매 현황·'세무상담' 제공 주체, 사진 권리, 기존 관광성 URL, 김의효 브랜드 증빙, SM 소속 전문가 소속 형태, 1단계 외부 데이터)를 실사표·권리표·결정 기록으로 정리한다. 확인되지 않은 항목은 `요건 미확정`·비공개로 둔 채 개발을 이어 간다.
6. 1단계 작업 단위(W1부터 — PRD_최종 §11.1, PRD-01A·01B·01C)대로 시작한다. AI 도우미(W7b)는 개발 워크스페이스 키로 만들고, 100문항 평가를 통과한 뒤 운영 키로 공개한다.
