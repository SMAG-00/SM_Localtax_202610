## 1. v2.0 분석 결과와 정리 방식

v2.0은 요구는 충실하지만 **세 번의 추가 지시(AI 도우미, 전문가 소개, SM 전문가 연락)를 뒤에 덧붙이면서 구조가 흐트러졌습니다.** 정리본은 내용을 빼지 않고 순서·중복·충돌을 바로잡았습니다.

### 2.2 불변 원칙

1. **세액은 감수된 결정론적 엔진만** 냅니다. AI는 세액·감면 판정·개별 세무 결론을 만들지 않습니다.
2. AI와 자동화는 **안내·초안**에만 쓰고, 대외 발행은 사람이 승인합니다.
3. 계산 입력값은 서버·이벤트·URL에 저장하거나 보내지 않습니다.
4. (2026-10-25 개정 — W11-g) **양도세(양도소득세·지방소득세 양도소득분) 금액은 만들지 않고** SM 부동산 세금 플랫폼으로 연결합니다. 상속세·증여세 금액은 「안심 상속증여계산기」에서 이식한 결정론적 엔진이 세무 감수 서명과 공식 결과 대조 게이트를 통과한 뒤에만 냅니다. 게이트 전에는 외부 계산기로 연결합니다. 국세와 지방세 금액을 한 줄 합계로 만들지 않고, AI는 국세 금액을 만들지 않습니다.
5. 기존 SM 부동산 세금 플랫폼은 바꾸지 않습니다. 1단계는 연결, 2단계는 검수된 엔진을 복사합니다.
6. 기사·정보 목록(행사·분양)·계산 도구·광고·상품을 CMS·URL·화면·구조화 데이터에서 구분합니다.
7. 투자 추천, 시세·금리 예측, 세무 신고 대행은 하지 않습니다.
8. **전문가 소개는 SM(선명) 소속 전문가만** 합니다 — 프로필은 관리자가 등록하고(AI가 쓰지 않음), 외부 전문가 등재·유료 등재·소개 대가는 없습니다(2026-10-24 PO 결정). **SM 소속 전문가는 이용자가 동의해 남긴 질문 요약을 받아 연락**하는 경우에만 정보를 전달합니다.
9. 출처·기준일·권리가 확인된 자료만 공개하고, 증빙 없는 경력·숫자는 표시하지 않습니다.
10. Vercel·Supabase 클라우드로 시작해 사내 Docker로 옮길 수 있게 만들고, 개발 포트는 `localhost:3001`로 고정합니다.

### 3.1 성장 순서

신뢰받는 전문 보도 → 검색·AI 검색·네이버 유입과 재방문 → 계산·해설·도우미로 문제 해결 → 구독·도서·교육·상담의 유료 가치 검증 → 수익 확대. 지역·부동산·금융 기사는 모두 「지방세로 읽기」로 지방세 해설·계산기·도서·전문가에게 이어집니다.

### 3.2 대표 사용자

| 사용자 | 첫 과업 | 성공 상태 |
| --- | --- | --- |
| 지방세 담당 공무원 | 개정 트래커 → 개정 브리핑 → 원문 | 기준일이 맞는 원문과 해설을 대조하고 교육원 강좌로 이동 |

### 4.3 핵심 여정

1. **지방세 공무원**: 홈 → 개정 트래커(2026년 지방세제 개편안) → 개정 브리핑 → 원문 → 교육원 개정세법 강좌 신청.
2. **조합원**: “○○구역 관리처분 취득세” 검색 → 프로젝트 페이지 → 재개발 상세 → 「지방세로 읽기」 → SM 취득세 계산기(새 창).
3. **개발금융 실무자**: PF 책임준공 사례 → 신탁 구조 해설 → 칼럼 → 브리핑 구독 → (3단계) 기관 구독.
4. **지역 주민**: 우리 구 금주 핫뉴스 → 정비계획 주민설명회 → 프로젝트 트래커 → 관심 프로젝트 알림.
5. **개별 상담이 필요한 이용자**: AI 도우미에 “제 경우 감면되나요?” → 관련 해설 + ‘SM 전문가 보기’ 또는 ‘SM 전문가에게 연락 받기’ → 요약 확인·동의 후 제출 → 담당 전문가 연락.
6. **AI 검색 유입**: AI 모드 답변의 인용 링크 → 「지방세 50문 50답」 → 관련 도서 카드 → 스토어.
7. **광고 유입 (2단계)**: 광고 “이 집 취득세 얼마?” → 캠페인 랜딩 `/go/acquisition` → 부동산 세금 계산기(취득세) → 결과 → ‘SM 전문가에게 상담 요청’ → 접수 완료.

## 5. 4대 콘텐츠 분야

### 6.4 SM(선명) 소속 전문가 연락 요청(EXPL-13\~21)

이용자가 궁금한 점을 요약해 남기면 **SM 소속 전문가가 먼저 연락**합니다. 이 경로에서만 이용자가 확인·동의한 요약과 연락처를 전달하고, 상담·업무는 자격 있는 수행 주체(세무사 사무소·세무법인·법률사무소 등) 명의로 이뤄집니다.

1. **진입** — 도우미의 ‘하지 않음’ 응답, `/experts` 상단, 기사·칼럼 하단.
2. **요약** — 도우미에서 오면 마스킹된 대화로 AI 초안을 양식에 채우고, 직접 오면 이용자가 씁니다.
3. **확인·동의** — 이용자가 요약을 고치고 분야·연락처·희망 시간을 넣은 뒤 필수 동의 후 직접 제출합니다. 연락처는 Claude API로 보내지 않습니다.
4. **배정** — 분야별 당번표로 배정하고, 담당자에게는 개인정보 없는 보안 화면 링크만 알립니다.
5. **연락** — 목표 시간(예: 1영업일) 안에 연락해 업무 범위·비용·수행 주체를 먼저 안내합니다.
6. **종결** — 계약은 이용자와 전문가(사무소)가 직접 맺고, 플랫폼은 상태만 기록한 뒤 보관 기간(기본 1년)이 지나면 파기합니다.

접수와 첫 연락은 무료이며, 요청 데이터는 담당자·운영 책임자만 열람(RLS·감사 로그)하고 기사·AI 학습·마케팅에 쓰지 않습니다. 주민등록번호·계좌번호 입력은 막고, 기한이 임박한 사안은 직접 연락을 권합니다.

## 7. 신뢰·성장 엔진

신뢰(브랜드·편집 품질)가 유입(네이버·검색·AI 검색)을 만들고, 유입이 수익으로 이어집니다. 세 엔진 모두 **실제 증빙과 원문 근거**가 있어야 작동하므로 숫자·경력·기사 수를 꾸며 채우지 않습니다.

### 7.2 네이버 뉴스 제휴(NAV-01\~24)

첫 목표는 **뉴스 검색 제휴**이며, 콘텐츠 제휴는 검색 제휴사만 신청할 수 있어 그다음입니다. 선정은 외부 결정이므로 PRD는 보장하지 않습니다.

| 2026년 규정 요점 `[웹확인]` | 제품이 대응하는 방식 |
| --- | --- |
| 2026-02 새 규정 발표, 3월 접수, 이후 매년 1회 심사, 뉴스스탠드 제외 | 다음 접수 공고를 목표로 1단계부터 실적을 쌓음(NAV-16) |
| 정량 50점 + 정성 50점, 검색 제휴 80점·콘텐츠 제휴 90점 합격선 | 규정 값을 코드에 고정하지 않고 버전 등록 |
| 자체 생산 비율·월 송출량·기획·탐사 실적·기자 1인당 생산량 중 하나라도 0점이면 탈락 | 월별 준비도 대시보드로 어느 지표도 0에 가깝지 않게 관리(NAV-17) |
| 평가 대상은 과거 1년 중 **임의의 3개월** | 임의 3개월 조합 모의 점검 후 신청(NAV-24) |
| 문장 단위 90% 유사 문장이 60% 넘으면 유사 기사 | 발행 전 유사도 검사, 핫뉴스는 편집자 요약+링크(NAV-18, LG-02) |
| 외부 기고자는 1명으로 합산 | 기자·기고자 등록부로 칼럼 비중 관리(NAV-19) |
| 부정평가 2년 누적 10점이면 해지 권고 | 광고성 기사·광고 강요 금지, 영업·기자 권한 분리(NAV-20) |

v1.7의 `NAV-01~15`(등록·제휴 실사, 콘텐츠 유형 구분, 취재 증거·정정·광고 분리, 정량형·정성형 기사 템플릿)는 그대로 쓰고, 분기별 기획·탐사 캘린더(NAV-21), 카카오 뉴스 제휴 병행 검토(NAV-22), 지역 매체 실적 집계(NAV-23)를 더합니다. 핫뉴스·행사·분양 정보·칼럼은 자체 취재 기사로 세지 않습니다.

### 7.3 AEO·GEO·SEO 최적화 알고리즘(OPT-01\~12)

**SEO**는 색인·순위의 기본기, **AEO**는 질문에 대한 직접 답으로 채택되는 구조, **GEO**는 생성형 AI가 우리 페이지를 근거로 인용하고 인물·브랜드를 정확히 인식하게 하는 신뢰 신호입니다. `[웹확인]` 구글은 AI 개요·AI 모드에 추가 요건이나 별도 AI 파일·특수 schema가 필요 없다고 안내하므로, 트릭이 아니라 기본기·답 먼저 구조·근거로 대응합니다.

| 점검 축 | 발행 전 점검 항목(차단 항목은 굵게) |
| --- | --- |
| SEO | 고유 제목·메타 설명·제목 위계·내부 링크 2개 이상·공식 출처·이미지 대체 텍스트, **canonical·중복** |

## 9. 기술·인프라·데이터

### 9.1 기술 구조

Next.js App Router + TypeScript + Tailwind, Supabase(Postgres·Auth·Storage·RLS 기본 거부), PGroonga 검색, 후속 pgvector. GitHub CI → Vercel(Production·Preview), Supabase prod·staging, Resend 메일, Claude API(AI 도우미). DB 변경은 SQL 마이그레이션으로만 하고, 배치는 Vercel Cron과 사내 스케줄러가 같은 함수를 부릅니다. 사내 Docker Compose 이전 시 SSE 버퍼링을 끕니다.

| 패키지 | 역할 |
| --- | --- |
| `apps/web`, `packages/ui`, `packages/db`, `packages/tax-engine` | 웹, 디자인 토큰·컴포넌트, DB 접근, (2단계) 복사한 세액 엔진 |
| `packages/igt-engine` | (3단계 W11-g) 「안심 상속증여계산기」에서 이식한 상속·증여세 결정론적 엔진 — 브라우저 계산만, 양도·부담부증여 없음, `packages/tax-engine`과 한 파일에서 함께 쓰지 않음, AI·서버 경로에서 import 0, 게이트 통과 세목만 공개 |
| `packages/seo-lint`, `packages/similarity`, `packages/structured-data` | AEO·GEO·SEO 점검 엔진, 문장 유사도, 화면과 같은 소스에서 만드는 JSON-LD |

### 9.2 인프라 계정·`.env`(ENV-01\~06)

앱이 실행에 쓰는 **API 키·토큰만** 환경변수로 다룹니다. GitHub·Vercel·Supabase·Anthropic의 **로그인 ID·비밀번호는 `.env`에 넣지 않고** 비밀번호 관리자에 둡니다.

| --- | --- |
| 계정 | 회사 명의, 2단계 인증, 관리자 2명 이상. Supabase prod·staging, Vercel 환경 3종, Anthropic 운영·개발 워크스페이스와 키 분리 |
| 파일 | 저장소에는 키 이름만 적은 `.env.example`, 로컬은 `.env.local`(커밋 금지), 운영·미리보기는 Vercel 환경변수, CI는 GitHub Actions Secrets |
