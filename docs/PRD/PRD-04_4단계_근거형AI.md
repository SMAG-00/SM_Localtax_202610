# 「김의효 지방세연구」 PRD-04 4단계 — 근거형 지방세봇 (AI 도우미 창의 별도 모드)

근거 없이는 답하지 않는 근거형 AI 「지방세봇」을 1단계 AI 도우미 창("무엇을 도와드릴까요?", PRD-01C CHAT)의 **별도 모드**로 엽니다(PRD_최종 §6.2 · PRD_최종 §11.1 W12). 1단계 도우미는 사이트 안내·검색형이고, 지방세봇 모드는 2단계 공공 원문, 3단계 감수 가이드·판정표·쟁점 연결 지도, 권리를 확인한 출판물로 만든 검색 색인을 근거로 빈 요건을 되묻고 인용을 붙여 답합니다. 같은 창에서 300문항 평가를 통과한 뒤 모드 전환을 엽니다(CHAT-15). 마스킹·가드·검증기는 도우미와 같은 코드를 쓰고, 모델·평가 기준은 지방세봇이 더 엄격합니다(1.2). 첨부 보고서가 '지세 로봇'이라 부른 메뉴입니다(이름은 PO 지시로 '지방세봇', PRD-00 4.4). 색인에 아직 없는 최신 원문은 국가법령정보 API로 바로 가져와 근거로 쓰고, 세액을 계산한 답변에는 해당될 수 있는 감면을 판정표로 찾아 붙입니다. 4a 내부 → 4b 초청 전문가 → 4c 대국민 순으로 공개하고, 신탁·정비와 상속·증여 취득세 답변 범위는 각자의 별도 평가를 통과한 뒤에만 엽니다. **국세(상속세·증여세·양도세) 금액은 만들지 않습니다** — 양도세는 SM 부동산 세금 플랫폼의 양도세 메뉴, 상속세·증여세는 「안심 상속증여계산기」(별도 사이트)와 국세청 공식 안내로 연결합니다(PRD_최종 §2.2 원칙 ④). 김의효의 이름·말투로 답하지 않습니다(BR-09). 같은 단계에서 결정례 요지와 키워드 맵, 지방세 데이터 스토리, 채널 배포 키트, 보안 정책 공개를 엽니다. 지방세봇은 홈의 일반 통합 검색을 대체하지 않습니다.

## 1. 목표와 범위

### 1.1 목표

- 1단계 AI 도우미 창에 근거형 지방세봇 모드를 더합니다 — 같은 창, 같은 가드·마스킹·검증기, 더 엄격한 평가(300문항)와 공개 게이트. 별도 URL·메뉴를 만들지 않습니다.
- 지방세 질문에 근거 인용을 붙여 답하는 에이전트를 평가 게이트를 통과시켜 엽니다.
- 세액은 엔진이 계산하고, 지방세봇은 엔진 결과를 그대로 보여 줍니다. 해당될 수 있는 감면도 판정표 결과만 보여 주고, 감면 여부를 단정하지 않습니다.
- 색인에 아직 없는 최신 법령·해석·결정례는 국가법령정보 API로 바로 가져와 근거로 씁니다. 일반 웹 문서는 근거로 쓰지 않습니다.
- 품질을 숫자로 관리합니다. 평가셋 정답률·인용 정밀도·필수 근거 재현율·역질문 누락·치명 오류가 공개를 정합니다.
- 3단계에서 감수한 신탁·정비 가이드·쟁점 연결 지도·판정 도우미(정비·신탁 세금 판정 PR-12 포함)를 근거로 지방세봇 범위를 넓히되, 투자 추천과 시세·금리 예측은 하지 않습니다. 상속·증여는 취득세(지방세) 질문에 답하고, 별도 평가를 통과한 뒤에만 엽니다. 국세(양도세·상속세·증여세)의 금액·공제는 계산하지 않고 SM 부동산 세금 플랫폼의 양도세 메뉴·외부 계산기(PRD-01B FAM-08)·국세청 공식 안내로 연결합니다.
- 지역 관광 질문에는 여행 답변을 만들지 않고 범위 밖임을 안내합니다. 지역 허브로 보내지 않습니다. 해당 지역의 세금·부동산 질문이면 지방세봇 범위에서 답합니다 (PRD_최종 v1.7 §5.3).
- 편집국 AI(결정례 요지·쟁점 태그·대중화 편집·채널별 원고·정합성 감시)를 검수 큐 위에서 돌립니다.
- 결정례를 쟁점 키워드 맵으로 찾게 하고, 지방세 통계를 데이터 스토리로 보여 주고, 승인된 콘텐츠를 여러 채널로 내보냅니다.
- 보안 정책과 내부 통제 목록을 공개해 전문가·기관의 신뢰를 얻습니다.

**범위 플래그** — 3단계에서 신탁법·도시정비법 등의 원문(PRD-03 TRU-04·RDV-05), 감수 가이드(TRU-02·RDV-03), 쟁점 연결 지도(LINK-01), 상속·증여 안내 페이지·상황 카드(1단계 PRD-01B FAM-01·02)와 상속·증여 원인 취득세 계산(2단계 PRD-02 FAM-03·07)이 이미 공개되어 있습니다. 그러나 지방세봇이 이 범위를 답하려면 범위별 평가를 따로 통과해야 합니다. 그래서 청크마다 범위 태그(기본 · 신탁정비 · 상속 · 증여)를 붙이고, `settings`의 범위 플래그(기본 꺼짐)가 꺼진 범위의 청크는 운영 검색에서 SQL로 뺍니다. 평가 실행에서만 켭니다. 플래그가 꺼진 동안 신탁·정비 질문은 지방세법 안의 신탁·정비 조문으로 답할 수 있는 부분만 답하고 감수 가이드·쟁점 지도 링크로 안내하며, 상속·증여 취득세 질문은 안내 페이지·취득세 계산기·공식 원문으로 안내합니다(FAM-09). 상속세·증여세 금액·공제 질문은 플래그와 무관하게 외부 계산기·국세청 공식 안내로 연결합니다. 공식 원문 실시간 조회(ASK-16)는 색인에 없는 *최신* 원문을 채우는 장치이지 범위를 앞당기는 장치가 아닙니다 — 플래그가 꺼진 범위의 법령은 실시간 조회 대상에서도 뺍니다.

**다른 일과의 관계** — AI 공개는 뉴스 제휴·유료 상품의 전제 조건이 아닙니다 — 네이버 제휴는 단계와 별개인 상시 트랙입니다(PRD_최종 §11). 3단계 심화·기관 기능은 이 단계를 기다리지 않습니다. 네이버 뉴스 제휴 트랙(NAV)도 4c 판정과 따로 갑니다.

**1단계 AI 도우미와의 관계** (PRD-01C CHAT, PRD_최종 §6.2) — 지방세봇은 새 창·새 메뉴가 아니라 도우미 창의 두 번째 모드입니다. 두 모드는 아래처럼 나눕니다.

| 항목 | 1단계 AI 도우미 (안내·검색형, PRD-01C) | 4단계 지방세봇 모드 (이 문서) |
|---|---|---|
| 창 | 모든 공개 페이지 우측 하단, 기본 닫힘, 관리자·결제 화면 제외 (CHAT-01·02) | 같은 창의 모드 전환 (CHAT-15). 별도 URL·색인 페이지 없음 |

### 1.6 상세본 대조 메모

- 상세본 v2.0이 없어(PO 확인) v2.1에서 이 단계 ID만 골랐습니다. CHAT-15는 §6.2의 '4단계 지방세봇 모드' 한 줄과 §11.1 W12를 한 행으로 만들었습니다(나눌 규칙이 하나입니다). 수용 기준은 §6.2(같은 창·300문항 통과)와 이 문서의 기존 게이트(9장)·범위 플래그 규칙을 묶어 쓰고, v2.1에 없는 값은 `[결정 안건]`으로 두었습니다. 상세본이 생기면 같은 ID로 대조합니다.
- 옮겨 온 53행의 근거 칸에 적힌 `PRD_최종 v1.7 §…`(FAM-09의 `§5.3.1`)은 v1.7 절 번호입니다(원본 근거 유지). 본문의 v1.7 참조는 `PRD_최종 v1.7 §x`로, v2.1 참조는 `PRD_최종 v1.7 §x`로 적습니다.

## 2. 공개 계획

이 장이 지방세봇 공개 계획의 고정 참조 위치입니다(4a 내부 → 4b 초청 전문가 → 4c 대국민). 모든 단계에서 지방세봇은 AI 도우미 창 안의 모드입니다 — 4a·4b 동안 모드 전환 버튼은 대상 계정에만 보이고, 4c 게이트 통과 뒤 모든 공개 이용자에게 보입니다 (CHAT-15). 시점(주차)은 단계 착수 기준의 참고 순서이며 W0 실사 뒤 다시 산정합니다.

**J2-b — 결정례에서 묻기 (U3, 초청 전문가 베타)**

1. 결정례 상세에서 [이 결정례에 대해 묻기]를 누릅니다. 도우미 창이 지방세봇 모드로 열리고 결정례 ID가 첫 질문에 붙습니다.
2. "이 결정례와 결론이 반대인 사례가 있나?"라고 묻습니다. 지방세봇이 사건번호 중심으로 답합니다.
3. 근거 칩을 눌러 원문 패널에서 해당 부분(형광 표시)을 확인합니다.

**J2-c — 어제 나온 결정례 묻기 (U3, 초청 전문가 베타)**

1. 어제 공개된 조세심판원 결정을 기사로 보고 지방세봇에 묻습니다.
2. 색인에 아직 없어 지방세봇이 국가법령정보 API로 원문을 실시간 조회합니다. 진행 상태에 "공식 원문 조회 중"이 보입니다.
3. 답변의 인용 칩 끝에 '실시간' 점이 있고, 원문 패널에 `실시간 · 미검수 · 조회 시각`이 있습니다. 그 원문은 2단계 수집 대기열로 넘어가 검수·색인되고, 다음 O2 실행에서 요지 초안이 붙습니다.

**J3 — 심판청구 유사 사례 찾기 (U4, 키워드 맵)**

1. 판례·해석 검색에서 [키워드 맵]을 열고 세목 탭에서 취득세를 고릅니다.
2. 쟁점 노드 하나를 누르면 그 쟁점이 붙은 결정례만 남습니다. 연결된 노드를 하나 더 누르면 두 쟁점이 함께 붙은 결정례로 좁혀집니다.
3. 결정례 카드에서 결론 배지와 요지 3줄(검수 완료)을 비교하고, [이 결정례에 대해 묻기]로 지방세봇에 넘어갑니다. 여러 결정례를 표로 비교하는 일은 5단계 리서치 코파일럿이 맡습니다.

**J4-b — 개정 속보를 채널로 (U6, 편집국)**

1. 개정 속보 기사가 승인되면 편집자가 [채널 원고 만들기]를 누릅니다.
2. O3가 브리프 요약·카드뉴스 문안·쇼츠 대본·블로그 원고를 검수 큐에 올립니다.
3. 편집자가 원문과 나란히 고쳐 승인하고, 배포 키트를 내려받아 각 채널에 직접 올린 뒤 게시 링크를 기록합니다.

**J5-b — 입주권을 묻기 (U8, 신탁·정비 범위를 연 뒤)**

2. 지방세봇이 "그 신탁은 언제 설정되었나요?"라고 되묻습니다 (6.2.1).
3. 답변에 근거 칩과 서명된 지도 버전이 붙은 인용 칩이 있습니다. 신탁 납세의무자 판정 도우미(PRD-03 TRU-03, P1)가 공개되어 있으면 판정 도우미 결과 카드가 붙고, 없으면 가이드 근거 답변 + 쟁점 지도 링크로 끝납니다.

**J7-b — 축제를 묻기 (U10)**

1. 지방세봇에 "강릉 이번 달 축제 뭐 있어?"라고 묻습니다.
2. 지방세봇은 축제 목록·장소 추천 같은 여행 답변도, 세금 답변으로 꾸민 응답도 만들지 않습니다. "지방세봇은 지방세·부동산 세금 질문에 답해요. 관광·축제 정보는 다루지 않아요"처럼 범위 밖임을 한 줄로 알리고, 답할 수 있는 질문 예시를 보입니다 (ASK-21). 지역 허브나 관광 정보로 보내는 링크는 없습니다.
3. "강릉에 집 사면 취득세는?"이라고 이어 물으면 지방세봇 범위의 세금 질문으로 보고, 역질문·인용 규칙대로 답합니다.

### 4.2 디자인 적용 — SM 톤앤매너

색·글꼴·컴포넌트는 PRD-00 8장의 SM 부동산 세금 플랫폼 토큰을 그대로 씁니다. 이 단계의 화면은 PRD-00 8.6의 지방세봇 컴포넌트(v0.3의 3단계 컴포넌트), 1단계 AI 도우미 창, 3단계 부동산 컴포넌트(판정 도우미 결과 카드)로만 만들고, 새 형태가 필요하면 같은 문법으로 PRD-00 8.6에 먼저 더한 뒤 씁니다. 이번 판에서 더한 형태는 '지방세봇 진입점 카드'(검색 결과 위)와 '범위 안내 카드'(투자 추천 차단·지역 관광 질문 범위 밖 안내·범위 준비 중)이며 PRD-00 8.6에 정의되어 있습니다 — 둘 다 링크 카드 문법이며 새 색을 쓰지 않습니다. v2.0의 '도우미 창 모드 전환 컨트롤'(도우미 창 머리의 탭 2개 — 안내 · 지방세봇)은 PRD-00 8.6에 추가가 필요합니다.

- **8.2 화면 규칙** — 일반 모드의 지방세봇·키워드 맵·데이터 스토리·보안 정책 화면은 R1~R11을 지킵니다. 이 네 화면과 진입점이 붙은 `/search`를 1단계 E2E 화면 규칙 측정 대상(PRD-01A, PRD-00 11장)에 더합니다.
  - R1 — 지방세봇 모드 첫 화면(도우미 창 안)은 입력창·추천 질문 칩·고지까지 150자 이하. 홈에 진입점을 더해도 홈 첫 화면 150자 이하를 유지합니다.
  - R2 — 지방세봇 화면의 주 버튼(hermes-500)은 [지방세봇에게 묻기] 하나입니다. 검색 화면의 주 버튼은 통합 검색이고 지방세봇 진입점은 보조 버튼·링크 카드입니다. 도우미 창 런처는 주 버튼 수에 세지 않습니다 (1단계 규칙). 답변의 다음 행동 버튼은 어두운 버튼·보조 버튼으로 둡니다.
  - R8 — 결론은 한 줄, 한 상자 3문장 이하, 전문 용어는 첫 등장에 풀이(`lookup_glossary`).
  - R9 — 고위험 배너와 기한은 "언제까지 무엇을 하면 되는지"와 함께 씁니다. rose는 '자주 틀리는 점' 상자에만, 근거 부족 카드는 amber, 해당될 수 있는 감면은 emerald.
  - R11 — 픽토그램 세트만 씁니다. 이 문서의 👍·👎는 표기일 뿐이며, 화면의 피드백 버튼은 픽토그램 + 글자 라벨("도움이 됐어요"·"아니에요")입니다.
- **8.7 모드별 밀도** — 전문가 모드는 본문 15px·카드 안쪽 16px, 조문·사건번호 중심 말투. R1~R3·R7·R10은 적용하지 않습니다.
- **8.8 글쓰기** — 금지 표현은 지방세봇 검증기 V5 사전과 같은 원본에서 읽습니다. 버튼에는 하는 일을 씁니다 ([근거 원문 보기]·[위택스 바로가기]·[감면 점검 보기]).
- **8.9 접근성** — 스트리밍 답변과 진행 상태는 `aria-live="polite"`. 키워드 맵과 데이터 차트에는 같은 내용의 목록·표를 함께 둡니다. 움직임 줄이기 설정이면 노드·차트 애니메이션을 끕니다.
- **8.10 화면 골격** — 지방세봇 답변은 PRD-00 8.10 "지방세봇 답변" 골격을 따릅니다 (블록 순서는 6.4). 홈과 유틸 메뉴의 검색은 4c 뒤에도 통합 검색입니다.

```
   ├ 필수 요건이 비었다 → ③ 역질문(선택지, 라운드당 최대 3개, 최대 2라운드) → 응답을 받아 ②로
   └ 요건이 찼다 → ④로
④ 검색 계획 — 하위 질의 1~4개 · 문서 유형 · 세목 · 기준일
⑤ 하이브리드 검색 — 접근 등급·권리 상태·기준일·범위 플래그 필터는 SQL에서 강제 · 회원 작성 글과 일반 웹문서는 색인에 없다
   └ 필요한 원문이 색인에 없거나 마지막 색인 갱신 뒤에 나왔다 → ⑤-1
⑤-1 공식 원문 실시간 조회 — 국가법령정보 API · 응답 원본을 raw_snapshots에 저장 · 질문당 최대 3회
     (공식 도메인 한정 검색은 기본 꺼짐 · 일반 웹 검색 없음 · 범위 플래그가 꺼진 법령 제외)
⑥ 재순위 — 상위 40개 → 12개 · 같은 문서는 최대 3청크
   └ 근거 점수가 기준 미달 → 근거 부족 응답
⑦ 계산·판정 도구 — 세액 질문일 때만 계산 · 결과 ID · 명세 · 룰셋 버전
   ├ 계산했으면 서버가 같은 입력으로 감면 점검(판정표) → 해당될 수 있는 감면
   └ 주택 수·신탁 납세의무자 질문 → 판정 도우미(판정표) → 판정 결과 (ASK-22)
⑧ 답변 생성 — 근거를 문서 블록으로 넣고 인용 기능 사용 · 모드별 말투
⑨ 검증기 V1~V6 — 문단 단위
   ├ 통과 → ⑩ 렌더(인용 칩 · 명세서 · 판정 카드 · 감면 블록 · 다음 행동 · 고지)
   └ 실패 → 재생성 1회 → 다시 실패하면 근거 목록 응답
```

#### 6.2.2 상속·증여 취득세 (FAM-09) [감수 필요]

상속·증여 범위 플래그가 켜진 뒤에만 씁니다. 필드·필수 여부는 2단계 취득세 계산기의 질문 스키마(CALC-11 — 취득 원인 4종, 증여일 때 시가표준액, PRD-02 FAM-03)와 3단계 상속·증여 후 주택 수 판정표(PRD-03 FAM-05)를 그대로 읽습니다(계산기·판정 도우미·지방세봇이 같은 스키마). 아래는 PRD_최종 v1.7 §5.3.1과 v0.3에 적힌 항목만 옮긴 것입니다. 역질문 상한(2라운드·라운드당 3개) 안에서 필수 요건을 다 채우지 못하면 금액 없이 "요건 확인 필요"와 취득세 계산기 링크로 끝냅니다. 상속세·증여세의 요건은 묻지 않습니다 — 계산하지 않으므로 외부 계산기 카드로 보냅니다 (FAM-09).

| 세목 | 필수 요건 | 선택 요건 | 역질문 예 |
|---|---|---|---|
| 취득세 (상속·증여) — v0.3 6.2에서 옮김 | 취득 원인, 과세표준 기준(상속은 시가표준액, 증여는 시가인정액 — 기준일별 원문·룰셋으로 확정), 관계 | 1가구 1주택 상속 여부 | "상속인가요, 증여인가요?" |
| 상속·증여 취득 공통 | 물건 종류, 가액, 취득 후 주택 수 (2단계 취득세 계산기 질문 그대로, PRD-02 FAM-03) | (증여) 시가표준액 — 증여 중과 판정용, 공동상속 지분·기존 주택 보유 (주택 수 판정, PRD-03 FAM-05) | "증여받는 집의 시가표준액을 아시나요?" |

| ⑦ | 다음 행동 | 버튼 2~4개 — [조건 바꿔 계산하기] · [근거 원문 보기] · [위택스 바로가기] (신고·납부·환급 조회가 다음 할 일일 때, `wetax_links` 공식 주소·확인일, 새 창) · 사람 연결 두 버튼 [SM 전문가 보기]·[SM 전문가에게 연락 받기] (CHAT-17 — 하나만 보이지 않습니다). 주 버튼이 아니라 어두운 버튼으로 둡니다 (R2) |
| ⑧ | 하단 고정 | 기준일 · 룰셋 버전 · "AI가 작성한 일반 정보이며 세무 자문이 아닙니다" · 👍/👎 · 오류 신고 |

화면 골격은 PRD-00 8.10 "지방세봇 답변"과 같습니다. 전문가 모드는 같은 블록을 조문·사건번호 중심으로 쓰고, 밀도는 PRD-00 8.7을 따릅니다. [감면 점검 보기]와 [조건 바꿔 계산하기]는 입력값을 브라우저 상태로만 넘깁니다 (원칙 11).

**상속·증여 답변 (FAM-09)** — ②의 명세서는 상속·증여 원인 취득세 명세(PRD-02 CALC-01 명세 그대로 — 취득세·지방교육세·농어촌특별세)만 둡니다. 납세의무자·기준일·룰셋 버전·신고 경로(위택스)를 적고, 결론 바로 아래에 "상속세·증여세는 이 계산에 포함되지 않습니다" 한 줄, ⑦ 다음 행동에 외부 계산기 카드(PRD-01B FAM-08)를 둡니다. 상속세·증여세 묶음·금액·합계 줄은 두지 않습니다.

**범위 안내 응답** — 투자 추천 차단(ASK-20)·지역 관광 질문(ASK-21)·범위 준비 중(ASK-19·FAM-09)·상속세·증여세 금액·공제 질문(FAM-09)은 ① 한 줄 안내 + ⑦ 링크 2~3개 + ⑧로만 구성합니다. 근거 칩·명세서는 없습니다. 지역 관광 질문의 ⑦은 지방세봇이 답하는 질문 예시와 `/tax`·`/realestate` 분야 허브만 두고, 지역 허브·관광 링크는 두지 않습니다. 상속세·증여세 질문의 ⑦은 외부 계산기 카드·국세청 공식 안내·상속·증여 안내 페이지입니다. 양도세 질문의 ⑦은 SM 부동산 세금 플랫폼의 양도세 메뉴 카드·국세청 공식 안내입니다.

### 6.5 인용 처리

1. 재순위를 거친 청크 8~12개를 Claude API의 문서 블록으로 넣고 인용 기능(`citations`)을 켭니다. 문서 제목 필드에 `source_id`를 둡니다.
2. 응답의 인용(인용 문장, 문서 번호)을 `source_id`에 대응시킵니다. 칩에 들어갈 번호·일자·링크는 DB 원문 메타에서 가져옵니다.
3. 인용 기능은 구조화 출력(JSON 형식 강제)과 함께 쓸 수 없습니다 [확인 필요: 착수 때 API 문서 재확인]. 그래서 답변 단계는 텍스트 + 인용으로 받고, 역질문·분류처럼 구조가 필요한 단계는 별도 호출에서 구조화 출력을 씁니다.
4. 본문의 조문·사건번호는 인용된 문서의 메타와 대조합니다(V2). 대조에 실패한 번호가 들어간 문장은 표시하지 않습니다.
5. 실시간 조회·공식 도메인 검색으로 가져온 원문도 문서 블록으로 넣습니다. 문서 제목 필드에는 스냅샷 `source_id`를 두고, 칩의 번호·일자·링크는 `raw_snapshots`의 응답 원본에서 코드가 뽑습니다. 렌더러가 칩 끝에 '실시간' 점을 붙이고, 원문 패널에 `실시간 · 미검수 · 조회 시각`을 씁니다 (PRD-00 8.6 인용 칩).
6. 쟁점 연결 지도(3단계 `issue_graph`)는 서명된 버전 행이 `source_id`입니다. 칩에는 렌더러가 지도 버전과 감수일을 붙입니다 (ASK-19).

### 6.6 검증기

화면에 나가기 전에 문단 단위로 돌리는 결정론적 검사입니다. 검사기는 1단계 도우미의 응답 검증기와 같은 모듈(`packages/assistant`)에 둡니다 — 도우미 모드는 금액·세무 결론·투자 추천·인물 사칭 차단 검사를 쓰고, 지방세봇 모드는 V1~V6 전부를 씁니다. 모델 출력을 문단 단위로 모아 통과한 문단만 내보내고, 생성 중에는 진행 상태(근거 찾는 중 → 근거 n건 확인 → 답변 작성 중)를 보여 줍니다.

| 코드 | 검사 | 실패 시 |
|---|---|---|
| V1 | 결론·요건 문장마다 인용 1개 이상 | 해당 문장 제외. 결론에 인용이 없으면 재생성 |
| V2 | 본문의 조문·사건번호(정규식 추출)가 인용 문서 메타에 있습니다. 실시간 조회·공식 도메인 검색 원문은 `raw_snapshots`에 스냅샷이 있고 해시가 맞을 때만 인용으로 인정합니다 | 스냅샷 없는 인용은 지우고 재생성 1회 |
| V3 | 금액·세율 숫자가 계산 결과나 인용 원문에 있습니다. 감면 블록의 금액은 엔진 `result_id`에서만 옵니다. 상속·증여 원인 취득세 세액은 `status=calculated`인 엔진 결과에서만 옵니다. 상속세·증여세 세액·공제액 문장은 엔진 결과가 없으므로 통과하지 않습니다 — 막고 외부 계산기 안내로 바꿉니다 (FAM-09). 양도소득세·지방소득세(양도소득분) 세액 문장도 통과하지 않습니다 — SM 부동산 세금 플랫폼의 양도세 메뉴 안내로 바꿉니다 (ASK-09) | 재생성 1회 |
| V4 | 인용한 법령 조문이 기준일에 시행 중입니다. 아니면 "시행 예정·폐지" 표기가 있습니다 | 재생성 1회 |
| V5 | 금지 표현이 없습니다 — 무료 상담·최저가·100% 환급·절세 보장·투자 권유·단정적 위법 판단·세무 자문 보장 등, 감면·비과세 해당 여부를 단정하는 문장("감면 대상입니다"·"비과세됩니다" 등 — 판정은 감면 블록만 보여 줍니다), 특정 구역·단지·상품 추천과 시세·금리 예측 문장(ASK-20), 실존 인물 사칭 — 김의효의 이름으로 답하거나 말투를 흉내 내는 문장(BR-09) (사전은 설정 파일, 버전 관리) | 표현을 막고 재생성 |
| V6 | 개인정보 패턴이 다시 나오지 않습니다 | 마스킹 |

감면 블록과 판정 카드는 모델 출력이 아니라 `check_benefits`·`run_determination` 결과로 렌더러가 그리므로, 모델 문장이 그 안에 들어갈 경로가 없습니다. 검증기는 모델 문단에서 감면 단정 문장만 막습니다(V5).

재생성 후에도 실패하면 **근거 목록 응답**(검색 상위 5건 + 원문 링크 + 사람 연결 두 버튼)으로 바꾸고 품질 콘솔에 기록합니다.

### 6.7 모델 구성

| 단계 | 기본안 | 비용 최적화안 (평가셋 통과 시) | 비고 |
|---|---|---|---|
| 개인정보 마스킹 | 정규식 (AI 아님) | 같음 | — |
| 의도·요건 분석, 범위 판단, 역질문 | Claude Opus 5.5, 추론 강도 low | Claude Haiku 5.5 | 구조화 출력 |
| 검색 계획, 재순위 | Opus 5.5, low | Haiku 5.5 | — |
| 실시간 조회 판단 | 답변 단계 모델이 도구 호출로 판단 | 같음 | 질문당 호출 상한은 서버가 강제 |
| 감면 점검 · 판정 도우미 | 판정표 + 계산 엔진 (AI 아님) | 같음 | 서버가 호출 |
| 답변 (일반 모드) | Opus 5.5, low~medium | Claude Sonnet 5.5 | 인용 기능 · 스트리밍 |
| 답변 (전문가 모드) | Opus 5.5, medium~high | 같음 | 인용 기능 |
| 편집국 에이전트 초안 (O2·O3·O6, 채널 원고 포함) | Opus 5.5, medium | Sonnet 5.5 (요약·대중화·채널 원고) | 배치 |
| 지방세 통계 수집 | 수집 배치 (AI 아님) | 같음 | — |

- **한 모델로 시작합니다.** 프롬프트 캐시는 모델별로 따로 쌓이므로 한 모델이면 캐시 효율이 높고, 품질 비교의 기준선도 됩니다. 비용 최적화안은 평가셋에서 기본안과의 정답률·인용 정밀도 차이가 2%p 이내일 때만 단계별로 바꿉니다.
- **도우미 모델과의 차이** — 1단계 AI 도우미는 답변 `claude-sonnet-5-5`·의도 분류 `claude-haiku-5-5`(`ANTHROPIC_MODEL_ANSWER`·`ANTHROPIC_MODEL_ROUTER`, PRD_최종 §6.2)를 씁니다. 지방세봇 모드는 근거 인용·역질문·평가 게이트가 더 엄격하므로 Opus 5.5 단일 기본안으로 시작하고(`AGENT_MODEL_*`), 비용 최적화안은 위 조건일 때만 씁니다. 두 모드는 같은 키·워크스페이스를 쓰되 모델 환경변수를 섞지 않습니다. 30일 보관이 필요한 모델 계열(Fable·Mythos)은 지방세봇 모드에도 쓰지 않습니다.
- **모델 ID와 추론 강도는 환경변수로 둡니다** (`AGENT_MODEL_ANSWER`·`AGENT_MODEL_UTILITY`·`AGENT_EFFORT_ANSWER` 등). 코드에 모델 이름을 박지 않습니다. 위 모델 이름은 2026-10 기준 기본안이며, 착수 때 실제 계약·공시를 확인해 정합니다 (PRD_최종 v1.7 §7.1).
- **프롬프트 캐싱** — 도구 정의와 지시문은 고정해 앞에 두고, 기준일(오늘 날짜)·범위 플래그 상태 같은 가변 값과 검색·실시간 원문 문서 블록은 마지막 캐시 지점 뒤에 둡니다. 공식 도메인 한정 검색을 켜고 끄면 도구 정의가 바뀌어 캐시가 새로 쌓입니다.
- **도구 호출 방식** — Opus 5.5·Sonnet 5.5는 특정 도구 강제 호출(`tool_choice` any·tool)을 지원하지 않습니다 [확인 필요: 착수 때 API 문서 재확인]. `auto`에 엄격한 스키마(`strict`)와 지시문을 더해 설계합니다. 반드시 돌아야 하는 감면 점검은 모델에 맡기지 않고 서버가 부릅니다.
- **거절·장애** — 모델이 거절(`refusal`)하면 서버 측 폴백 옵션을 쓰고, 그래도 실패하거나 API에 장애가 나면 검색 모드(ASK-15)로 넘어갑니다.
- **인증** — 사용자 경로는 서버 전용 `ANTHROPIC_API_KEY`(PRD_최종 §9.2 — 1단계 도우미와 같은 사용자 경로 키, v1.2의 `ANTHROPIC_API_KEY_APP`을 이 이름으로 바꿨습니다)로만 호출합니다. `NEXT_PUBLIC_` 접두어 금지. 구독 인증 토큰은 배포 환경에 두지 않습니다 (PRD-00 7장 원칙 6, 12장).
- **AI 호출 경로** — Anthropic 공식 TypeScript SDK를 `packages/agent`(지방세봇 모드)·`packages/assistant`(1단계 도우미 — 가드·검증기는 두 모드 공유)·`workflows`(편집국 배치)에서만 씁니다. Vercel AI Gateway는 쓰지 않습니다. 사내 서버로 옮긴 뒤에도 같은 코드가 돌아야 하기 때문입니다 (PRD-00 7장 원칙 15 이식성).

### 6.13 스트림 이벤트

`/api/ask`(지방세봇 모드)는 서버 전송 이벤트(SSE)로 아래 이벤트를 보냅니다. 도우미 창은 모드에 따라 `/api/assistant`(1단계) 또는 `/api/ask`를 부릅니다 — 라우트를 하나로 합칠지는 16장 결정 안건.

| 이벤트 | 내용 |
|---|---|
| `status` | 진행 상태 (근거 찾는 중 · 공식 원문 조회 중 · 근거 n건 확인 · 답변 작성 중) |
| `clarify` | 역질문과 선택지 (라운드 번호 포함) |
| `paragraph` | 검증을 통과한 문단과 인용 ID (실시간 조회 인용은 스냅샷 ID와 실시간 표시) |
| `calc` | 계산 결과 ID와 명세, 상태 |
| `benefits` | 감면 점검 결과 — 판정 항목·요건 체크·근거 ID·금액 결과 ID·판정표 버전 |
| `determination` | 판정 도우미 결과 — 판정 결과 ID·결론·요건 체크·근거 ID·판정표 버전 (ASK-22) |
| `fallback` | 근거 목록·범위 안내 응답과 그 사유 (근거 부족·장애·예산·투자 추천 차단·지역 관광·범위 준비 중) |
| `done` | 검증 요약 · 기준일 · 룰셋 버전 |
| `error` | 사용자에게 보일 오류 문구와 다음 행동 |

이벤트는 표준 SSE 형식이라 Vercel과 사내 서버 Docker에서 같은 코드로 돕니다. 사내 서버 이전 뒤에는 공용 리버스 프록시가 응답을 모아 두지 않게 버퍼링을 끕니다 (PRD-00 10.5 — Nginx는 `X-Accel-Buffering: no` 응답 헤더). CI의 Docker 이미지 E2E에서 첫 `status` 이벤트가 1초 안에 오는지 확인합니다.

에이전트는 `review_items`에만 쓸 수 있고, 공개는 사람이 승인한 뒤에만 합니다 (PRD-00 7장 원칙 5). 채널 원고도 승인 후 사람이 각 채널에 올립니다.

- 채널 원고는 채널별 글자 수 상한과 체크리스트(출처 표기·AI 활용 표기·대체 텍스트·광고 아님 확인)를 거칩니다.

## 8. 검색 파이프라인과 미세조정

- 검색 대상 규모는 공공 원문 + 권리 확인 출판물 + 기사 + 3단계 감수 가이드·쟁점 지도로 0.5~1백만 청크를 예상합니다. 벡터 색인 크기에 맞춰 Supabase 컴퓨트를 늘립니다 [확인 필요: 0단계 실사 후 재산정].
- 검색 대상은 공식 원문과 감수한 콘텐츠뿐입니다. 회원 작성 글(5단계 Q&A·댓글)과 일반 웹문서는 색인에 넣지 않습니다 (PRD-00 7장 원칙 10, PRD_최종 v1.7 §5.2).
- **범위 확장 색인** — 3단계 가이드(`guides`)는 절 단위, 쟁점 연결 지도(`issue_graph`)는 서명된 버전마다 쟁점 요약 1청크 + 연결 표 행 단위로 넣습니다. 서명 전·회수된 버전은 넣지 않습니다. 범위 태그가 붙어 플래그가 꺼진 동안 운영 검색에 나오지 않습니다. 지도가 새 버전으로 바뀌면 이전 버전 청크는 기준일 필터로만 찾습니다.
- **미세조정(fine-tuning)은 하지 않습니다.** 첨부 보고서는 30년 출판 데이터를 LLM에 미세조정하고 RAG를 적용하자고 제안합니다(RP-17, BM-A8). 그러나 세법은 해마다 바뀌어 학습 시점의 지식이 곧 낡고, 학습한 지식은 출처를 추적할 수 없어 "근거 없는 답은 내보내지 않습니다"(원칙 4)를 지킬 수 없습니다. 그래서 출판물은 권리를 확인한 분량만 색인에 넣고 인용으로만 쓰며(RAG-06), 품질은 검색 증강 + 인용 강제 + 평가셋으로 관리합니다 (PRD-00 4.4, 12장).
- **최신성은 학습이 아니라 조회로 확보합니다.** 보고서는 학습 데이터 밖의 최신 예규·판례를 웹 검색으로 찾자고 합니다(BM-A6). 이 플랫폼은 2단계 수집 파이프라인의 증분 색인(RAG-03)을 기본으로 하고, 그 사이에 나온 원문은 국가법령정보 API 실시간 조회(ASK-16)로 채웁니다. 실시간 조회한 원문은 수집 대기열로 넘겨 검수·색인하므로, 같은 원문을 두 번 조회할 일이 줄어듭니다. 실시간 조회 비율이 높아지면 색인 갱신이 늦다는 신호로 보고 수집 주기를 점검합니다 (15장).

| 역질문 | 60 | 필수 요건이 빠진 질문. "법인이 부동산을 취득할 때 과점주주 기준은?"(기대 역질문: 상장 여부 — 코스피 상장법인 · 비상장법인 · 모르겠어요)을 반드시 넣습니다 | ASK-02 · EVAL-01 |
| 감면 안내 | 30 | 세액 계산과 함께 감면·비과세 판정이 걸리는 질문. 정답에 '해당될 수 있는 감면' 목록과 금지 단정 문장을 둡니다 | ASK-18 |
| 실시간 조회 사례 | 15 | 필수 근거를 색인에서 가린 채 돌리는 문항 — 최근 공포된 법령·새 결정례를 실시간 조회로 찾아야 합니다 | ASK-16 |

- 문항마다 질문, 필수 요건과 기대 역질문, 정답 결론(감수위원 작성), 필수 근거 ID, 금지 주장을 둡니다. 금지 주장에는 개별 세무 자문을 보장하는 문장과 근거 없는 결론을 넣습니다 (PRD_최종 v1.7 §7.2).
- 300문항 안에 상속·증여 취득세나 신탁·정비 문항이 있으면 해당 범위 플래그가 꺼진 동안의 기대 응답을 '안내 페이지·계산기·공식 원문 안내'(신탁·정비는 '지방세법 조문 범위 답변 + 링크')로 두고 채점합니다. 상속세·증여세 금액·공제 문항의 기대 응답은 플래그와 무관하게 '외부 계산기·국세청 공식 안내, 금액 0'입니다.
- '범위 밖' 문항에는 지역 관광 질문(축제·명소·맛집·여행 일정)과 관광 + 세금 혼합 질문을 넣습니다. 기대 응답은 여행 답변 없는 범위 밖 안내(지역 허브·관광 링크 0)이고, 혼합 질문은 세금 부분만 채점 대상 답변으로 둡니다 (ASK-21).
- '범위 밖·고위험' 문항에 양도세 금액 질문과 실존 인물 사칭 요청(BR-09)을 넣습니다. 기대 응답은 양도세 금액 0 + SM 부동산 세금 플랫폼의 양도세 메뉴 안내, 사칭 없는 일반 답변입니다.
- 채점은 감수위원 2인(PO + 보조 세무 전문가)이 블라인드로 합니다. 의견이 갈리면 두 사람이 원문을 함께 다시 확인하고, 그래도 갈리면 외부 세무사 1인 자문을 3인째 판정으로 기록합니다 (PRD-00 12장). 대량 회귀는 AI 채점으로 1차 선별한 뒤 사람이 확인합니다.
- 실시간 조회 사례는 색인 제외 목록을 건 별도 실행으로 채점합니다. 국가법령정보 API 응답은 실행 시점마다 달라질 수 있으므로, 회귀용으로는 고정한 실응답 견본을 쓰고 게이트 판정 때 실제 API로 한 번 더 돌립니다.
- 공식 도메인 한정 검색(ASK-17)을 켜는 판단은 같은 평가셋을 켠 실행과 끈 실행으로 비교합니다.

| 지표 | 4a 내부 베타 | 4b 초청 전문가 베타 | 4c 대국민 공개 |
|---|---|---|---|
| 정답률 | ≥ 80% | ≥ 85% | ≥ 90% |
| 인용 정밀도 | ≥ 95% | ≥ 97% | ≥ 98% |
| 필수 근거 재현율 | ≥ 70% | ≥ 80% | ≥ 85% |
| 필수 요건 역질문 누락 | ≤ 10% | ≤ 7% | ≤ 5% |
| 답 없음 문항에서 지어낸 답 | 0 | 0 | 0 |
| 감면 해당 여부 단정 (감면 안내 문항) | 0 | 0 | 0 |
| 스냅샷 없는 실시간 인용 | 0 | 0 | 0 |
| 치명 오류 | ≤ 2건 | 0 | 0 |

게이트 값은 감수위원과 협의해 4단계 착수 때 확정합니다. 단 4c 값은 PRD_최종 v1.7 §5.2의 수치이며 이보다 낮추지 않습니다. 하나라도 미달이면 4c를 열지 않습니다. 게이트 리포트(EVAL-04)는 교차 유형별 결과를 따로 적어, 전체 정답률에 가려진 약한 유형이 보이게 합니다. 치명 오류는 PRD-00 1장의 정의(과세·비과세 반대 안내 · 신고·불복 기한 오류 · 요건 반대 안내 · 존재하지 않는 근거 인용)를 따릅니다.

## 17. 다음 단계로 넘기는 것

- 검색 색인과 증분 갱신(범위 태그 포함), 지방세봇 코어(도구·검증기·스트림·실시간 조회·감면 점검·판정 연결), 평가 체계와 게이트 리포트(교차 유형·범위별), 품질 콘솔, 범위 플래그 승인 절차.
- 5단계 준비 — 프리미엄 하루 100회 공정 사용 한도(ASK-10)와 출판물 전체 색인을 구독 권한(LIB·PAY)에 잇습니다. 보안 통제 목록과 자가 점검 기록을 정보보호 인증(SEC-02)의 출발점으로, O2 요지·쟁점 태그를 맞춤 AI 브리핑(WS-06)·관련 자료 패널 v2(LAW-10)에, 채널 원고 흐름을 네이버 프리미엄 콘텐츠(CH-02)에 넘깁니다. 리서치 코파일럿은 지방세봇과 같은 검증기와 실시간 조회를 씁니다. 5단계 Q&A 회원 글은 지방세봇 색인에 넣지 않는 규칙을 그대로 지킵니다.
- 4c 뒤 운영 — 진입점별 이용 기준선으로 지방세봇 메뉴 여부를 정하고(16장), 이 단계에서 열지 못한 범위(신탁·정비·상속·증여 취득세)는 같은 범위 게이트로 다시 판정합니다. AI의 지역별 세금 답변 확장은 3단계 조례·정비 현황 데이터의 감수 준비에 맞춰 별도 평가로 검토합니다.
