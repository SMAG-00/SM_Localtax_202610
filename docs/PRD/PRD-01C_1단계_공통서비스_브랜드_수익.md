# 「SM(선명) 지방세·부동산·지자체뉴스 종합 플랫폼」 PRD-01C 1단계-C — 공통 서비스·브랜드·수익 (AI 도우미·전문가 소개·SM 전문가 연락 요청·김의효 브랜드·자사 상품)

4대 분야(지방세 · 부동산 · 부동산개발금융 · 지자체뉴스)를 가로지르는 공통 서비스와, 그 신뢰를 매출로 잇는 장치를 1단계에 연다. ① 모든 공개 페이지 우측 하단의 **AI 도우미 "무엇을 도와드릴까요?"** — 1단계는 사이트 안내·검색형이다. 자사 공개 콘텐츠를 찾아 인용 링크와 함께 안내하고, 세액·세무 결론·국세 금액·투자 추천·인물 사칭은 하지 않으며 그런 요청은 전문가 연결로 넘긴다. 100문항 평가를 통과해야 공개한다 ② **전문가 소개** — 소개 대가 없는 광고형 디렉터리. 자격이 검증된 세무사·공인회계사·변호사·법무사·부동산 전문가를 함께 보여 주고, 이용자가 직접 연락한다 ③ **SM(선명) 소속 전문가 연락 요청** — 이용자가 확인·동의한 요약과 연락처만 SM 소속 전문가에게 전달하고, 상담·업무는 자격 있는 수행 주체 명의로 한다 ④ **김의효 브랜드** — 증빙 먼저, 표시는 그 뒤. 인물 페이지·감수 표시·시그니처 콘텐츠 ⑤ **자사 상품** — 이미 팔고 있는 지면 구독·도서·교육원 강좌를 쉽게 사게 하고, 기사 하단 '자사 상품' 카드는 1개 이하로 둔다. 제품명은 가칭이다.

## 1. 목표와 범위

### 1.1 목표

- 어떤 페이지에서든 독자가 "무엇을 도와드릴까요?"로 길을 찾게 한다. 도우미는 자사 공개 콘텐츠만 근거로 인용 링크를 붙여 안내하고, 하지 않는 일은 전문가 소개로 넘긴다 (PRD_최종 §6.2).
- 도우미는 세액·세무 결론·국세(상속세·증여세·양도세) 금액·투자 추천·인물 사칭을 만들지 않는다. 개인정보는 보내기 전에 가리고, 마스킹본만 30일(설정값) 보관한다. 100문항 평가를 통과하기 전에는 공개하지 않는다.
- 개별 상담이 필요한 독자를 자격이 확인된 전문가에게 잇는다. 외부 전문가는 소개 대가 없는 광고형 디렉터리로, SM 소속 전문가는 이용자 동의 기반 연락 요청으로만 정보를 전달한다 (원칙 ⑧).
- 김의효 50년 세무 브랜드를 증빙이 확인된 범위에서만 보인다. '50년'·직함·경력은 증빙과 동의가 있어야 화면에 나온다 (원칙 ⑨).
- 이미 팔고 있는 지면 구독·도서·교육원 강좌를 쉽게 사게 하고, 기사와 상품을 섞지 않는다. 기사 하단 '자사 상품' 카드는 1개 이하, 상품 담당은 기사 승인 권한이 없다 (원칙 ⑥).
- 유입 경로(기사·칼럼·브리핑·검색·AI 검색·네이버·도우미·전문가 소개)별 전환을 집계로 재고, 비용 정의가 승인된 상품부터 공헌이익을 계산한다.

**공개 범위의 조건** — 도우미는 100문항 평가(CHAT-14)와 13장 #24 감수, 전문가 소개는 #20 감수, SM 연락 요청은 #12 실사·#2 결정·#20 감수, 브랜드 표시는 #11 실사·#22 감수, 스토어 가격·신청은 #15 실사·#23 감수가 끝나야 공개 플래그를 켠다. 검토가 끝나기 전에는 기능 플래그로 숨기고 빈 링크를 두지 않는다 (PRD_최종 §10). 실사 #12에서 SM 소속 전문가 연락 요청을 적법하게 운영할 방식이 정해지지 않으면, EXPL-13~21을 1단계 공개 범위에서 뺄지 PO가 결정한다(11장) — 그 경우 도우미의 [SM 전문가에게 연락 받기] 버튼도 없다(CHAT-17).

### 1.6 상세본 대조 메모

- 상세본 v2.0이 없어 v2.1의 묶음 표(6.2 기능 묶음 · 6.3 기능 묶음 · 6.4 여섯 단계와 공통 문단 · 7.1 기능 묶음 · 8장 상품표와 공통 요구)의 규칙을 적힌 ID 순서대로 하나씩 나눴다. 규칙이 ID보다 적은 묶음은 가장 복합적인 규칙을 나눴다 — CHAT-10~12는 '속도·예산·검색 결과만 모드 / 주입 방어·읽기 전용 / 모델·프롬프트 버전'으로, EXPL-13~21은 6.4의 여섯 단계와 공통 문단을 '진입 · 요약 · 확인·동의 · 배정·알림 · 수행 주체 · 목표 시간·무료 범위 · 열람 통제 · 민감 입력 차단 · 종결·파기'로, BR-04~06은 시그니처 콘텐츠 여섯 가지를 '칼럼·그때와 지금 / 한 줄 평·50문 50답 / 영상·낭독·아카이브'로 나눴다.
- 새 행의 근거 칸은 `PRD_최종 §6.2 · 상세본 대조 필요`처럼 v2.1 절 번호와 표지를 함께 적었다. 숫자는 v2.1에 있는 값(30일·1영업일·1년·100문항·카드 1개 이하)만 쓰고, 나머지는 설정값·`[결정 안건]`·`[감수 필요]`로 두었다. 상세본이 생기면 같은 ID의 수용 기준과 대조해 이 문서를 고친다.

- **R1** — 도우미 패널 첫 화면(고지·추천 칩 포함)은 150자 이하. `/experts`·`/store`·`/edu` 첫 화면도 150자 이하. 연락 요청 양식은 입력 화면이라 안내 문단 4줄을 R8 안에서 쓴다.
- **R2** — 런처·패널 [보내기]·전문가 버튼·상품 카드 버튼은 어두운 버튼이다(주 버튼 아님). 그래서 어떤 페이지에서 패널을 열어도 그 페이지의 주 버튼 수가 늘지 않는다. `/experts/request`의 주 버튼은 [요청 보내기] 하나다.
- **R3** — 런처는 hermes-500 면을 쓰지 않는다(픽토그램 포인트만). 런처를 포함해도 오렌지 면적 5% 이하.
- **R8** — 도우미 답변 문단은 3문장 이하, 한 줄 사유는 60자 이하.
- **R9** — 연락 요청의 기한 임박 안내는 "언제까지 무엇을 하면 되는지"(위택스·국세청 공식 안내)와 함께 쓴다. 공포 표현 사전을 도우미 고정 문구·검증기에도 쓴다.
- **R11** — 도움됨/아니에요 버튼은 픽토그램 + 글자 라벨이다. 이모지를 쓰지 않는다.
- **8.8 글쓰기** — 금지 표현(무료 상담·최저가·100% 환급·절세 보장·승소 보장·"최고"·"1위" 등)은 도우미 검증기·전문가 프로필 문구·상품 문구가 같은 사전 원본을 읽는다. 버튼에는 하는 일을 쓴다([전문가 직접 찾기]·[교육원에서 신청하기 ↗]).
- **8.9 접근성** — 패널은 대화 상자 역할(`role="dialog"`, 제목 연결), 열면 입력창 초점, Esc로 닫고 런처로 초점을 돌린다. 답변 스트리밍은 `aria-live="polite"`. 폼 오류는 `aria-describedby`.
- 이 문서의 화면을 PRD-01A의 E2E 화면 규칙 측정 대상(주요 화면 목록)에 더한다 — `/experts` · `/experts/request` · `/people/[slug]` · `/store` · `/store/books/[slug]` · `/edu` · 도우미 패널(열림 상태).

## 4. 기능 요구사항

`근거`는 새 요구사항이면 PRD_최종 절 번호와 `상세본 대조 필요` 표지, 옮겨 온 EDU-01은 v1.2 원본의 보고서 항목 ID(RP-22)다.

### 4.1 AI 도우미 — "무엇을 도와드릴까요?" (CHAT)

1단계 도우미는 **사이트 안내·검색형**이다. 4단계 평가(300문항)를 통과하면 같은 창에서 근거형 지방세봇 모드를 연다(CHAT-15, PRD-04).

**요청 → 동작 → 전문가 연결** (PRD_최종 §6.2)

| 요청 | 도우미의 동작 | 전문가 연결 |
|---|---|---|
| 길찾기·기사·용어·"이 글 요약" | 관련 페이지 링크, 짧은 설명과 인용, 'AI 요약' 표시 | — |
| 트래커·프로젝트·행사 상태 | DB 조회 결과를 그대로 | — |
| 구독·도서·교육, 정정·제보 | 안내 페이지·접수 양식으로 | — |
| 하지 않음 — 세액 계산 | 금액을 만들지 않고 SM 계산기로 | 지방세 전문 세무사 |
| 하지 않음 — 상속세·증여세 | 외부 계산기·국세청 안내로 | 상속·증여 세무 전문가 |
| 하지 않음 — 감면 등 개별 판단 | 판단 없이 관련 해설·원문 | 해당 세목 세무사 |
| 하지 않음 — 조합·신탁 법률 분쟁 | 판단 없이 해설·사례 | 정비·신탁 전문 변호사 |
| 하지 않음 — 분양·투자 추천, 시세 전망 | 추천·전망 없음 | 감정평가사·변호사(투자자문 소개 없음) |

양도세 금액 질문은 '세액 계산'과 같이 다룬다 — 금액 없이 SM 부동산 세금 플랫폼의 양도세 메뉴(새 창)·국세청 안내로 보낸다(원칙 ④). SM 계산기 5종(취득세·양도세·보유세·과점주주·비교)의 주소는 `official_links` 설정값이며 입력값을 넘기지 않는다.

**요청 흐름** — 가드가 마스킹한 질문만 Claude API로 가고, 답의 근거는 읽기 전용 도구가 Supabase 공개 뷰에서 가져온 것뿐이며, 검증기를 통과한 답만 인용 링크·전문가 버튼과 함께 돌아간다.

| 순서 | 구간 | 하는 일 |
|---|---|---|
| 1 | 위젯 (브라우저) | 질문과 페이지 맥락(경로·제목·분야)을 `/api/assistant`로 보낸다. 브라우저에는 위젯 UI만 있고 키·지시문·도구가 없다 |
| 2 | 가드 (`packages/assistant`) | 기능 플래그·속도 제한·일일 예산 확인 → 정규식 마스킹 → 의도 분류(라우터 모델, 구조화 출력) → '하지 않음' 범주면 답변 모델을 부르지 않고 고정 안내 문구 + 관련 해설 검색 결과 + 전문가 버튼으로 끝낸다 → 그 밖에는 서버가 먼저 `search_site`를 돌려 결과를 준비한다 |
| 3 | Claude API ↔ 읽기 전용 도구 | 답변 모델에 검색 결과를 `search_result` 블록으로 넣고 인용을 켠다. 모델은 필요하면 읽기 전용 도구를 더 부른다(질문당 호출 상한은 서버가 강제). 응답은 SSE로 흐른다 |
| 4 | 검증기 | 문단 단위 결정론적 검사(아래 A1~A6). 통과한 문단만 내보내고, 실패하면 재생성 1회 뒤 근거 목록 응답('검색 결과만'과 같은 형태)으로 바꾼다 |
| 5 | 응답 | 문단 + 출처 링크 + 'AI 답변' 표시 + (해당 시) 전문가 버튼 2개. 기록은 마스킹본만 |

**모델 구성** (PRD_최종 §6.2 `[웹확인]`)

| 단계 | 모델 | 환경변수 | 비고 |
|---|---|---|---|
| 개인정보 마스킹 | 정규식 (AI 아님) | — | 가드 |
| 의도 분류 | 권고 `claude-haiku-5-5` | `ANTHROPIC_MODEL_ROUTER` | 구조화 출력. 범주 — 길찾기 · 요약 · 상태 조회 · 운영 안내 · 하지 않음 5종 · 범위 밖 |
| 답변 | 권고 `claude-sonnet-5-5` | `ANTHROPIC_MODEL_ANSWER` | `search_result` 인용 · 스트리밍. 인용 기능은 구조화 출력과 같은 호출에 쓰지 않는다 |
| 연락 요청 요약 초안 (EXPL-14) | 답변 모델과 같은 변수 | `ANTHROPIC_MODEL_ANSWER` | 마스킹된 대화만 입력 |
| 검증기 | 결정론적 검사 (AI 아님) | — | A1~A6 |

- 모델 ID는 환경변수로 바꾸고 코드에 두지 않는다. Claude API는 대화 내용을 기본적으로 보관하지 않고 명시적 허락 없이 학습에 쓰지 않는다고 안내하므로, **데이터 30일 보관이 필요한 모델(Fable·Mythos 계열)은 도우미에 쓰지 않는다** (PRD_최종 §6.2). 계약 때 데이터 처리 조건을 다시 확인한다 [확인 필요].
- 특정 도구 강제 호출은 쓰지 않는다 — 권고 모델은 강제 호출을 지원하지 않는다 [확인 필요: 착수 때 API 문서 재확인]. 반드시 돌아야 하는 검색은 서버가 먼저 부르고, 모델에는 `auto`와 엄격한 스키마를 준다.
- 모델 거절·API 장애·시간 초과는 재시도 1회 뒤 '검색 결과만' 모드로 넘어간다.
- 사용자 경로는 상용 API 키(`ANTHROPIC_API_KEY`, 서버 전용)로만 부른다. 구독 인증 토큰은 배포 환경에 두지 않는다(PRD-00 원칙 6을 1단계부터 적용). Anthropic SDK는 `packages/assistant`(1단계)·`packages/agent`(4단계)·`workflows`에서만 불러온다(PRD-00 원칙 7 확장).

**읽기 전용 도구** — 모두 공개 뷰만 읽는 DB 역할 `assistant_reader`로 돈다. service role 키를 쓰지 않는다.

| 도구 | 하는 일 | 읽는 곳 |
|---|---|---|
| `search_site` | 발행 승인된 기사·해설·칼럼·용어·「지방세 50문 50답」·상품·강좌 통합 검색(PGroonga) | 공개 검색 뷰 |

### 4.2 전문가 소개 (EXPL-01~10·12)

유틸 메뉴·바닥글·홈 카드와 `/experts`에 두는 **광고형 디렉터리**다. 이용자가 여러 전문가의 검증된 프로필을 비교해 직접 연락하며, 플랫폼은 예약·수임·보수·결제에 관여하지 않고 **소개 대가를 받지 않는다** (PRD_최종 §6.3).

2026-10-16 웹 확인에서 김의효의 경력을 확인할 공개 자료를 찾지 못했고 회사 인사말 페이지에도 이름이 없다. 반면 회사가 밝힌 출판 이력(「지방세 실무」 1982년 초판·38판, 「지방세 편람」 27판, 월간 「지방세 연구」 327호 등)은 강력한 증거다. 그래서 **증빙 먼저, 표시는 그 뒤**로 설계한다 (PRD_최종 §7.1).

## 6. 외부 연동

모든 계정은 새로 개설한 회사 명의 계정만 쓴다. SM 부동산 세금 플랫폼의 계정·DB·배포·키를 쓰지 않는다 (PRD-00 원칙 14). 로그인 ID·비밀번호는 `.env`에 넣지 않고 비밀번호 관리자에 둔다 (PRD_최종 §9.2).
