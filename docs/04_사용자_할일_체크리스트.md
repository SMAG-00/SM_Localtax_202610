- [ ] 86. 내부 모의 점검 — 과거 1년 중 임의의 3개월 조합(NAV-24)으로, 최근 심사 대상 기간의 기사·취재 증거·편집 정책·등록 자료·기술·보안 점검·정정 이력을 묶어 점검하고, 층화 표본을 제3의 편집 책임자가 다시 검토한다. 요건에 못 미치면 신청을 미루고 결함을 고친다
- [ ] 87. 신청 시점 판단 — 다음 연 1회 접수 공고를 목표로, 해당 연도 접수 창구가 열리고 자격·자료가 갖춰졌을 때 신청한다. 첫 후보는 뉴스 검색 제휴(아웃링크). 뉴스 콘텐츠 제휴(인링크)는 편집 역량·계약 조건·자체 사이트 유입 효과를 비교한 뒤 판단한다
- [ ] 88. 제휴 체결 후 운영 평가 확인 — 월간 운영 평가, 전송 실패, 정정·삭제, 스폰서 표기, 독자 불만을 본다. 네이버 경유 유입은 자체 유입과 나눠 본다

## SM 코드 복사·외부 계산기 연결 (옛 T5 — SM 선행 확장은 철회, 2026-10-16)

SM 선행 확장 트랙(T5·SMX-01~08·PRD-SM)은 철회했다. SM은 바꾸지 않는다. 새 플랫폼은 2단계에 SM 취득세 계산기를 상속·증여 원인까지 그대로 복사하고, 상속세·증여세는 「안심 상속증여계산기」(PO가 운영하는 별도 사이트)로 연결만 한다. 다른 문서가 번호로 가리키므로 89~95번은 번호를 그대로 두고 내용만 고쳤다. PRD_최종 v2.1로 1단계에 SM 계산기 5종 새 창 연결이 생겨 126번을 붙였다.

- [ ] 89. SM 코드 현황 확인과 복사 기준선 승인 — 읽기 전용 코드 실사(2026-10-15)에서 SM 취득세 계산기에 취득 원인 4값(유상·상속·증여·원시)이 이미 있음을 확인했다. 이 코드를 상속·증여 원인까지 그대로 복사한다(FAM-03). 복사한 코드가 SM과 같게 도는지 볼 기준선(취득 원인 4종 대표 사례·테스트 수 — PRD-00 10장 SM 코드 현황)을 승인한다 (2단계 복사 전). SM 운영 화면은 바꾸지 않는다
- [ ] 90. (철회 2026-10-16) SM 상속·증여 계산 차단과 재개방 — 2026-10-15의 차단 결정을 **철회**했다. SM은 바꾸지 않는다. SM 취득세 계산기의 상속·증여 원인은 지금 상태로 충분하다(PO 판단). 로컬에서 만든 차단 변경은 되돌렸다(배포된 적 없음)
- [ ] 91. (철회 2026-10-16) 상속·증여 결과의 SM 리드 폼 처리 결정 — SM을 바꾸지 않으므로 정할 일이 없다. 새 플랫폼은 계산 입력값을 서버에 저장하지 않는다(헌법 7) — SM 리드 폼은 복사하지 않는다
- [x] 92. 감수자와 서명 방식 — **결정** (2026-10-15, 2026-10-16 고침): 상속·증여 취득세(지방세)는 PO(세무사)가 서명하고, 보조 세무 전문가(20번)가 교차 확인한다. 별도 위촉은 없다. 국세(상속세·증여세) 서명은 **철회**했다 — 이 사이트는 상속세·증여세를 계산하지 않는다. 서명 기록은 2단계 계산 룰셋 감수 절차(PRD-02, 54번)를 따른다
- [ ] 93. (철회 2026-10-16) SM 트랙 비식별 대조 사례 확보 — 상속세·증여세 대조는 없앴다. 상속·증여 원인 취득세 사례(각 30건 이상)는 2단계 55번에서 모은다
- [ ] 94. 「안심 상속증여계산기」 링크 확인 — 주소(https://ansim-igt-calculator.vercel.app/)를 `official_links`(kind=`external_calculator`)에 넣을 값으로 확인하고, 두 사이트의 운영 주체 관계를 연결 카드에 어떻게 밝힐지 정한다 [결정 안건]. 연결이 안 될 때 대신 보일 국세청 공식 안내 주소(`03_인프라_개설_요청.md` 4-1)도 함께 확인한다. 1단계 상속·증여 안내 페이지 공개 전 (FAM-08). 계정·키는 필요 없다.
